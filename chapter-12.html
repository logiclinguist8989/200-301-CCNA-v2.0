Chapter 12Single-area OSPFv2 and OSPFv3

🖼️ 3 figures⏱️ ~17 min read

Objective covered: 3.3 Configure single-area OSPFv2 for IPv4 and OSPFv3 for IPv6 — 3.3.a neighbor adjacencies (excluding authentication), 3.3.b point-to-point, 3.3.c broadcast (DR/BDR selection), 3.3.d router ID. OSPF is the only dynamic routing protocol named in v2.0, so expect configuration, show output and troubleshooting questions.

12.1 Learning objectives

After this chapter you can:

  1. Explain how a link-state protocol builds its routing table and why OSPF uses areas.
  2. Describe OSPF packets, neighbor states and the conditions for an adjacency.
  3. Predict the router ID and the DR/BDR on a broadcast network.
  4. Configure OSPFv2 with network statements or per interface, passive interfaces, cost, priority, network type and a default route.
  5. Configure OSPFv3 for IPv6.
  6. Read show ip ospf neighbor, show ip ospf interface and show ip route ospf, and troubleshoot adjacencies that do not form.

12.2 Introduction: why a routing protocol

Static routes do not scale and cannot react to failures beyond the next hop (Chapter 11). A dynamic routing protocol lets routers tell each other which networks they can reach and recalculate automatically when something changes. OSPF (Open Shortest Path First) is an open-standard link-state protocol: every router learns the full map of its area, then each runs the SPF (Dijkstra) algorithm to compute the best (lowest-cost) path to every network.

Property OSPF
Type Link-state, interior gateway protocol
Versions OSPFv2 for IPv4; OSPFv3 for IPv6
Administrative distance 110
Metric Cost = reference bandwidth ÷ interface bandwidth
Transport IP protocol 89
Multicast 224.0.0.5 all OSPF routers, 224.0.0.6 DR/BDR (IPv6: FF02::5, FF02::6)
Hello / dead timers 10 s / 40 s on broadcast and point-to-point networks
Areas Area 0 is the backbone; v2.0 tests single-area OSPF (everything in area 0)

12.3 How OSPF works internally

  1. Discover neighbors with Hello packets on every OSPF-enabled interface.
  2. Form adjacencies and exchange the link-state database (LSDB).
  3. Each router floods LSAs (link-state advertisements) describing its links; all routers in the area end up with an identical LSDB.
  4. Each router runs SPF with itself as the root and installs the best paths as O routes.
  5. When a link changes, only the affected LSA is flooded and SPF reruns — fast convergence without periodic full updates.

The five OSPF packet types:

Type Name Purpose
1 Hello Discover and keep neighbors; carry the parameters that must match
2 DBD (Database Description) Summary list of the LSAs in the sender's database
3 LSR (Link-State Request) Ask for LSAs you are missing
4 LSU (Link-State Update) Carry full LSAs
5 LSAck Acknowledge LSUs

12.4 Neighbor states and adjacencies (3.3.a)

Figure 12.1 shows the states two routers pass through.

Read Figure 12.1 top to bottom: the arrows are packets, the left column is the state they cause. A pair reaches FULL only after both databases match.

State Meaning Stuck here usually means
Down No Hellos received Link down, OSPF not enabled on the interface, passive interface, ACL blocking 224.0.0.5
Init Hello received, but my RID is not in it One-way communication; Hellos not reaching the other side
2-Way Each sees itself in the other's Hello Normal between two DROthers; otherwise DR/BDR election issue
ExStart / Exchange Negotiating and exchanging DBDs MTU mismatch
Loading Requesting missing LSAs Corrupt or lost LSUs (rare)
Full Synchronized Healthy

What must match for two routers to become neighbors (the Hello packet carries these):

  1. Area ID (both interfaces in area 0).
  2. Subnet and mask on the shared link.
  3. Hello and dead intervals.
  4. Authentication settings (excluded from the objective, but they must match).
  5. Stub area flag (not relevant in a single backbone area).
  6. Unique router IDs — two routers with the same RID will not form a proper adjacency.
  7. MTU — a mismatch lets them reach ExStart/Exchange but not Full.
  8. The interface must not be passive.

12.5 Router ID (3.3.d)

Every OSPF router needs a 32-bit router ID (RID), written like an IPv4 address. It is chosen once, when the OSPF process starts, in this order:

  1. The router-id command (best practice: set it).
  2. Otherwise the highest IPv4 address on an up loopback interface.
  3. Otherwise the highest IPv4 address on an up physical interface.

Changing the RID later requires clear ip ospf process (or a reload) to take effect. OSPFv3 uses the same 32-bit RID; on a router with no IPv4 addresses you must configure router-id manually.

12.6 Network types: broadcast and point-to-point (3.3.b, 3.3.c)

Network type Default on DR/BDR? Neighbors reach FULL with
Broadcast Ethernet Yes The DR and the BDR only
Point-to-point Serial (HDLC/PPP); configurable on Ethernet No The single neighbor

On a link with only two routers (a /30 or /31 between them) a DR is pointless. Setting ip ospf network point-to-point on both ends skips the election and the wait, so the adjacency forms faster. Both ends must use the same network type; mismatched types can form an adjacency yet produce missing routes.

12.7 DR and BDR election (3.3.c)

On a broadcast network every router would otherwise need a full adjacency with every other router — n(n−1)/2 of them. Instead one Designated Router (DR) and a Backup DR (BDR) are elected, and everyone else (DROther) forms FULL adjacencies only with those two (Figure 12.2).

In Figure 12.2 the blue lines are FULL adjacencies; the dashed line between the two DROthers is 2-WAY, which is correct and expected.

Election rules:

  1. Highest interface OSPF priority wins (0–255, default 1; ip ospf priority <n>).
  2. Tie: highest router ID.
  3. Priority 0 = never DR or BDR.
  4. No preemption: a better router that joins later does not take over until the DR fails or the OSPF process is reset on the segment. When the DR fails, the BDR becomes DR and a new BDR is elected.

The election happens per segment (per interface), so a router can be DR on one LAN and DROther on another.

12.8 OSPF cost and the metric

Cost = reference bandwidth ÷ interface bandwidth, with a default reference of 100 Mb/s. Costs below 1 are rounded up to 1, so FastEthernet, Gigabit and 10-Gigabit links all cost 1 by default — OSPF cannot tell them apart. Fix it on every router with the same value:

R1(config-router)# auto-cost reference-bandwidth 10000      ! in Mb/s: now 10G = 1, 1G = 10, 100M = 100

You can also set a cost directly on an interface: ip ospf cost 20. The route's metric is the sum of the outgoing interface costs along the path, from the router to the destination.

12.9 Configuring OSPFv2

Method 1 — network statements in router configuration mode. Each statement uses a wildcard mask (the inverse of a subnet mask: 0 = must match, 1 = ignore) to select interfaces; matching interfaces join the area.

R1(config)# router ospf 1                                  ! process ID: local only, need not match
R1(config-router)# router-id 1.1.1.1
R1(config-router)# auto-cost reference-bandwidth 10000
R1(config-router)# network 10.0.123.0 0.0.0.255 area 0     ! the LAN
R1(config-router)# network 10.0.12.0 0.0.0.3 area 0        ! the /30 point-to-point link
R1(config-router)# network 10.10.10.0 0.0.0.255 area 0     ! the loopback LAN
R1(config-router)# passive-interface loopback10            ! advertise it, but send no Hellos
R1(config-router)# default-information originate always    ! advertise a default route into OSPF

Method 2 — per interface (clearer, and the only method in OSPFv3):

R1(config)# interface gigabitethernet0/0/0
R1(config-if)# ip ospf 1 area 0
Command Mode Purpose / notes
router ospf <pid> Global Starts OSPF process; the process ID is locally significant
router-id <a.b.c.d> Router Sets the RID; needs clear ip ospf process if OSPF already runs
network <addr> <wildcard> area <id> Router Enables OSPF on matching interfaces. network 10.0.123.1 0.0.0.0 area 0 matches exactly one interface
ip ospf <pid> area <id> Interface Enables OSPF on this interface
passive-interface <int> / passive-interface default Router No Hellos (no neighbors) on that interface, but its network is still advertised. Use on LAN and loopback interfaces with no routers
ip ospf network point-to-point Interface Point-to-point type: no DR/BDR (3.3.b). On a loopback it advertises the real mask instead of /32
ip ospf priority <0-255> Interface DR election priority (3.3.c)
ip ospf cost <n> Interface Override the computed cost
ip ospf hello-interval / dead-interval Interface Timers; must match neighbors
auto-cost reference-bandwidth <Mb/s> Router Same value on every router
default-information originate [always] Router Advertise a default route; always even if this router has no default itself

Loopbacks and /32. OSPF advertises a loopback as a /32 host route regardless of its mask. To advertise Lo10 as 10.10.10.0/24 (as if it were a LAN), add ip ospf network point-to-point on the loopback.

12.10 Configuring OSPFv3 for IPv6

OSPFv3 works the same way (same states, DR/BDR rules, cost and AD) but is enabled per interface, forms neighbors over link-local addresses, and needs IPv6 routing on:

R1(config)# ipv6 unicast-routing
R1(config)# ipv6 router ospf 1
R1(config-rtr)# router-id 1.1.1.1                         ! mandatory if the router has no IPv4 address
R1(config-rtr)# auto-cost reference-bandwidth 10000
R1(config-rtr)# passive-interface loopback10
R1(config-rtr)# exit
R1(config)# interface gigabitethernet0/0/0
R1(config-if)# ipv6 ospf 1 area 0
R1(config-if)# interface gigabitethernet0/0/1
R1(config-if)# ipv6 ospf 1 area 0
R1(config-if)# ipv6 ospf network point-to-point

Newer IOS XE releases also offer the address-family syntax (router ospfv3 1, address-family ipv6 unicast, interface ospfv3 1 ipv6 area 0); both produce the same result. OSPFv2 and OSPFv3 are separate processes with separate neighbor tables and separate DR elections.

12.11 Verification

R1# show ip ospf neighbor
Neighbor ID     Pri   State           Dead Time   Address         Interface
2.2.2.2           0   FULL/  -        00:00:36    10.0.12.2       GigabitEthernet0/0/1

Read it as: R1 has two adjacencies with R2 (one per link) and one with R3. On the point-to-point link the role is - (no DR) and priority shows 0. On the LAN, R3 is DR and R2 BDR; R1 itself is DROther (shown in the next command).

R1# show ip ospf interface brief
Interface    PID   Area     IP Address/Mask    Cost  State Nbrs F/C
Lo10         1     0        10.10.10.1/24      1     P2P   0/0
Gi0/0/1      1     0        10.0.12.1/30       10    P2P   1/1
Gi0/0/0      1     0        10.0.123.1/24      10    DROTH 2/2

R1# show ip route ospf
O     10.20.20.0/24 [110/11] via 10.0.12.2, 00:05:10, GigabitEthernet0/0/1
                    [110/11] via 10.0.123.2, 00:05:10, GigabitEthernet0/0/0
O     10.30.30.0/24 [110/11] via 10.0.123.3, 00:05:10, GigabitEthernet0/0/0

The cost of 11 is 10 (1 Gb/s link with reference 10000) + 1 (the remote loopback). R1 has two equal-cost paths to R2's LAN, so both are installed.

12.12 Troubleshooting OSPF

Symptom Likely cause Evidence / fix
No neighbor at all Interface not in OSPF (wrong network wildcard), passive interface, area mismatch, subnet mismatch, ACL blocking 224.0.0.5 show ip ospf interface brief (interface missing?), show ip protocols (passive?)
Neighbor never appears; timers differ Hello/dead mismatch show ip ospf interface on both ends; match them
Stuck in ExStart/Exchange MTU mismatch Match ip mtu on both ends
%OSPF-4-DUP_RTRID_NBR Two routers with the same RID Set unique router-id; clear ip ospf process
Two routers show only 2-WAY Both are DROthers on a broadcast LAN Normal
Unexpected DR Elections are not preemptive; priorities changed after the election clear ip ospf process on the segment after setting priorities
Routes for a loopback show as /32 Loopback network type ip ospf network point-to-point on the loopback
Slow path chosen over a fast one Reference bandwidth left at 100 (all fast links cost 1) or different on routers Same auto-cost reference-bandwidth everywhere
Adjacency up, but routes odd on a two-router link Network type mismatch (one end broadcast, one point-to-point) Make both ends the same
No default route learned default-information originate missing (or no default without always) Add it on the edge router
OSPFv3 will not start No router ID on an IPv6-only router, or ipv6 unicast-routing missing Configure both

Order of checks: interface up and addressed → interface in OSPF and not passive → Hello parameters match (area, subnet, timers) → unique RID → MTU → routes and costs.

Experiments

  1. Timer mismatch: on R3 G0/0/0 enter ip ospf hello-interval 5. Within 40 s R1 and R2 drop R3 (dead timers no longer match). Remove the command.
  2. Point-to-point failover: shut R1 G0/0/1. R1's route to 10.20.20.0/24 drops to a single path via the LAN. Restore it.
  3. Non-preemption: set ip ospf priority 255 on R1 G0/0/0. Nothing changes until you clear the OSPF process on all three routers; then R1 becomes DR. Set it back and clear again.
  4. Passive mistake: on R2 enter router ospf 1 then passive-interface gigabitethernet0/0/0. R2 loses both LAN neighbors but still advertises 10.0.123.0/24. Remove it.

12.14 Lab 12.2 — OSPF challenge

On a copy of Lab 12.1 apply: on R2 router ospf 1 → no network 10.0.123.0 0.0.0.255 area 0 → network 10.0.123.0 0.0.0.255 area 1; on R3 router ospf 1 → router-id 1.1.1.1 and clear ip ospf process; on R1 router ospf 1 → passive-interface gigabitethernet0/0/1; on R2 router ospf 1 → no auto-cost reference-bandwidth 10000. Diagnose with show commands and logs only.

Answer key (hide until done): (1) Area mismatch on R2's LAN interface: no LAN adjacencies for R2; show ip ospf interface shows area 1. (2) Duplicate router ID between R1 and R3: %OSPF-4-DUP_RTRID_NBR messages, unstable adjacencies. (3) Passive point-to-point interface: the R1–R2 link loses its adjacency, though 10.0.12.0/30 is still advertised. (4) Reference bandwidth mismatch: adjacencies stay up, but R2 calculates all gigabit links as cost 1 while the others use 10, so paths and metrics differ between routers.

12.15 Chapter 12 summary notes (exam revision)

  • OSPF: link-state, AD 110, metric cost = reference bandwidth (default 100 Mb/s) ÷ interface bandwidth; protocol 89; 224.0.0.5 / 224.0.0.6 (FF02::5 / FF02::6).
  • Packets: Hello, DBD, LSR, LSU, LSAck. States: Down, Init, 2-Way, ExStart, Exchange, Loading, Full.
  • Neighbors need matching area, subnet/mask, Hello/dead, authentication, stub flag, MTU (for Full); unique RIDs; non-passive interfaces.
  • RID: router-id → highest loopback IP → highest active interface IP; change needs clear ip ospf process.
  • Broadcast: DR/BDR by highest priority (default 1, 0 = never), then highest RID, non-preemptive; DROthers FULL with DR/BDR, 2-WAY with each other. Point-to-point: no DR.
  • Config: router ospf 1, network ... wildcard area 0 or ip ospf 1 area 0, passive-interface, auto-cost reference-bandwidth, default-information originate. OSPFv3: ipv6 router ospf 1, router-id, interface ipv6 ospf 1 area 0.
  • Verify: show ip ospf neighbor, show ip ospf interface [brief], show ip protocols, show ip route ospf (and ipv6 versions).

Common conceptual mistakes

Mistake Correct idea
"Process IDs must match between neighbors" They are local; areas must match
"2-WAY means the adjacency failed" Between DROthers it is the correct final state
"Raising a priority immediately makes that router DR" No preemption; reset the process
"Passive interfaces are not advertised" They are advertised; they just send no Hellos
"1 G and 10 G links have different OSPF costs by default" Both cost 1 until the reference bandwidth is raised

12.17 Answer key with explanations

  1. 10.255.0.9 — the highest loopback address wins over any physical interface, even a numerically larger one.
  2. DR R3 (highest priority 10). BDR R1 (priority 1 tie with R2, broken by higher RID 4.4.4.4 over 2.2.2.2). R4 (priority 0) can never be DR or BDR.
  3. B. Mismatched MTU stops the DBD exchange. Area or Hello mismatches prevent the neighbor from appearing at all.
  4. No. DROthers on a broadcast segment remain 2-WAY with each other and are FULL only with the DR and BDR.
  5. network 172.16.5.1 0.0.0.0 area 0.
  6. Both are 1 (100 ÷ 1000 and 100 ÷ 10000 round up to 1), so OSPF cannot prefer the faster link. Fix with the same auto-cost reference-bandwidth on all routers.
  7. B and C. Process IDs are local; RIDs must be different, not the same; descriptions are irrelevant.
  8. No DR/BDR election takes place, the adjacency forms faster, and show ip ospf neighbor shows FULL/ - instead of DR/BDR roles.
  9. It stops sending and processing Hellos there (no neighbors can form), but the interface's network is still advertised into OSPF.
  10. default-information originate (here with always) on R1, the router at 10.0.123.1. It appears as an external type 2 route with metric 1.
  11. A manual router-id (no IPv4 address exists to choose one from), and ipv6 unicast-routing must be enabled.
  12. Hello/dead timer mismatch: R3 uses 5/20 while R1 uses the default 10/40, so R3 never becomes a neighbor of R1 (or of R2, which also uses the defaults). Make the timers identical on every router on the LAN.
  13. OSPF advertises loopbacks as /32 host routes by default. Add ip ospf network point-to-point on Loopback10 so the configured /24 is advertised.
  14. No. 2-WAY between DROthers is normal and efficient; forcing everyone to the same priority changes nothing about that (a DR and BDR are still elected) and could move the DR to a weaker router. No change is needed.
