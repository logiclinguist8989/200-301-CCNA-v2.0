14.2 Why DHCP

Typing an address, mask, gateway and DNS server into every PC, phone and laptop is slow and error-prone, and mistakes cause duplicates and wrong gateways (Chapter 2). DHCP (Dynamic Host Configuration Protocol) lets a host ask the network for its settings. A DHCP server keeps pools of addresses and leases them for a set time.

Fact Value
Transport UDP: server port 67, client port 68
First messages Broadcast (the client has no address yet)
What a client receives Address, mask, default gateway, DNS servers, domain name, lease time, plus optional extras
Typical server A Windows/Linux server in larger networks; an IOS router or switch in small sites and labs
IPv6 equivalent DHCPv6 and SLAAC (Chapter 3); this chapter is IPv4 only

14.3 The DORA exchange

A new client gets its address in four messages, remembered as DORA (Figure 14.1):

In Figure 14.1 time runs downward. The two messages from the client are broadcasts because it has no address yet; the highlighted Acknowledgment is the moment the lease begins.

  1. Discover — client → broadcast. Source 0.0.0.0:68, destination 255.255.255.255:67. "Is there a DHCP server?" It carries the client's MAC address.
  2. Offer — server → client. Proposes an address (10.10.10.11), mask, gateway, DNS and lease time. Before offering, an IOS server pings the address to make sure no one is using it.
  3. Request — client → broadcast. "I accept the offer from server X." It is broadcast so that every server that made an offer learns which one was chosen; the others return their addresses to the pool.
  4. Acknowledgment (ACK) — server → client. Confirms the lease. The client then checks the address with ARP (a duplicate triggers a DHCPDECLINE) and starts using it.

Other messages: NAK (server refuses a request, for example the client moved to another subnet), DECLINE (client found the offered address already in use), RELEASE (client gives the address back: ipconfig /release), INFORM (client already has an address and wants only options).

Lease timers. At T1 = 50 % of the lease the client renews by unicast with its own server. If that fails, at T2 = 87.5 % it rebinds by broadcast to any server. If the lease expires, it stops using the address and starts again with a Discover. A Windows client that gets no answer at all assigns itself an APIPA address, 169.254.x.x (Chapter 2) — the classic sign of a DHCP failure.

Options you should recognise:

Option Meaning IOS pool command
1 Subnet mask network <net> <mask>
3 Default gateway (router) default-router
6 DNS servers dns-server
15 Domain name domain-name
51 Lease time lease <days> [hours] [minutes]
43 Vendor-specific, e.g. WLC address for lightweight APs (Chapter 7) option 43 hex …

Memory trickDORA: Discover, Offer, Request, Acknowledge. Client on UDP 68, server on UDP 67.

14.4 Configuring an IOS DHCP server

An IOS router or Layer 3 switch can serve DHCP. All commands below are in global configuration mode, except the pool's own options in DHCP pool configuration mode (R1(dhcp-config)#).

R1
R1(config)# ip dhcp excluded-address 10.10.10.1 10.10.10.10      ! never lease gateways, servers, printers
R1(config)# ip dhcp pool STAFF
R1(dhcp-config)# network 10.10.10.0 255.255.255.0                ! the pool's subnet and mask (option 1)
R1(dhcp-config)# default-router 10.10.10.1                       ! option 3: the HSRP virtual IP, not a real one
R1(dhcp-config)# dns-server 10.10.99.53                          ! option 6 (the DNS server built in Chapter 22)
R1(dhcp-config)# domain-name campus.example                      ! option 15
R1(dhcp-config)# lease 2                                         ! 2 days (default 1 day)
Command Purpose Common mistake
ip dhcp excluded-address <first> [<last>] Addresses the server must never hand out Forgetting the gateway and its HSRP real addresses (.1, .2, .3), so the server offers them to PCs
ip dhcp pool <name> Creates a pool; the name is local —
network <net> <mask> Subnet the pool serves; with relay, it must contain the relay's giaddr (14.5) A mask or network that does not match the client VLAN
default-router <ip> Gateway given to clients A router's real IP instead of the FHRP virtual IP
dns-server <ip> [<ip>] DNS servers Leaving it out: names do not resolve (Chapter 22)
lease {days [hours [min]] \| infinite} Lease time Very short leases cause constant renewals
host <ip> <mask> + client-identifier <01+MAC> or hardware-address <MAC> A reservation: one pool per reserved host Packet Tracer support varies; give printers static addresses if it is missing
service dhcp DHCP server and relay service (on by default) no service dhcp silently disables both

Conflict detection. Before an Offer, IOS pings the address. If something answers, the address goes into the conflict table (show ip dhcp conflict) and is not leased until you clear it with clear ip dhcp conflict *.

14.5 DHCP relay: crossing a router

Discover messages are broadcasts, and routers do not forward broadcasts. If the DHCP server sits in another subnet — usual in any real network — the router facing the clients must relay the request (Figure 14.2):

In Figure 14.2 the grey legs are on the client's VLAN and the highlighted legs cross the routed network. The three cards show what is in the packet at each stage; the giaddr value is what lets one central server serve many VLANs.

  1. The client broadcasts its Discover in VLAN 10.
  2. The relay agent (the SVI or router interface with ip helper-address) receives it.
  3. The relay writes its own interface address in the client VLAN into the giaddr (gateway IP address) field, for example 10.10.10.2, and unicasts the message to the server.
  4. The server uses giaddr to choose the pool: the pool whose network contains 10.10.10.2 is STAFF.
  5. The server unicasts the Offer back to giaddr; the relay sends it on to the client in VLAN 10. Request and Ack follow the same path.
DSW1
DSW1(config)# interface vlan 10
DSW1(config-if)# ip helper-address 10.0.0.1          ! the DHCP server's address; one line per server

Where it goes: on the interface that receives the client's broadcast — the client VLAN's SVI (or router subinterface) — never on the interface toward the server. With HSRP (Chapter 13), configure it on both distribution switches; each relays, the server answers both, and the client takes one Offer.

Requirements: the server needs a route back to every giaddr subnet, and a pool whose network contains each giaddr. ip helper-address also forwards a few other UDP broadcast services by default (such as TFTP, DNS and NetBIOS), which matters only when you use them.

14.6 IOS as a DHCP client

A router's Internet-facing interface often gets its address from the ISP by DHCP:

R1
R1(config)# interface gigabitethernet0/0/1
R1(config-if)# ip address dhcp                      ! interface configuration mode
R1(config-if)# no shutdown

R1# show dhcp lease
Temp IP addr: 198.51.100.6  for peer on Interface: GigabitEthernet0/0/1
Temp  sub net mask: 255.255.255.248
   DHCP Lease server: 198.51.100.1, state: 5 Bound
   DHCP transaction id: 1A2B
   Lease: 86400 secs,  Renewal: 43200 secs,  Rebind: 75600 secs
Temp default-gateway addr: 198.51.100.1

The router installs the received gateway as a default route with AD 254 (S* 0.0.0.0/0 [254/0]), so any static default you configure (AD 1) wins (Chapter 10). Renewal at 43,200 s and rebind at 75,600 s are the 50 % and 87.5 % points of the 86,400 s lease. (Exact show dhcp lease layout varies by release.)

14.8 Troubleshooting DHCP

Follow the request from the client toward the server, then follow the reply back (Figure 14.3).

Figure 14.3 asks one question per hop, in the order the Discover travels. The first answer that leads right is the fault to fix; then start again from the top to confirm the client now gets an address.

Symptom Likely cause Evidence / fix
Client has 169.254.x.x No Offer received: client port down or in the wrong VLAN, no relay, server unreachable, pool missing or exhausted Work through Figure 14.3
Clients in one VLAN only fail ip helper-address missing on that SVI, or no pool whose network contains that giaddr show ip interface vlan X; compare pools with SVI addresses
Relay configured, still nothing Server has no route back to the giaddr subnet, or the helper points at the wrong address Ping the server from the SVI address: ping 10.0.0.1 source vlan 10
Address fine, but no access off the subnet Wrong default-router, or a real IP instead of the virtual IP ipconfig /all gateway; fix the pool
Names do not resolve dns-server missing in the pool Add it (Chapter 22)
Clients get addresses from an unknown subnet A rogue DHCP server (for example a home router plugged in) Find it with the binding/MAC tables; prevent with DHCP snooping (Chapter 23)
New clients fail after weeks of working Pool exhausted show ip dhcp pool: leased = total; enlarge the subnet or shorten leases
Gateway or printer addresses handed out Exclusions missing Add excluded-address; check show ip dhcp conflict, then clear it
Client gives up before an Offer arrives Access port without PortFast waits \~30 s for STP spanning-tree portfast (Chapter 9)
Server never answers anyone no service dhcp, or an ACL blocking UDP 67/68 Re-enable the service; check ACLs (Chapter 20)

Server statistics tell you where to look. If show ip dhcp server statistics shows Discovers arriving but no Offers, the server has no matching pool (or it is exhausted). If no Discovers arrive at all, the problem is between the client and the server: the relay, the routing or the client's VLAN.

14.11 Chapter 14 summary notes (exam revision)

  • DORA: Discover (broadcast) → Offer → Request (broadcast) → Ack. Server UDP 67, client UDP 68. Also NAK, DECLINE, RELEASE, INFORM.
  • Lease: renew by unicast at T1 = 50 %, rebind by broadcast at T2 = 87.5 %. No server at all → Windows uses 169.254.x.x (APIPA).
  • IOS server: ip dhcp excluded-address (global) + ip dhcp pool with network, default-router, dns-server, domain-name, lease. The server pings before offering; answered addresses go to show ip dhcp conflict.
  • Relay: ip helper-address <server> on the client-facing interface/SVI; the relay fills giaddr with its own interface IP and unicasts to the server; the server picks the pool whose network contains giaddr and needs a route back.
  • IOS client: ip address dhcp on the interface; default gateway installed as AD 254; show dhcp lease.
  • Verify: show ip dhcp binding, show ip dhcp pool, show ip dhcp conflict, show ip dhcp server statistics, show ip interface (helper), ipconfig /all.
  • With HSRP: default-router = virtual IP; exclude virtual and real addresses; relay on both gateways.

Common conceptual mistakes

Mistake Correct idea
"ip helper-address goes on the interface toward the server" On the interface that receives the client broadcast
"The relay forwards the broadcast as a broadcast" It converts it to a unicast to the server
"The server picks the pool from the client's MAC" From giaddr (or, with no relay, the interface it arrived on)
"169.254.x.x means the DHCP server gave a bad address" It means no DHCP server answered at all
"The excluded-address command goes inside the pool" It is a global configuration command
