Chapter 18Secure device access: local users, SSH and AAA

🖼️ 3 figures⏱️ ~15 min read

Objective covered: 4.1 Configure network devices with local usernames and as an AAA client (TACACS+ and RADIUS) for management. This chapter is about who may log in to a router or switch to manage it, how they prove it, and how that is recorded. Network access for users (802.1X, Chapter 16) uses the same AAA ideas.

18.1 Learning objectives

After this chapter you can:

  1. Secure console and remote access with local usernames, strong password hashing and privilege levels.
  2. Configure SSH version 2 and disable Telnet.
  3. Explain authentication, authorization and accounting and compare TACACS+ with RADIUS.
  4. Configure an IOS device as a TACACS+ and RADIUS client with local fallback.
  5. Explain the difference between a server rejecting a login and a server being unreachable.
  6. Verify and troubleshoot AAA logins.

18.2 Local usernames, privilege and password storage

A single shared line password (password cisco under line vty) cannot tell administrators apart and cannot be revoked for one person. Local usernames fix that on a small network.

R1(config)# enable algorithm-type scrypt secret Str0ng-Enable-2026      ! type 9 hash
R1(config)# username netadmin privilege 15 algorithm-type scrypt secret N3t-Admin-2026
R1(config)# username helpdesk privilege 1 algorithm-type scrypt secret H3lp-Desk-2026
R1(config)# security passwords min-length 10
R1(config)# login block-for 120 attempts 3 within 60       ! slow down password guessing
R1(config)# service password-encryption                     ! hides any remaining type 0 passwords as type 7
R1(config)# line console 0
R1(config-line)# login local
R1(config-line)# exec-timeout 10 0
Password type in the configuration Meaning Use
0 Plain text Never leave it
7 Reversible (service password-encryption) Only hides text from shoulder-surfers; decodable in seconds
5 MD5 hash (secret on older IOS) Weak by today's standards
8 PBKDF2-SHA-256 Good
9 scrypt Best available; algorithm-type scrypt

Privilege levels: 1 = user EXEC (>, show commands only), 15 = privileged EXEC (#, everything); levels 2–14 can be customised. A user with privilege 15 lands directly in privileged EXEC; a level 1 user must type enable and know the enable secret.

18.3 SSH for remote management

Telnet sends everything, including passwords, in clear text. SSH encrypts the session. Configure SSH version 2 and allow only SSH on the VTY lines:

R1(config)# hostname R1
R1(config)# ip domain-name campus.example                  ! needed for the RSA key name
R1(config)# crypto key generate rsa modulus 2048           ! RSA key pair for SSH
R1(config)# ip ssh version 2
R1(config)# ip ssh time-out 60
R1(config)# ip ssh authentication-retries 3
R1(config)# line vty 0 15
R1(config-line)# login local
R1(config-line)# transport input ssh                       ! no Telnet
R1(config-line)# exec-timeout 10 0

Verify with show ip ssh (version, timeouts) and show ssh (active sessions); connect from a PC with ssh -l netadmin 10.10.99.2 (Windows, Linux, macOS and Packet Tracer). Restrict which subnets may reach the VTY lines with an ACL and access-class (Chapter 20).

Local accounts do not scale: with 50 switches, a password change means 50 logins, and there is no central record of who did what. That is what AAA solves.

18.4 AAA: authentication, authorization, accounting

AAA moves user accounts off each device to a central server:

Function Question Example
Authentication Who are you? Username and password checked by the server
Authorization What may you do? Privilege 15 for network engineers, privilege 1 or a limited command set for help desk
Accounting What did you do, and when? Login/logout times and every command entered, sent to the server

The router or switch is the AAA client (also called the network access server, NAS); the AAA server is typically Cisco ISE, or another TACACS+/RADIUS server. Each client and the server share a secret key that protects their messages. Figure 18.1 shows a login.

In Figure 18.1 time runs downward. The two green replies are the server's decisions (who you are, what you may do); the dashed blue arrow is accounting, which keeps running for the whole session.

18.5 TACACS+ versus RADIUS

TACACS+ RADIUS
Origin Cisco; now documented as RFC 8907 Open standard (RFC 2865/2866)
Transport TCP 49 UDP 1812 (authentication), 1813 (accounting); old ports 1645/1646
Encryption Whole payload Password only; the rest is visible
AAA functions Separated — authentication, authorization and accounting can use different servers Authentication and authorization combined in one reply
Per-command authorization Yes — the server can allow or deny each command No
Typical use Device administration (who may configure routers and switches) Network access — 802.1X, Wi-Fi, VPN users; also device administration

Rule of thumb for the exam: TACACS+ for administrators managing devices; RADIUS for users joining the network. Both are on the syllabus as AAA clients for management, and both work for it.

How the server sets the privilege level. After a successful login, the server's authorization reply can carry a privilege level (for TACACS+ priv-lvl=15; for RADIUS a Cisco attribute such as shell:priv-lvl=15). The device uses it only if exec authorization is configured (18.6); otherwise users arrive at privilege 1.

18.6 Configuring IOS as an AAA client

Step 0 — protect yourself from lock-out. aaa new-model immediately changes how logins work. Before entering it, create a local privilege 15 user, keep a console session open, and save the configuration only after testing.

TACACS+ (current IOS XE syntax)

DSW1(config)# username netadmin privilege 15 algorithm-type scrypt secret N3t-Admin-2026   ! local fallback account
DSW1(config)# aaa new-model
DSW1(config)# tacacs server ISE-TAC
DSW1(config-server-tacacs)# address ipv4 10.10.99.20
DSW1(config-server-tacacs)# key T4cacs-Sh4red-Key
DSW1(config-server-tacacs)# exit
DSW1(config)# aaa group server tacacs+ ADMIN-TAC
DSW1(config-sg-tacacs+)# server name ISE-TAC
DSW1(config-sg-tacacs+)# ip tacacs source-interface Vlan99      ! requests always come from 10.10.99.2
DSW1(config-sg-tacacs+)# exit
DSW1(config)# aaa authentication login VTY-AUTH group ADMIN-TAC local
DSW1(config)# aaa authorization exec VTY-AUTH group ADMIN-TAC local if-authenticated
DSW1(config)# aaa accounting exec default start-stop group ADMIN-TAC
DSW1(config)# aaa accounting commands 15 default start-stop group ADMIN-TAC
DSW1(config)# aaa authentication login CONSOLE local               ! console never depends on the network
DSW1(config)# line vty 0 15
DSW1(config-line)# login authentication VTY-AUTH
DSW1(config-line)# authorization exec VTY-AUTH
DSW1(config-line)# transport input ssh
DSW1(config-line)# line console 0
DSW1(config-line)# login authentication CONSOLE

RADIUS (current IOS XE syntax)

SW1(config)# aaa new-model
SW1(config)# radius server ISE-RAD
SW1(config-radius-server)# address ipv4 10.10.99.20 auth-port 1812 acct-port 1813
SW1(config-radius-server)# key R4dius-Sh4red-Key
SW1(config-radius-server)# exit
SW1(config)# aaa group server radius ADMIN-RAD
SW1(config-sg-radius)# server name ISE-RAD
SW1(config-sg-radius)# exit
SW1(config)# aaa authentication login default group ADMIN-RAD local
SW1(config)# aaa authorization exec default group ADMIN-RAD local if-authenticated
SW1(config)# aaa accounting exec default start-stop group ADMIN-RAD

The list named default applies to every line that has no named list; a named list (VTY-AUTH) applies only where you reference it. Older syntax, still accepted by many releases and used by Packet Tracer: tacacs-server host 10.10.99.20 key T4cacs-Sh4red-Key and radius-server host 10.10.99.20 key R4dius-Sh4red-Key, with group tacacs+ / group radius in the method lists.

Command Mode Purpose
aaa new-model Global Turns on AAA; method lists now control logins
tacacs server <name> / radius server <name> + address, key Global → server Defines a server and its shared key
aaa group server tacacs+ \| radius <name> Global Groups servers; failover to the next server in the group
aaa authentication login <list> <method1> <method2> … Global Who may log in, and in which order to ask
aaa authorization exec <list> … Global Fetches the privilege level for the session
aaa accounting exec \| commands <level> <list> start-stop … Global Records sessions and commands
login authentication <list> / authorization exec <list> Line Applies named lists to console or VTY
ip tacacs source-interface / ip radius source-interface Group or global Fixes the source address the server sees

18.7 Method lists: error versus failure

A method list is tried left to right (Figure 18.2). The next method is used only if the current one gives no answer — server unreachable, timed out, or not configured (ERROR). If the server answers "reject" (FAIL), the login is refused and IOS does not try the local database.

So group ADMIN-TAC local means: "use TACACS+; only if every TACACS+ server is unreachable, use the local accounts". This is deliberate — a person removed from the AAA server must not get in with an old local password.

Figure 18.2 reads from the login on the left. Only the amber ERROR path leads down to the local database; a red FAIL from the server ends the attempt.

18.8 Verifying and troubleshooting AAA

Command Use it to check
show running-config \| section aaa\|tacacs\|radius Method lists, servers, keys (keys appear encrypted)
show aaa servers Each server's state (UP/DEAD), requests, responses, timeouts
show tacacs / show radius statistics Per-protocol counters
test aaa group ADMIN-TAC netadmin <password> legacy Test a login against the server without logging out
show users / who Who is logged in, from where, on which line
debug aaa authentication, debug tacacs, debug radius Watch the exchange (briefly)
Server logs (ISE live logs) The server's reason for a reject: bad password, unknown device, wrong secret
Symptom Likely cause Fix
Locked out right after aaa new-model No local user, or method list pointing at an unreachable server with no fallback Console access; create the local user first next time
Every login fails, server log shows "invalid shared secret" or no record Key differs, or the device is not added as a client on the server Match keys; add the device's source IP as a client
Server marked DEAD, logins use local No route to the server, ACL blocking TCP 49 / UDP 1812, wrong source interface Ping the server sourced from the AAA source interface; fix routing or ACLs
Valid user rejected, local account not tried Server answered reject (FAIL); fallback applies only to ERROR Fix the user on the server
Login works but lands at > (privilege 1) No aaa authorization exec, or server not returning priv-lvl 15 Configure exec authorization; set the shell profile on the server
Console also asks the server default list applies to the console Separate named list CONSOLE with local
No accounting records Accounting not configured, or wrong port 1813/1646 on RADIUS Configure accounting; match ports

18.9 Packet Tracer Lab 18.1 — SSH with TACACS+ and RADIUS, and local fallback (Intermediate–Advanced)

Objective: 4.1. Start from: your Lab 14.1 file. You will: add an AAA server in the management VLAN, make DSW1 a TACACS+ client and SW1 a RADIUS client for SSH logins, keep local accounts as fallback, and prove the ERROR-versus-FAIL rule.

New device: 1 × Server-PT (AAA-1) cabled to SW1 Fa0/5.

Figure 18.3 shows only the devices this lab touches; the rest of the campus (Figure 14.4) is unchanged. The two dashed arrows are the two AAA protocols, each from its client to the same server.

Item Value
AAA-1 10.10.99.20/24, gateway 10.10.99.1 (VLAN 99 virtual IP)
SW1 Fa0/5 switchport mode access, switchport access vlan 99
AAA clients on the server DSW1 10.10.99.2, TACACS, key T4cacs-Sh4red-Key; SW1 10.10.99.11, RADIUS, key R4dius-Sh4red-Key
Server user alice / Al1ce-2026
Local fallback user (on DSW1 and SW1) netadmin / N3t-Admin-2026

AAA-1: Desktop → IP Configuration (static address above); Services → AAA → On; add the two clients (Client Name, Client IP, Secret, Server Type) and user alice.

DSW1 — TACACS+ client (Packet Tracer uses the older server syntax; algorithm-type scrypt may be unavailable, so plain secret is used)

configure terminal
enable secret En4ble-2026
username netadmin privilege 15 secret N3t-Admin-2026
ip domain-name campus.example
crypto key generate rsa
! answer 2048 when asked for the modulus
ip ssh version 2
aaa new-model
tacacs-server host 10.10.99.20 key T4cacs-Sh4red-Key
aaa authentication login VTY-AUTH group tacacs+ local
aaa authentication login CONSOLE local
line vty 0 15
 login authentication VTY-AUTH
 transport input ssh
line console 0
 login authentication CONSOLE
end

SW1 — RADIUS client

configure terminal
enable secret En4ble-2026
username netadmin privilege 15 secret N3t-Admin-2026
ip domain-name campus.example
crypto key generate rsa
ip ssh version 2
aaa new-model
radius-server host 10.10.99.20 key R4dius-Sh4red-Key
aaa authentication login default group radius local
line vty 0 15
 transport input ssh
end

(SW1's VTY lines use the default list automatically; so does its console — acceptable here because of the local fallback, but in production give the console its own local list as on DSW1.) Test every login before copy running-config startup-config.

PT note Packet Tracer's AAA server cannot send a privilege level, so server users arrive at > and use enable with the enable secret. Real servers (ISE) return privilege 15 with exec authorization (18.6).

Tests and expected results (from PC1's Command Prompt)

Test Command Expected Why
1 ssh -l alice 10.10.99.2 Logged in (DSW1>) TACACS+ PASS
2 ssh -l netadmin 10.10.99.2 Refused Server answers reject (FAIL): local not tried
3 ssh -l alice 10.10.99.11 Logged in on SW1 RADIUS PASS
4 On SW1 shutdown Fa0/5, then ssh -l netadmin 10.10.99.2 Logged in after a delay Server unreachable (ERROR): local used
5 Same, ssh -l alice 10.10.99.2 Refused alice exists only on the server
6 Restore Fa0/5; on DSW1 change the key to Wrong-Key alice refused; netadmin often allowed An unusable reply is usually treated as an error, so a key mismatch can look like a dead server
7 telnet 10.10.99.2 from PC1 Refused transport input ssh

Restore the correct key, then save on both switches.

18.10 Chapter 18 summary notes (exam revision)

  • Local accounts: username <name> privilege 15 algorithm-type scrypt secret <pw> (type 9); enable algorithm-type scrypt secret; type 7 is reversible; login local on lines; login block-for; exec-timeout.
  • SSH: hostname + ip domain-name + crypto key generate rsa modulus 2048 + ip ssh version 2 + transport input ssh + login local (or an AAA list).
  • AAA: Authentication (who), Authorization (what), Accounting (record). Device = AAA client; server = ISE or similar; shared key per client.
  • TACACS+: TCP 49, encrypts all, separates A/A/A, per-command authorization — device administration. RADIUS: UDP 1812/1813 (1645/1646), encrypts the password only, combines authentication and authorization — network access.
  • Config: aaa new-model; tacacs server/radius server + address + key; aaa group server; aaa authentication login <list> group <grp> local; aaa authorization exec; aaa accounting exec|commands; login authentication <list> on lines. Older syntax: tacacs-server host … key ….
  • Method lists: left to right; next method only on ERROR (no answer), never on FAIL (reject).
  • Verify: show aaa servers, test aaa group …, show users, debug aaa authentication, server logs.

Common conceptual mistakes

Mistake Correct idea
"local after the server is used when the password is wrong on the server" Only when the server does not answer
"RADIUS encrypts the whole packet" Only the password; TACACS+ encrypts the payload
"service password-encryption makes passwords safe" Type 7 is reversible; use secret with scrypt
"aaa new-model changes nothing until lists are written" It applies default login behaviour immediately
"The server identifies the device by hostname" By the source IP of the request plus the shared key

11. (Accounting) Which command records every privileged-level command an administrator types?

18.12 Answer key with explanations

  1. B. TACACS+ uses TCP 49. UDP 1812 is RADIUS authentication.
  2. Any two: TCP vs UDP; whole payload encrypted vs password only; separate vs combined authentication/authorization; per-command authorization (TACACS+ only); Cisco-originated vs open standard; typical use device admin vs network access.
  3. ip domain-name campus.example → crypto key generate rsa modulus 2048 → ip ssh version 2 → username … → line vty 0 15 → login local → transport input ssh.
  4. No. A reject is a FAIL; the local method is used only on ERROR (no answer).
  5. Yes (after the timeout). The server gives no answer, an ERROR, so IOS moves to the local database.
  6. It is a type 7 password: reversible, offering almost no protection. Replace it with username ops algorithm-type scrypt secret ….
  7. Either register 10.0.0.2 as the client on the server, or (better) fix the source with ip tacacs source-interface Vlan99 / ip radius source-interface Vlan99 so requests come from 10.10.99.2.
  8. aaa authorization exec … on the device (and a privilege-15 shell profile on the server).
  9. A and C. RADIUS encrypts only the password, has no per-command authorization, and is an open standard.
  10. So that console access never depends on the network or a server: it is the way back in when AAA or routing is broken.
  11. aaa accounting commands 15 default start-stop group <tacacs-group> (command accounting is a TACACS+ feature).
  12. After 3 failed logins within 60 seconds, all logins are blocked for 120 seconds (quiet mode), slowing password-guessing attacks.
  13. With local first, IOS checks local accounts and only asks TACACS+ if the local database gives no answer — so centralised control and per-user revocation are lost, and stale local passwords stay valid. Put the server group first and local last as a fallback.
