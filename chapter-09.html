9.2 Why loops are deadly

Redundant links between switches are good: if one fails, another carries traffic. But Ethernet frames have no TTL field, so a frame caught in a Layer 2 loop circulates forever (Figure 9.1). Three things happen within seconds:

In Figure 9.1 the red arrows follow one copy of PC1's broadcast around the triangle. Each switch floods it out every port except the one it arrived on, so it never stops and every lap adds more copies. The numbered effects below happen in parallel.

  1. Broadcast storm — every switch floods each broadcast out every other port, so copies multiply until links and CPUs are saturated.
  2. MAC address table instability — the same source MAC arrives on different ports, so the switch keeps relearning it (%SW_MATM-4-MACFLAP_NOTIF).
  3. Duplicate frames — hosts receive multiple copies of the same unicast frame.

Spanning Tree Protocol (STP) prevents this by choosing one loop-free tree through the switches and blocking the redundant ports. If an active link fails, STP unblocks a backup path.

9.3 The STP family

Protocol Standard Instances Convergence Notes
STP IEEE 802.1D One for all VLANs 30–50 s Original; obsolete
PVST+ Cisco One per VLAN 30–50 s 802.1D per VLAN
RSTP IEEE 802.1w One for all VLANs Typically under a few seconds Rapid convergence
Rapid PVST+ Cisco One RSTP instance per VLAN Rapid The v2.0 objective; default on many current Cisco switches
MSTP IEEE 802.1s Groups VLANs into a few instances Rapid Large networks; not a v2.0 objective

"Per VLAN" means each VLAN can have a different root bridge and different blocked ports, which lets you use all links across different VLANs (9.9).

9.4 Bridge ID and BPDUs

Switches running STP exchange BPDUs (Bridge Protocol Data Units) to build the tree. In RSTP every switch sends a BPDU on its designated ports every hello time (2 s); a neighbor is considered lost after three missed hellos (6 s). Each BPDU carries the sender's view of who the root is, its cost to reach the root, and its own bridge ID.

The bridge ID (BID) is 8 bytes (Figure 9.2):

Figure 9.2 shows why priorities jump in steps of 4096: the priority has only 4 bits, sitting above the 12-bit VLAN field. IOS prints the two together as one number, which is why VLAN 10's default appears as 32778.

Part Bits Meaning
Bridge priority 4 Configurable in steps of 4096: 0, 4096, 8192 … 61440. Default 32768
Extended system ID 12 The VLAN number, added to the priority
MAC address 48 A MAC address of the switch (the tie-breaker)

So in VLAN 10 a switch with default priority shows 32778 (32768 + 10). Lower BID is better. The priority is compared first; the MAC address decides only when priorities are equal.

9.5 Port cost

Each port has a cost based on its speed; a switch's root path cost is the sum of the costs of the ports a BPDU enters on the way from the root. Cisco switches commonly use the short method by default; some platforms use the long method (spanning-tree pathcost method long).

Link speed Short (802.1D-1998) cost Long (802.1t) cost
10 Mb/s 100 2,000,000
100 Mb/s 19 200,000
1 Gb/s 4 20,000
10 Gb/s 2 2,000
2 × 1 Gb/s EtherChannel 3 10,000

9.6 The election in four steps

Worked example (Figure 9.3): SW-A, SW-B and SW-C in a triangle, all 1 Gb/s links (cost 4), all at default priority, VLAN 10. MACs: SW-A 0011.1111.1111, SW-B 0022.2222.2222, SW-C 0033.3333.3333.

Figure 9.3 is the end state of the four steps below. Every link has exactly one designated port, every non-root switch exactly one root port, and the single leftover port (red) discards.

  1. Elect one root bridge per VLAN — lowest BID. All priorities are 32778, so the lowest MAC wins: SW-A is root. Every port on the root bridge is a designated port.
  2. Each non-root switch picks one root port — lowest root path cost. SW-B reaches SW-A directly for 4 (via C would be 8): SW-B Gi0/1 is its root port. Likewise SW-C Gi0/1.
  3. Each link (segment) picks one designated port — the side advertising the lowest root path cost. On the SW-B–SW-C link both advertise cost 4, a tie.
  4. Break ties in this order: lowest root path cost → lowest sender bridge ID → lowest sender port priority → lowest sender port number. SW-B's BID is lower than SW-C's, so SW-B Gi0/2 is designated. SW-C Gi0/2 is neither root nor designated, so it becomes an alternate port and discards — the loop is broken.

Exam method: find the root first; then on each non-root switch find its cheapest path to the root (root port); then on each link the end closer to the root is designated; every port left over is alternate (or backup) and blocks.

Common trapsThe root bridge is chosen by BID, not by speed or position, so an old access switch can become root by accident if nobody sets priorities. Cost is added for the ports a BPDU enters, not exits.

Memory trickEvery STP tie-break is lowest wins: bridge ID → root path cost → sender bridge ID → sender port ID. Elect the root bridge, then a root port per switch, then a designated port per link — everything left blocks.

9.7 RSTP port roles (2.5.a)

Role Abbreviation in IOS Meaning State in a stable network
Root port Root The one port on a non-root switch with the best path to the root bridge Forwarding
Designated port Desg The one port on each link that forwards toward that link (all ports of the root bridge are designated) Forwarding
Alternate port Altn A backup path to the root through a different switch; ready to become the root port instantly Discarding
Backup port Back A backup for a designated port on the same shared segment (rare: needs a hub) Discarding
Disabled — Shut down or not participating —

Root bridge "primary" and "secondary" are not port roles; they are the switches you choose to be root and backup root for a VLAN (9.9).

9.8 RSTP port states (2.5.b) and rapid convergence

RSTP reduces 802.1D's five states to three:

802.1D state RSTP state Learns MACs? Forwards frames?
Disabled Discarding No No
Blocking Discarding No No
Listening Discarding No No
Learning Learning Yes No
Forwarding Forwarding Yes Yes

Why RSTP is fast:

  1. Alternate ports are pre-computed. If the root port fails, the alternate port becomes the root port and starts forwarding immediately.
  2. Proposal/agreement handshake. On a point-to-point link a new designated port sends a proposal; the neighbor syncs its own ports and replies with an agreement, and the port forwards at once instead of waiting through timers.
  3. Edge ports (PortFast) go straight to forwarding because nothing can loop through an end host.
  4. Faster failure detection: three missed hellos (6 s) instead of the 20 s max age.

Link types decide whether the handshake can be used: point-to-point (full-duplex links between switches, the normal case), shared (half duplex, old hubs — falls back to slower timers) and edge (PortFast ports). show spanning-tree prints them in the Type column (P2p, Shr, P2p Edge).

Timers (defaults): hello 2 s, max age 20 s, forward delay 15 s. RSTP rarely relies on max age and forward delay; you should not need to change any of them for the exam.

Memory trickRSTP has only three states — Discarding, Learning, Forwarding. Discarding absorbs the old blocking, listening and disabled states.

9.9 Configuring Rapid PVST+

Step 1 — run Rapid PVST+ on every switch. Some platforms default to PVST+ (802.1D); mixing works but loses the rapid behaviour on those links.

DSW1
DSW1(config)# spanning-tree mode rapid-pvst

Step 2 — choose the root bridges deliberately (2.5.a). Put the root on a distribution switch, never leave it to chance:

DSW1
DSW1(config)# spanning-tree vlan 10,30 root primary       ! DSW1 = root for VLANs 10 and 30
DSW1(config)# spanning-tree vlan 40,99 root secondary     ! backup root for 40 and 99
DSW2(config)# spanning-tree vlan 40,99 root primary
DSW2(config)# spanning-tree vlan 10,30 root secondary

root primary is a macro: it sets the priority to 24576, or lower if needed to beat the current root. root secondary sets 28672, so the switch takes over only if the primary fails. Both are one-time calculations written into the configuration as spanning-tree vlan X priority N.

You can also set the value directly (multiples of 4096):

DSW1
DSW1(config)# spanning-tree vlan 10 priority 4096

Step 3 (optional) — influence the path with cost or port priority on an interface:

SW1
SW1(config)# interface fastethernet0/24
SW1(config-if)# spanning-tree vlan 40 cost 2                ! make this path cheaper for VLAN 40
SW1(config-if)# spanning-tree vlan 40 port-priority 64      ! 0-240 in steps of 16; default 128; lower wins

Remember: cost changes the decision on the switch where you configure it (its root port); port priority affects the neighbor's choice, because the neighbor compares the sender's port ID.

Command Mode Effect
spanning-tree mode rapid-pvst Global Enable Rapid PVST+
spanning-tree vlan <list> root primary / secondary Global Make this switch root / backup root
spanning-tree vlan <list> priority <0–61440> Global Set bridge priority (multiple of 4096)
spanning-tree vlan <list> cost <n> Interface Override the port cost for those VLANs
spanning-tree vlan <list> port-priority <0–240> Interface Override port priority (multiple of 16)
spanning-tree pathcost method {short \| long} Global Choose the cost scale

Per-VLAN load sharing. With DSW1 root for VLANs 10 and 30 and DSW2 root for 40 and 99, each VLAN builds its own tree, so different VLANs block different links and both distribution switches carry traffic. Align the STP root with the VLAN's default gateway (the SVI or FHRP active router, Chapter 13) so traffic does not take an extra hop.

9.10 PortFast (2.5.c)

Without PortFast, a newly connected access port must negotiate or wait before forwarding; a PC may time out on DHCP. PortFast marks a port as an edge port that moves straight to forwarding, because an end host cannot create a loop.

SW1
SW1(config)# interface fastethernet0/1
SW1(config-if)# spanning-tree portfast                 ! one access port
SW1(config)# spanning-tree portfast default            ! global: all access (non-trunk) ports
SW1(config-if)# spanning-tree portfast trunk           ! a trunk to a server/hypervisor (Chapter 7)

Newer IOS releases use spanning-tree portfast edge, spanning-tree portfast edge default and spanning-tree portfast edge trunk. IOS prints a warning when you enable PortFast, reminding you to use it only on host ports. A PortFast port still sends BPDUs; if it receives one it loses edge status and runs normal STP. Never enable PortFast on a link to another switch.

9.11 BPDU guard, root guard and loop guard (2.5.d)

These three features protect the tree from mistakes and attacks. Figure 9.4 shows where each belongs.

In Figure 9.4 each coloured dot marks the port end where a feature is configured, and the text beside each row names it. Root guard sits on the distribution side of the access links, loop guard on the access side of the same links, and PortFast with BPDU guard on every host port.

BPDU guard — for edge ports. If any BPDU arrives (someone plugged in a switch), the port is err-disabled immediately.

SW1
SW1(config-if)# spanning-tree bpduguard enable                 ! per port
SW1(config)# spanning-tree portfast bpduguard default          ! global: all PortFast ports
%SPANTREE-2-BLOCK_BPDUGUARD: Received BPDU on port Fa0/1 with BPDU Guard enabled. Disabling port.
%PM-4-ERR_DISABLE: bpduguard error detected on Fa0/1, putting Fa0/1 in err-disable state

Recover by removing the cause and then shutdown / no shutdown, or automatically with errdisable recovery cause bpduguard and errdisable recovery interval 300 (seconds).

Root guard — for designated ports that should never lead toward the root, typically distribution-switch downlinks to access switches. If a superior BPDU (one claiming a better root) arrives, the port is placed in root-inconsistent state (discarding). It recovers automatically when the superior BPDUs stop.

DSW1
DSW1(config)# interface port-channel 1
DSW1(config-if)# spanning-tree guard root
%SPANTREE-2-ROOTGUARD_BLOCK: Root guard blocking port Port-channel1 on VLAN0010.

Loop guard — for root and alternate ports (the uplinks of access switches). If BPDUs stop arriving on such a port — for example because one fibre strand failed and the link is now unidirectional — normal STP would wrongly turn it into a forwarding designated port and create a loop. Loop guard instead puts it in loop-inconsistent state (discarding) until BPDUs return.

SW1
SW1(config)# spanning-tree loopguard default        ! global: all point-to-point ports
SW1(config-if)# spanning-tree guard loop            ! or per port
Feature Put it on Triggered by Action Recovery
PortFast Edge (host) ports — Port forwards immediately —
BPDU guard Edge ports Any BPDU received err-disabled Manual bounce or errdisable recovery
Root guard Distribution downlinks (designated ports) Superior BPDU received root-inconsistent (discarding) Automatic when superior BPDUs stop
Loop guard Access uplinks (root and alternate ports) Missing BPDUs loop-inconsistent (discarding) Automatic when BPDUs resume

Root guard and loop guard cannot be enabled on the same port. BPDU filter (stops sending and receiving BPDUs) also exists, but it disables protection and is not a v2.0 objective; avoid it unless a design specifically requires it.

show spanning-tree inconsistentports lists ports blocked by root guard or loop guard; show interfaces status err-disabled lists ports shut by BPDU guard.

9.13 Troubleshooting Rapid PVST+

Symptom Likely cause Fix
Traffic takes a strange path; an access switch is root Root left to default priorities; oldest switch (lowest MAC) won root primary / secondary on the distribution switches
A new switch plugged into an access port takes over as root No root guard on distribution downlinks, no BPDU guard on edge ports Root guard on downlinks; BPDU guard on edge ports
Host port err-disabled BPDU guard saw a BPDU (a switch or a bridging device was connected) Remove the device, bounce the port, or enable errdisable recovery
PCs wait \~30 s for a link and DHCP fails PortFast missing on access ports spanning-tree portfast (or portfast default)
Broadcast storm, MAC flapping, high CPU A loop: PortFast + BPDU filter on a switch link, a unidirectional link, or STP disabled Find the loop, re-enable STP protection, add loop guard
Port stuck root-inconsistent A downstream switch claims a better root Fix that switch's priority; port recovers by itself
Port stuck loop-inconsistent BPDUs not arriving (unidirectional fibre, faulty transceiver) Fix the physical link (Chapter 1); port recovers when BPDUs resume
Slow convergence on some links Neighbor runs legacy PVST+, or link type shared (half duplex) spanning-tree mode rapid-pvst everywhere; fix duplex

Why no root guard on DSW2's downlinks here? Root guard forces a port to stay designated. 9.16 Chapter 9 summary notes (exam revision)

  • Loops cause broadcast storms, MAC flapping and duplicate frames because Ethernet has no TTL. STP blocks redundant ports.
  • Rapid PVST+ = one RSTP instance per VLAN. spanning-tree mode rapid-pvst.
  • BID = priority (multiple of 4096, default 32768) + VLAN number + MAC. Lowest wins. VLAN 10 default shows 32778.
  • Election: lowest BID = root (all its ports designated) → each non-root switch's lowest-cost path = root port → each link's lowest-cost side = designated → the rest are alternate (discarding). Ties: root cost → sender BID → sender port priority → sender port number.
  • Costs (short): 10M 100, 100M 19, 1G 4, 10G 2, 2×1G bundle 3.
  • Roles: root, designated, alternate, backup. States: discarding, learning, forwarding.
  • root primary = priority 24576 (or lower); root secondary = 28672. Put roots on distribution switches; share VLANs between them.
  • PortFast on host ports only; BPDU guard err-disables on any BPDU; root guard blocks on a superior BPDU (root-inconsistent, auto-recovers); loop guard blocks when BPDUs stop (loop-inconsistent, auto-recovers).

Common conceptual mistakes

Mistake Correct idea
"The fastest or newest switch becomes root" The lowest BID does; set priorities deliberately
"The root bridge has a root port" It has none; all its ports are designated
"Port priority on my switch changes my root port" Port priority influences the neighbor's choice; use cost to change your own
"Root guard and BPDU guard do the same thing" BPDU guard err-disables on any BPDU; root guard blocks only on a superior BPDU and recovers by itself
"PortFast is fine on any port" Only on host-facing ports; on a switch link it risks a loop

A switch can reach the root over a 100 Mb/s link directly, or over two 1 Gb/s links through another switch. Using short costs, which path wins?

Answer it in your head (or on paper) first.

Direct 100 Mb/s costs 19; two 1 Gb/s links cost 4 + 4 = 8. The path through the other switch wins (lower total cost).

9Electionthink, then reveal

SW2 has two 1 Gb/s links to the root bridge SW1: SW2 Gi0/1 connects to SW1 Gi0/2, and SW2 Gi0/2 connects to SW1 Gi0/1. Port priorities are default. Which SW2 port becomes the root port?

Answer it in your head (or on paper) first.

Costs and sender BID are equal (both links go to SW1), and port priority is 128 on both, so the lowest sender port number decides: the link to SW1 Gi0/1, which is SW2's Gi0/2. The neighbor's port ID matters, not your own.

10Conceptthink, then reveal

What happens when a port with BPDU guard receives a BPDU, and what happens when a port with root guard receives a superior BPDU?

Answer it in your head (or on paper) first.

BPDU guard: the port is err-disabled immediately and stays down until bounced or recovered. Root guard: the port goes root-inconsistent (discarding) and recovers automatically when the superior BPDUs stop.

11Designthink, then reveal

A technician enables spanning-tree portfast trunk on the trunk between two access switches to speed up convergence. Is this acceptable?

Answer it in your head (or on paper) first.

No. PortFast tells STP the port cannot form a loop; between two switches it can. Use PortFast only toward hosts (and host trunks such as hypervisors).

12Conceptthink, then reveal

What problem does loop guard solve?

Answer it in your head (or on paper) first.

If BPDUs stop arriving on a root or alternate port (for example on a unidirectional link), normal STP would make that port designated and forwarding, creating a loop. Loop guard puts it in loop-inconsistent (blocked) state instead until BPDUs return.
