Chapter 8Validating network documentation with CDP and LLDP

🖼️ 3 figures⏱️ ~15 min read

Objective covered: 2.3 Validate the accuracy of network documentation using CDP and LLDP. The verb is validate: the exam gives you a topology drawing or port table plus neighbor output and asks what is wrong.

8.1 Learning objectives

After this chapter you can:

  1. Explain what CDP and LLDP are, what they advertise, and which devices they can and cannot see.
  2. Read show cdp neighbors, show lldp neighbors and their detail versions without mixing up local and remote ports.
  3. Enable, disable and tune CDP and LLDP globally and per interface.
  4. Compare CDP with LLDP and explain LLDP-MED.
  5. Follow a repeatable process to compare documentation against discovered neighbors and correct the right thing.
  6. Decide where to disable discovery protocols for security.

8.2 Introduction: documentation drifts

A network drawing is correct on the day it is made. Then a technician moves a cable to a spare port, a switch is replaced by a different model, a management address changes — and nobody updates the drawing. Months later someone troubleshoots from the wrong picture. CDP and LLDP let devices describe their own direct connections, so you can check the documentation against what is really cabled.

Both are Layer 2 protocols: a device sends periodic advertisements out each interface, and the directly connected neighbor stores them. Advertisements are never forwarded, so a device learns only about its directly connected neighbors (Figure 8.1). They also work only between devices that run the protocol: switches, routers, IP phones and APs do; most PCs and printers do not.

In Figure 8.1 the arrows are advertisements on each link, in both directions. Because DSW1 does not pass SW1's advertisement on to R1, building a full network map means logging in to each device in turn and following the neighbors hop by hop. PC1 is invisible to both protocols, so end hosts are documented from the MAC address table instead.

CDP LLDP
Standard Cisco proprietary IEEE 802.1AB, any vendor
Default on Cisco IOS Enabled Often disabled (enable with lldp run)
Advertisement timer 60 s 30 s
Holdtime 180 s 120 s
Destination MAC 01:00:0C:CC:CC:CC 01:80:C2:00:00:0E
Extras Native VLAN, duplex, VTP domain, voice VLAN, power Extensible TLVs; LLDP-MED for phones (voice VLAN, PoE)

8.3 CDP (Cisco Discovery Protocol)

CDP runs on Cisco routers, switches, IP phones and APs, and is enabled by default on every interface. CDP version 2 is the default.

What CDP advertises: device ID (hostname), management IP address(es), local port the advertisement left from, platform (model), capabilities (router, switch, phone…), software version, and on CDPv2 the native VLAN, duplex, VTP domain, and for phones the voice VLAN and power request.

Column Belongs to Meaning
Device ID Neighbor Neighbor's hostname
Local Intrfce This device My port the neighbor is connected to

Platform Neighbor Neighbor's model (often truncated)

The classic exam trap: "Local Intrfce" is yours; "Port ID" is the neighbor's. Read the line above as: my Gi1/0/24 connects to R1's G0/0/0. Note also that each member of an EtherChannel appears separately — CDP runs on physical links, not on the port-channel.

cdp run / no cdp run Global config Enable / disable CDP on the whole device

CDP also produces two useful log messages you met earlier: %CDP-4-DUPLEX_MISMATCH (Chapter 1) and %CDP-4-NATIVE_VLAN_MISMATCH (Chapter 5). Both are documentation clues too.

8.4 LLDP (Link Layer Discovery Protocol)

LLDP (IEEE 802.1AB) does the same job as CDP but is vendor-neutral, so it discovers non-Cisco switches, servers, firewalls and phones. Information is carried in TLVs (type-length-value fields). Mandatory TLVs are chassis ID, port ID and time-to-live; optional ones include system name, system description, system capabilities, port description and management address.

On many Cisco IOS devices LLDP is off by default. Turn it on globally; each interface then both transmits and receives unless you say otherwise:

DSW1(config)# lldp run                                ! enable globally
DSW1(config)# interface gigabitethernet1/0/24
DSW1(config-if)# no lldp transmit                     ! stop sending on this port
DSW1(config-if)# no lldp receive                      ! stop listening on this port
Command Mode Effect
lldp run / no lldp run Global config Enable / disable LLDP
lldp transmit / lldp receive Interface config Per-direction control (both on once LLDP runs)
lldp timer 30 Global config Advertisement interval (default 30 s)
lldp holdtime 120 Global config How long neighbors keep the entry (default 120 s)
lldp reinit 2 Global config Delay before LLDP initializes on a port (default 2 s)
show lldp Privileged EXEC Status and timers
show lldp neighbors [detail] Privileged EXEC Neighbor table / full TLVs
show lldp interface Privileged EXEC Per-interface transmit/receive state 
DSW1# show lldp neighbors
Capability codes:
    (R) Router, (B) Bridge, (T) Telephone, (C) DOCSIS Cable Device
    (W) WLAN Access Point, (P) Repeater, (S) Station, (O) Other

Device ID           Local Intf     Hold-time  Capability      Port ID
SW1                 Gi1/0/1        120        B               Gi0/1
SW2                 Gi1/0/2        120        B               Gi0/1
R1                  Gi1/0/24       120        R               Gi0/0/0
...
Total entries displayed: 7

The same rule applies: Local Intf is yours, Port ID is the neighbor's. LLDP capability codes differ from CDP's — a switch is B (bridge), a phone T, an AP W.

LLDP-MED (Media Endpoint Discovery) extends LLDP for endpoints such as IP phones: the switch advertises the voice VLAN and QoS settings in a Network Policy TLV, and the phone reports its PoE needs and inventory. It is how non-Cisco phones learn their voice VLAN (Chapter 7).

8.5 CDP or LLDP? And when to turn them off

Situation Use
All-Cisco network CDP (already on); LLDP optional
Mixed vendors, servers, Linux hosts LLDP
Non-Cisco IP phones LLDP-MED
Cisco IP phones CDP (or LLDP-MED)

Security. Advertisements reveal hostnames, models, software versions and management IPs — useful to an attacker planning an exploit. Best practice:

  • Disable on ports facing untrusted networks: the Internet edge, ISP links, guest-facing ports (no cdp enable, no lldp transmit).
  • Keep them on infrastructure links and on IP phone ports, where the voice VLAN depends on them.
  • Some organisations disable CDP globally and use LLDP only where needed.

8.6 A repeatable validation process

Figure 8.2 shows the loop. In words:

  1. Collect the documentation: topology drawing, port-to-port connection table, IP addressing plan, device inventory (models, software).
  2. Gather the evidence on every switch and router: show cdp neighbors detail and/or show lldp neighbors detail, plus show interfaces description and show interfaces status.
  3. Compare field by field for every link: neighbor hostname, local port, remote port, platform/model, management IP, and (CDP) native VLAN and duplex.
  4. For each mismatch, decide what is wrong. If the network works and follows the design standard, the documentation is wrong: update it. If the documented design is the approved standard (for example a cabling plan), the network is wrong: fix it through change control, then re-check.
  5. Hosts that do not run CDP/LLDP (PCs, printers): verify with show mac address-table interface <port> and the DHCP or ARP tables.
  6. Publish the corrected documentation with the date and who verified it, and update interface descriptions so the next audit is faster.

Figure 8.2 runs once per link. Matching links go straight to the published record; mismatches go either to a documentation fix or, when the network breaks the approved design, to a change that is re-checked from step 2.

DSW1 port Documented neighbor and port Discovered by CDP Result Action
Gi1/0/1 SW1 Gi0/1, mgmt 10.10.99.21 SW1 Gi0/1, IP 10.10.99.11 IP differs SVI is .11 by design: correct the documentation

Three lessons from this audit:

  • Read the Port ID column for the far end; reading the local column instead is the most common error.
  • CDP lists each EtherChannel member, so a bundle appears as two lines; the documentation should record every member and the port-channel number.
  • A mismatch does not automatically mean the network is wrong. Decide which one matches the approved design.

8.8 Troubleshooting CDP and LLDP

Symptom Likely cause Check / fix
Neighbor missing from show cdp neighbors Link down; CDP disabled globally or on either interface; neighbor is not Cisco show interfaces status; show cdp interface; use LLDP for non-Cisco devices
Nothing in show lldp neighbors LLDP not enabled (lldp run) on one or both sides show lldp; enable it
Neighbor appears only one way One side has no lldp transmit or no cdp enable show lldp interface / show cdp interface on both ends
Old neighbor still listed after re-cabling Entry has not aged out yet (holdtime 180 s CDP, 120 s LLDP) Wait, or clear cdp table / clear lldp table
Router two hops away is not listed Expected: advertisements are not forwarded Log in to the next device and continue hop by hop
PCs and printers never appear They do not run CDP/LLDP Use show mac address-table, ARP and DHCP tables
%CDP-4-NATIVE_VLAN_MISMATCH or %CDP-4-DUPLEX_MISMATCH Configuration mismatch on the link Fix the trunk or duplex settings (Chapters 1 and 5)

8.10 Chapter 8 summary notes (exam revision)

  • CDP: Cisco proprietary, on by default, every 60 s, holdtime 180 s; CDPv2 adds native VLAN and duplex. cdp run (global), cdp enable (interface).
  • LLDP: IEEE 802.1AB, often off by default on Cisco IOS (lldp run), every 30 s, holdtime 120 s, reinit 2 s; per-interface lldp transmit / lldp receive. LLDP-MED gives phones their voice VLAN and PoE information.
  • Scope: directly connected neighbors only; advertisements are never forwarded. PCs and printers usually run neither protocol.
  • Reading output: Local Intrfce / Local Intf = my port; Port ID = the neighbor's port. Each EtherChannel member is listed separately.
  • detail / show cdp entry adds management IP, full platform, software version, native VLAN and duplex.
  • Validation: compare hostname, both ports, model, IP (and VLAN/duplex) for every link; correct whichever side breaks the approved design; verify hosts with MAC, ARP and DHCP tables; publish dated documentation.
  • Security: disable on untrusted or Internet-facing ports; keep on infrastructure links and phone ports.

Common conceptual mistakes

Mistake Correct idea
"Port ID is my port" Port ID is the neighbor's port
"CDP shows the whole network" Only directly connected neighbors
"LLDP works as soon as it is configured on one side" It must run on both ends (transmit on one, receive on the other)
"A mismatch means the cabling is wrong" Often the documentation is wrong; check the approved design
"CDP can find the printer" Printers and PCs rarely run CDP; use the MAC address table

8.12 Answer key with explanations

  1. No — the ports are swapped. The local port (DSW1's) is Gi1/0/48 and CORE-2's port is Gi1/1/1. Correct documentation: DSW1 Gi1/0/48 connects to CORE-2 Gi1/1/1.
  2. B. LLDP is IEEE 802.1AB; CDP is Cisco proprietary; DTP and VTP are not discovery protocols.
  3. lldp run in global configuration. LLDP is often disabled by default on Cisco IOS.
  4. No. CDP advertisements are not forwarded, so each device sees only directly connected neighbors. You must log in to DSW1 to see SW1.
  5. B. CDP sends every 60 seconds and keeps entries for 180 seconds. A matches LLDP.
  6. A and C. The summary already shows device ID, local interface, capability, platform and port ID; the detail view adds addresses, version, native VLAN and duplex.
  7. C. Advertising device details to the ISP or the Internet helps attackers and serves no purpose. Phone ports need CDP/LLDP for the voice VLAN; internal infrastructure links benefit from it.
  8. It lets the switch advertise the voice VLAN (and QoS) in a network-policy TLV, and lets the phone report its PoE requirements and inventory — the multi-vendor equivalent of what CDP does for Cisco phones.
  9. The documentation. The network is working and matches the approved design, so update the port table (and interface descriptions).
  10. Use show mac address-table interface <port> (and the ARP or DHCP table to match the printer's MAC to its IP), because the printer is invisible to CDP and LLDP.
  11. The old entry on Gi1/0/1 stays until its holdtime (180 s) expires; the new entry on Gi1/0/5 appears immediately. clear cdp table removes it sooner.
  12. No. Gig 1/0/24 is DSW1's port (Local Intrfce) and Gig 0/0/0 is R1's port (Port ID). The correct reading is: DSW1 Gi1/0/24 connects to R1 G0/0/0. Check every assistant summary of neighbor output for this column swap.
