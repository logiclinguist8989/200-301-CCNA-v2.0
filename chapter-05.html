5.2 Introduction

Without VLANs, every device on a switch shares one broadcast domain. In a 300-user college building, every ARP request and DHCP Discover reaches every PC, printer and phone; a guest laptop sits on the same network as the accounts office. VLANs (virtual LANs) let you group ports logically — Staff, Wireless, Printers, Management — regardless of which switch they are on, and keep each group's broadcasts and traffic separate. Moving traffic between VLANs then requires a router or Layer 3 switch, which is where security policy can be applied.

5.3 VLAN concepts

A VLAN is a broadcast domain (Figure 5.1). A switch forwards a frame only to ports in the same VLAN. Each VLAN normally maps to one IP subnet; this guide uses 10.10.VLAN.0/24.

In Figure 5.1 the dashed boxes are VLAN memberships, not separate hardware. The arrows trace PC1's broadcast: SW1 floods it only to PC2, the one other port in VLAN 10. PC3, PC4 and the printer never see it, even though they are on the same switch.

VLAN range Use
1 Default VLAN: every port starts in it; cannot be deleted. Also the default native VLAN
2–1001 Normal range: user VLANs
1002–1005 Reserved for legacy Token Ring and FDDI; cannot be deleted
1006–4094 Extended range (needs VTP transparent mode or VTPv3 on older switches)
0 and 4095 Reserved, never used

Benefits: smaller broadcast domains, security separation (a firewall or ACL controls inter-VLAN traffic), logical grouping across buildings, and easier management (move a user by changing one port).

Best practices used in this guide:

  • Do not put users in VLAN 1. Use a dedicated management VLAN (99).
  • Use an unused VLAN as the trunk native VLAN (999), not VLAN 1.
  • Shut down unused ports and put them in an unused "parking" VLAN.
  • Allow only the VLANs you need on each trunk.

About VTP. VLAN Trunking Protocol can copy VLAN lists between switches, but it is not a v2.0 objective and a mistake can delete VLANs network-wide. This guide creates VLANs on each switch by hand (VTP transparent or off).

5.4 Creating VLANs and Layer 2 access ports (2.1.a)

A Layer 2 interface (a switchport) forwards frames by MAC address within a VLAN. An access port belongs to exactly one data VLAN and sends and receives untagged frames; it connects end devices.

Step 1 — create and name the VLANs (global configuration, then VLAN configuration mode):

SW1
SW1(config)# vlan 10
SW1(config-vlan)# name STAFF
SW1(config-vlan)# vlan 30
SW1(config-vlan)# name WIRELESS
SW1(config-vlan)# vlan 40
SW1(config-vlan)# name PRINTERS
SW1(config-vlan)# vlan 99
SW1(config-vlan)# name MGMT
SW1(config-vlan)# vlan 999
SW1(config-vlan)# name NATIVE
SW1(config-vlan)# exit

Step 2 — make the port an access port and assign the VLAN:

SW1
SW1(config)# interface fastethernet0/1
SW1(config-if)# description PC1 - Staff
SW1(config-if)# switchport mode access
SW1(config-if)# switchport access vlan 10
SW1(config-if)# exit
SW1(config)# interface range fastethernet0/3 - 24
SW1(config-if-range)# shutdown                      ! unused ports off
Command Mode Purpose Notes and common mistakes

name <text> VLAN config Names the VLAN Names are local labels; they do not need to match between switches (but should)

5.5 802.1Q trunks (2.1.b)

When VLAN 10 exists on two switches, the link between them must carry VLAN 10 — and VLAN 30, 40 and 99 too. Rather than one cable per VLAN, a trunk carries many VLANs over one link by tagging each frame with its VLAN ID. IEEE 802.1Q is the standard (Cisco's old ISL is obsolete).

The 802.1Q tag (Figure 5.2). The sending switch inserts 4 bytes between the source MAC and the Type field:

Figure 5.2 zooms into the highlighted tag from Figure 1.3's frame. The 12-bit VID is what tells the receiving switch which VLAN the frame belongs to; the 3-bit PCP is reused for voice priority in Chapter 7.

Field Size Meaning
TPID 16 bits Always 0x8100: "this frame is tagged"
PCP 3 bits Priority (Class of Service) 0–7; IP phones use 5 for voice
DEI 1 bit Drop eligible indicator (formerly CFI)
VID 12 bits VLAN ID: 1–4094 usable

Because the frame changes, the switch recalculates the FCS. The maximum frame size grows from 1518 to 1522 bytes.

How a frame crosses a trunk (Figure 5.3):

  1. PC1 sends an ordinary, untagged frame into its access port on SW1 (VLAN 10).
  2. SW1 decides the destination is reachable through the trunk Gi0/1 and inserts an 802.1Q tag with VID 10.
  3. SW2 receives the tagged frame, reads VID 10, and forwards it only to VLAN 10 ports.
  4. SW2 removes the tag before sending the frame out the access port to PC3, which never sees a tag.

Figure 5.3 matches the four steps above. Arrows show the direction of travel; the thick highlighted link is the trunk. The tag exists only on the trunk, which is why end devices on access ports never need to know VLANs exist.

The native VLAN. Frames in the trunk's native VLAN cross the link untagged, and untagged frames received on a trunk are placed in the native VLAN. The default is VLAN 1. Both ends must use the same native VLAN; otherwise traffic leaks between VLANs and CDP reports %CDP-4-NATIVE_VLAN_MISMATCH. Best practice: set it to an unused VLAN (999) on both ends.

Configuring a trunk:

SW1
SW1(config)# interface gigabitethernet0/1
SW1(config-if)# description Trunk to DSW1 Gi1/0/1
SW1(config-if)# switchport trunk encapsulation dot1q    ! only on switches that also support ISL
SW1(config-if)# switchport mode trunk
SW1(config-if)# switchport trunk native vlan 999
SW1(config-if)# switchport trunk allowed vlan 10,30,40,99
SW1(config-if)# switchport nonegotiate                   ! stop sending DTP
Command Purpose Notes and common mistakes
switchport trunk encapsulation dot1q Chooses 802.1Q Needed only on platforms that support ISL (for example Catalyst 3560); if switchport mode trunk is rejected with "encapsulation is Auto", add this first. Catalyst 2960 and many newer switches support only 802.1Q and do not have the command
switchport mode trunk Forces trunking Both ends should be configured as trunks
switchport trunk native vlan 999 Sets the untagged VLAN Must match on both ends
switchport trunk allowed vlan 10,30,40,99 Replaces the allowed list Typing allowed vlan 50 later replaces the list with only 50
switchport trunk allowed vlan add 50 Adds one VLAN to the list The safe way to add; also remove 50, except 50, all, none
switchport nonegotiate Disables DTP frames Use on manually configured trunks and access ports

DTP (Dynamic Trunking Protocol). A Cisco-proprietary protocol that lets ports negotiate trunking. Its modes and the result for each pair:

Side A \ Side B access trunk dynamic desirable dynamic auto
access Access Mismatch (do not do this) Access Access
trunk Mismatch Trunk Trunk Trunk
dynamic desirable Access Trunk Trunk Trunk
dynamic auto Access Trunk Trunk Access

The classic exam trap: two ports left at dynamic auto (a common default) both wait to be asked and never form a trunk. Best practice is to hard-code switchport mode trunk or switchport mode access and disable DTP, because an attacker's PC can otherwise negotiate a trunk (VLAN hopping).

Memory trickNative = naked. Frames in the native VLAN cross an 802.1Q trunk untagged; every other VLAN wears a 4-byte tag.

5.6 Layer 3 routed ports on a switch (2.1.a)

A multilayer (Layer 3) switch such as a Catalyst 3650 or 9300 can also route. Any physical port can be turned into a routed port: it stops being a switchport, belongs to no VLAN, and takes an IP address like a router interface. Routed ports are used for switch-to-router and switch-to-switch links in routed campus designs.

DSW1
DSW1(config)# ip routing                              ! enable IPv4 routing on the switch
DSW1(config)# interface gigabitethernet1/0/24
DSW1(config-if)# description Routed link to R1 G0/0/0
DSW1(config-if)# no switchport                        ! Layer 2 -> Layer 3
DSW1(config-if)# ip address 10.0.0.2 255.255.255.252
DSW1(config-if)# no shutdown
Layer 2 switchport Layer 3 routed port
Command switchport (default on Catalyst switches) no switchport
Belongs to A VLAN (access) or many VLANs (trunk) No VLAN
Addressing None on the port IP address on the port
Typical link To end devices, to other switches To a router, or between Layer 3 switches
Spanning tree Participates Does not run STP on that port

ip routing is off by default on many Layer 3 switches. Without it, SVIs and routed ports still get addresses, but the switch will not route between them — a very common lab fault.

5.7 Switch virtual interfaces and inter-VLAN routing (2.1.d)

A switch virtual interface (SVI) is a logical Layer 3 interface for a VLAN: interface vlan 10. It gives the switch an IP address inside that VLAN. SVIs have two uses.

1. Management SVI on a Layer 2 switch. An access switch needs one IP address so you can reach it with SSH, SNMP and syslog:

SW1
SW1(config)# interface vlan 99
SW1(config-if)# description Management
SW1(config-if)# ip address 10.10.99.11 255.255.255.0
SW1(config-if)# no shutdown
SW1(config-if)# exit
SW1(config)# ip default-gateway 10.10.99.1          ! a Layer 2 switch is a host: it needs a gateway

2. Gateway SVIs on a multilayer switch (inter-VLAN routing). Each VLAN's SVI is the default gateway for that VLAN, and the switch routes between SVIs internally:

DSW1
DSW1(config)# ip routing
DSW1(config)# interface vlan 10
DSW1(config-if)# ip address 10.10.10.1 255.255.255.0
DSW1(config-if)# no shutdown
DSW1(config-if)# interface vlan 30
DSW1(config-if)# ip address 10.10.30.1 255.255.255.0
DSW1(config-if)# no shutdown

When is an SVI up/up? All of these must be true:

  1. The VLAN exists in the switch's VLAN database and is active.
  2. At least one port in that VLAN (an access port, or a trunk allowing it) is up and in the STP forwarding state.
  3. The SVI is not administratively shut down (no shutdown; SVIs start shut on many switches).

This "autostate" behaviour is why an SVI shows up/down when its VLAN has no active ports.

Comparing inter-VLAN routing methods (Figure 5.4).

The highlighted arrows in Figure 5.4 trace a packet from a VLAN 10 host to a VLAN 30 host. On the left it travels up the trunk to R1 in VLAN 10 and comes back down the same trunk in VLAN 30. On the right it is routed between the two SVIs inside DSW1 and never leaves the switch.

Method How Pros Cons
Router-on-a-stick One router interface, one 802.1Q subinterface per VLAN, trunk to the switch Cheap; works with a Layer 2 switch Single link carries traffic twice (hairpin); router CPU and link become bottlenecks
Multilayer switch SVIs One SVI per VLAN, ip routing Hardware speed, scales, no extra link Needs a Layer 3 switch
Separate router interface per VLAN (legacy) One physical router port per VLAN, access links Simple Wastes ports; does not scale

Router-on-a-stick configuration (the switch side is a normal trunk):

R1
R1(config)# interface gigabitethernet0/0/1
R1(config-if)# no shutdown                          ! enable the physical interface
R1(config-if)# interface gigabitethernet0/0/1.10
R1(config-subif)# description Gateway VLAN 10
R1(config-subif)# encapsulation dot1Q 10
R1(config-subif)# ip address 10.10.10.1 255.255.255.0
R1(config-subif)# interface gigabitethernet0/0/1.30
R1(config-subif)# encapsulation dot1Q 30
R1(config-subif)# ip address 10.10.30.1 255.255.255.0
R1(config-subif)# interface gigabitethernet0/0/1.999
R1(config-subif)# encapsulation dot1Q 999 native   ! match the switch's native VLAN

The subinterface number (.10) is only a label; the encapsulation dot1Q 10 command is what ties it to VLAN 10. Making them match is good practice.

Packet walk: PC1 (VLAN 10) to PC2 (VLAN 30) through DSW1 SVIs.

  1. PC1 sees 10.10.30.11 is in another subnet, so it ARPs for its gateway 10.10.10.1 and sends the frame to the VLAN 10 SVI's MAC.
  2. The frame arrives on DSW1 in VLAN 10 (tagged on the trunk from SW1, or untagged on an access port).
  3. DSW1 routes the packet: destination 10.10.30.0/24 is connected via Vlan30.
  4. DSW1 ARPs for PC2 in VLAN 30 if needed, builds a new frame, and sends it out the VLAN 30 port or trunk.
  5. PC2 receives it from the SVI's MAC as the source. The IP addresses never changed; the MAC addresses did (Chapter 1, Figure 1.2).

5.13 Chapter 5 summary notes (exam revision)

  • VLAN = broadcast domain = (usually) one subnet. Ranges: 1 default; 2–1001 normal; 1002–1005 reserved; 1006–4094 extended.
  • Access port: switchport mode access, switchport access vlan <id>; untagged; one VLAN. Deleting a VLAN leaves its ports inactive.
  • Trunk: switchport mode trunk (+ switchport trunk encapsulation dot1q on ISL-capable switches), native vlan, allowed vlan — use add to append. 802.1Q tag = 4 bytes: TPID 0x8100, PCP 3 bits, DEI 1 bit, VID 12 bits.
  • Native VLAN: untagged on the trunk; must match both ends; default VLAN 1; best practice an unused VLAN.
  • DTP: auto + auto = access; desirable + auto/desirable/trunk = trunk. Hard-code modes and use switchport nonegotiate.
  • show vlan brief lists access ports only; trunks appear in show interfaces trunk (allowed → active → forwarding).
  • Routed port: no switchport + ip address; no VLAN, no STP. Multilayer switches need ip routing.
  • SVI: interface vlan <id>; up/up only if the VLAN exists, has an active forwarding port, and the SVI is no shutdown. Layer 2 switches need ip default-gateway for their management SVI.
  • Router-on-a-stick: subinterface + encapsulation dot1Q <vlan> (+ native for the native VLAN); the physical interface must be no shutdown.

Common conceptual mistakes

Mistake Correct idea
"allowed vlan 50 adds VLAN 50" It replaces the list; use allowed vlan add 50
"A trunk port is missing from show vlan brief, so it is broken" Trunks are never listed there
"The subinterface number sets the VLAN" encapsulation dot1Q <id> sets it
"An SVI with an IP is always up" It needs an active, forwarding port in its VLAN
"A Layer 3 switch routes by default" Many need ip routing first
