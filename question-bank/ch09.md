# Chapter 9 — Rapid PVST+ and STP protection

CCNA-style practice questions for [Chapter 9](../CCNA%20200-301%20v2.0%20Study%20Guide.md#chapter-9--rapid-pvst-and-stp-protection) · Domain 2 · Objectives 2.5 and 2.5.a–d. The format is described in the [question bank README](README.md).

## Questions

### Q1 · Multiple choice — choose two
<sub>Source: 9.2</sub>

An engineer adds a second link between two access switches in a VLAN where spanning tree has been disabled. Within seconds, users in the VLAN lose connectivity. Which two effects of the resulting Layer 2 loop explain this? (Choose two.)

- [x] Broadcast frames circulate around the loop without end and multiply until links and switch CPUs are saturated.
- [x] The switches keep relearning the same source MAC address on different ports and log `%SW_MATM-4-MACFLAP_NOTIF`.
- [ ] Each looping frame is discarded when its TTL reaches zero, so only a short burst of traffic is lost.
- [ ] The switches err-disable the ports at both ends of the new link.
- [ ] The switches block the redundant link automatically once the 20-second max age timer expires.

> **Explanation:** Ethernet frames have **no TTL field**, so a frame caught in a Layer 2 loop circulates forever. Three things happen in parallel: a **broadcast storm**, **MAC address table instability** (the same source MAC arrives on different ports, logged as `MACFLAP_NOTIF`), and duplicate frames delivered to hosts. With spanning tree disabled, no timer ends the loop and no port is blocked or err-disabled — err-disabling needs a feature such as BPDU guard. Spanning tree prevents all of this by blocking the redundant port.

### Q2 · Multiple choice
<sub>Source: 9.4, 9.9</sub>

DSW2 runs Rapid PVST+. The current root bridge for VLAN 99 uses the default bridge priority. An engineer enters `spanning-tree vlan 40,99 root primary` on DSW2. Which priority does the Bridge ID section of `show spanning-tree vlan 99` on DSW2 now display?

- [ ] 24576
- [x] 24675
- [ ] 28771
- [ ] 32867

> **Explanation:** `root primary` is a macro that sets the priority to 24576, or lower if that is needed to beat the current root. A root with the default priority (32768) is beaten by 24576. IOS adds the extended system ID — the VLAN number — so it displays 24576 + 99 = **24675**, printed as `24675 (priority 24576 sys-id-ext 99)`. 24576 alone leaves out the VLAN number, 28771 is the `root secondary` value (28672 + 99), and 32867 is the default (32768 + 99).

### Q3 · Multiple choice
<sub>Source: 9.5, 9.6</sub>

DSW1 is the root bridge for VLAN 10. SW1 has two uplinks: Gi1/0/1, a 1 Gb/s link directly to DSW1, and Te1/1/1, a 10 Gb/s link to DSW2. DSW2's root port is its own 10 Gb/s link to DSW1. All switches use short path costs and the default port costs and port priorities. Which port does SW1 select as its root port for VLAN 10, and what is SW1's root path cost?

- [x] Gi1/0/1, with a root path cost of 4
- [ ] Te1/1/1, with a root path cost of 2
- [ ] Te1/1/1, with a root path cost of 4, because the faster port wins the tie
- [ ] Gi1/0/1, with a root path cost of 8

> **Explanation:** Root path cost is the sum of the costs of the ports a BPDU **enters** on its way from the root. Directly: SW1 Gi1/0/1 costs 4. Through DSW2: DSW2's 10 Gb/s root port (2) plus SW1 Te1/1/1 (2) = 4. The costs tie, so the next tie-breaker is the lowest **sender bridge ID**. On Gi1/0/1 the sender is DSW1, the root itself, which has the lowest bridge ID in the VLAN, so Gi1/0/1 becomes the root port. Counting only the local 10 Gb/s port gives 2, and counting both ends of the direct link gives 8; neither is how cost is added. Port speed is not a tie-breaker — only cost, sender bridge ID, sender port priority and sender port number are.

### Q4 · Drag and drop — order
<sub>Source: 9.6</sub>

Drag the steps of the spanning-tree election for one VLAN into the order in which STP applies them.

1. Elect the root bridge: the switch with the lowest bridge ID
2. On each non-root switch, select the root port: the port with the lowest root path cost
3. On each link, select the designated port: the side advertising the lowest root path cost
4. Put every remaining port into the alternate (or backup) role, where it discards

> **Explanation:** Find the root first — lowest bridge ID, with the priority compared before the MAC address. Every port on the root bridge is designated. Each non-root switch then picks its single cheapest path to the root as its root port, and each link gets one designated port, the end closer to the root. Ports left over are alternate (or backup) and discard, which breaks the loop. Ties at any step are broken by lowest root path cost, then lowest sender bridge ID, then lowest sender port priority, then lowest sender port number.

### Q5 · Drag and drop — match
<sub>Source: 9.7</sub>

Drag the RSTP port role, with its abbreviation in `show spanning-tree`, to the description it matches.

| Description | Port role |
| --- | --- |
| The one port on a non-root switch with the best path to the root bridge | Root port (Root) |
| The one forwarding port on each link; every port on the root bridge has this role | Designated port (Desg) |
| A discarding port that offers a backup path to the root through a different switch | Alternate port (Altn) |
| A discarding port that backs up a designated port on the same shared segment | Backup port (Back) |

**Extra targets:** Edge port (Edge) · Blocking port (Blk)

> **Explanation:** In a stable network root and designated ports forward, while alternate and backup ports discard. An alternate port leads to the root through a **different** switch and takes over at once if the root port fails. A backup port protects a designated port on the **same** shared segment, which needs a hub, so it is rare. "Edge" is a link type that `show spanning-tree` prints in the Type column for PortFast ports, not a role, and "blocking" is an 802.1D state, not an RSTP role (`BLK` in the Sts column means the port is discarding).

### Q6 · Drag and drop — match
<sub>Source: 9.10, 9.11</sub>

Drag the STP feature that meets each requirement to that requirement. Not every feature is used.

| Requirement | Feature |
| --- | --- |
| A user's PC must get a forwarding port as soon as it is connected | PortFast |
| A host port must be err-disabled if anyone connects a switch to it | BPDU guard |
| A distribution downlink must block if an access-layer switch claims to be a better root | Root guard |
| An access-switch uplink must not start forwarding if BPDUs stop arriving over a unidirectional fibre | Loop guard |

**Extra targets:** BPDU filter

> **Explanation:** **PortFast** makes a host port an edge port that forwards immediately. **BPDU guard**, also for edge ports, err-disables the port when **any** BPDU arrives. **Root guard** goes on distribution downlinks (designated ports) and puts the port in root-inconsistent state when a **superior** BPDU arrives. **Loop guard** goes on access uplinks (root and alternate ports) and puts the port in loop-inconsistent state when BPDUs go **missing**, so a unidirectional link cannot turn into a forwarding designated port. BPDU filter stops sending and receiving BPDUs, which removes protection instead of adding it.

### Q7 · Multiple choice
<sub>Source: 9.11, 9.13</sub>

Refer to the exhibit.

```
DSW1#
%SPANTREE-2-ROOTGUARD_BLOCK: Root guard blocking port Port-channel2 on VLAN0010.
%SPANTREE-2-ROOTGUARD_BLOCK: Root guard blocking port Port-channel2 on VLAN0030.
DSW1# show spanning-tree inconsistentports

Name                 Interface              Inconsistency
-------------------- ---------------------- ------------------
VLAN0010             Port-channel2          Root Inconsistent
VLAN0030             Port-channel2          Root Inconsistent

Number of inconsistent ports (segments) in the system : 2
```

DSW1 is the root bridge for VLANs 10 and 30. Po2 is DSW1's downlink to access switch SW2, which has no other uplink. The messages appeared right after a technician changed the spanning-tree configuration on SW2. What should the engineer do to restore Po2?

- [x] Return SW2's bridge priority for VLANs 10 and 30 to a value that does not beat DSW1; Po2 then recovers by itself.
- [ ] Enter `shutdown` and then `no shutdown` on Po2 to clear its err-disabled state.
- [ ] Repair the physical link, because BPDUs from SW2 are no longer arriving on Po2.
- [ ] Remove `spanning-tree guard root` from Po2 so that SW2 can take over as the root bridge.

> **Explanation:** Root guard on Po2 blocked the port because a **superior BPDU** arrived: SW2 now claims a better root than DSW1, for example after a low `spanning-tree vlan 10,30 priority` value. The port is **root-inconsistent** (discarding), not err-disabled, and it recovers **automatically** once the superior BPDUs stop — so fix SW2's priority. A bounce is the recovery for a BPDU guard err-disable, which `show interfaces status err-disabled` would list. Missing BPDUs would be a loop guard event, shown as loop-inconsistent. Removing root guard would let an access switch become root and pull traffic along a poor path.

After a link failure, traffic through DSW2 takes much longer to recover than traffic elsewhere in the campus. DSW2 is meant to be the root bridge for VLAN 40. You are in global configuration mode on DSW2. Enter the command that fixes the problem.

### Q9 · CLI
<sub>Source: 9.11</sub>

SW1 Fa0/3 is a PortFast access port in a meeting room, and visitors sometimes connect small switches to it. You are in interface configuration mode for Fa0/3. Enter the command that err-disables this port as soon as it receives a BPDU, without changing any global setting.

**Prompt:** `SW1(config-if)#`

**Accepted:** `spanning-tree bpduguard enable`

> **Explanation:** `spanning-tree bpduguard enable` turns on BPDU guard for one port. If any BPDU arrives, IOS logs `%SPANTREE-2-BLOCK_BPDUGUARD` and `%PM-4-ERR_DISABLE` and the port is err-disabled. The global command `spanning-tree portfast bpduguard default` would protect every PortFast port instead. To recover, remove the switch and enter `shutdown` / `no shutdown`, or let `errdisable recovery cause bpduguard` bring the port back.

### Q10 · Multiple choice
<sub>Source: 9.5, 9.6, 9.14</sub>

Why is Po2, and not Fa0/24, SW2's root port for VLAN 40, even though Fa0/24 connects directly to the root bridge?

- [x] The path through DSW1 costs 3 + 4 = 7, which is lower than the cost of 19 on the direct 100 Mb/s link.
- [ ] STP always prefers a port-channel to a single physical link.
- [ ] DSW1 is the root bridge for VLAN 40, so the path toward DSW1 is preferred.
- [ ] Loop guard has blocked Fa0/24 because DSW2 sends no BPDUs on that link.

> **Explanation:** The root port is the port with the lowest root path cost: **cost decides, not distance**. Through Po2 the BPDU enters DSW1 Gi1/0/23 (4) and SW2 Po2 (3), for the root path cost of 7 shown under Root ID; the direct link costs 19. The bundle wins because of its low cost, not because it is a port-channel. The root's priority of 24616 (24576 + 40) shows that DSW2, configured with `root primary`, is the root. Fa0/24 is listed as `Altn BLK`, a normal alternate port; a port blocked by loop guard would appear as loop-inconsistent, and DSW2, as the root bridge, sends BPDUs on all its designated ports.

### Q11 · Multiple choice — choose two
<sub>Source: 9.7, 9.8</sub>

Both member links of Po2 fail. Which two statements describe how SW2 reacts in VLAN 40? (Choose two.)

- [x] Fa0/24 becomes the root port and starts forwarding immediately, because the alternate path was already computed.
- [x] SW2's root path cost for VLAN 40 becomes 19.
- [ ] Fa0/24 first waits through the listening and learning states before it forwards.
- [ ] SW2 becomes the root bridge for VLAN 40 because it no longer has a root port.
- [ ] Fa0/24 stays discarding until an engineer enters `shutdown` and `no shutdown` on it.

> **Explanation:** RSTP pre-computes alternate ports: when the root port fails, the alternate port becomes the root port and forwards at once. SW2 now reaches DSW2, the root, only over Fa0/24, so its root path cost is that port's cost, 19. RSTP has no listening state; waiting through listening and learning timers is legacy 802.1D behaviour (30–50 seconds). Losing a root port does not change bridge IDs, so DSW2 stays root. No manual action is needed.

### Q12 · Multiple choice
<sub>Source: 9.5, 9.9</sub>

Po2 is working again. The team wants SW2 to use Fa0/24 as its root port for VLAN 40, while DSW2 stays the root bridge. Which change on SW2 achieves this?

- [x] On Fa0/24: `spanning-tree vlan 40 cost 2`
- [ ] On Fa0/24: `spanning-tree vlan 40 cost 8`
- [ ] On Fa0/24: `spanning-tree vlan 40 port-priority 64`
- [ ] In global configuration mode: `spanning-tree pathcost method long`

> **Explanation:** Cost changes the root port decision on the switch where it is configured. With a cost of 2 on Fa0/24, the direct path to DSW2 costs 2, which beats the 7 through Po2. A cost of 8 is still higher than 7, so Po2 stays the root port. Port priority influences the **neighbor's** choice, because the neighbor compares the sender's port ID; it cannot change SW2's own root port. The long method only rescales the costs: a 100 Mb/s port costs 200,000 there, still far more than the 2 × 1 Gb/s bundle at 10,000.
