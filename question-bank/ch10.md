### Q1 · Multiple choice
<sub>Source: 10.5, 10.10</sub>

Refer to the exhibit.

```
R2# show ip route
Codes: L - local, C - connected, S - static, R - RIP, M - mobile, B - BGP
       D - EIGRP, EX - EIGRP external, O - OSPF, IA - OSPF inter area
       N1 - OSPF NSSA external type 1, N2 - OSPF NSSA external type 2
       E1 - OSPF external type 1, E2 - OSPF external type 2
       i - IS-IS, * - candidate default, + - replicated route ...

Gateway of last resort is 10.0.0.9 to network 0.0.0.0

S*    0.0.0.0/0 [1/0] via 10.0.0.9
      10.0.0.0/8 is variably subnetted, 7 subnets, 5 masks
C        10.0.0.8/30 is directly connected, GigabitEthernet0/0/0
L        10.0.0.10/32 is directly connected, GigabitEthernet0/0/0
C        10.0.0.12/30 is directly connected, GigabitEthernet0/0/1
L        10.0.0.13/32 is directly connected, GigabitEthernet0/0/1
O IA     10.10.0.0/16 [110/2] via 10.0.0.9, 00:21:37, GigabitEthernet0/0/0
O IA     10.10.32.0/19 [110/4] via 10.0.0.14, 00:21:37, GigabitEthernet0/0/1
S        10.10.40.0/24 [1/0] via 10.0.0.14
```

R2 receives a packet for 10.10.50.20. Which route does R2 use to forward it?

- [ ] 10.10.0.0/16 via 10.0.0.9, because its metric is lower
- [x] 10.10.32.0/19 via 10.0.0.14, because it is the longest prefix that contains the destination
- [ ] 10.10.40.0/24 via 10.0.0.14, because static routes have the lowest AD
- [ ] 0.0.0.0/0 via 10.0.0.9, because no more specific route contains the destination

> **Explanation:** Find every route that contains 10.10.50.20 and take the longest. The /19 has a block size of 32 in the third octet, so 10.10.32.0/19 covers 10.10.32.0–10.10.63.255 and contains the address. 10.10.0.0/16 and 0.0.0.0/0 contain it too, but they are shorter. 10.10.40.0/24 is longer but does not contain it (40 ≠ 50), so it is never a candidate. AD and metric are never compared across different prefixes, so the /16's lower metric and the static route's AD 1 do not matter.

### Q2 · Multiple choice
<sub>Source: 10.3, 10.4, 10.6</sub>

R3 learns 10.20.0.0/24 from two sources. OSPF knows two paths to it, with costs 3 and 5. RIP offers the same prefix with a hop count of 1. No other route to this prefix exists. What does R3 install in its routing table for 10.20.0.0/24?

- [x] Only the OSPF path with cost 3
- [ ] Only the RIP route, because a metric of 1 is lower than 3
- [ ] Both OSPF paths, sharing the traffic between them
- [ ] The OSPF path with cost 3 and the RIP route, sharing the traffic between them

> **Explanation:** Same prefix, different sources: administrative distance decides, and OSPF (110) beats RIP (120). Metrics from different protocols cannot be compared, because OSPF uses cost and RIP uses hop count. Within OSPF the lower metric wins, so only the cost-3 path is installed. ECMP would install both OSPF paths only if their costs were equal.

### Q3 · Multiple choice — choose two
<sub>Source: 10.4, 10.6, 10.12</sub>

Which two statements correctly describe how a router chooses routes? (Choose two.)

- [x] Longest prefix match is applied to every packet and looks only at routes already installed in the routing table.
- [x] When one routing protocol finds two paths to the same prefix with equal metrics, both are installed and traffic is shared between them.
- [ ] A static route to 10.10.0.0/16 is used instead of an OSPF route to 10.10.40.0/24 for traffic to 10.10.40.25, because AD 1 is lower than AD 110.
- [ ] The router uses the first route in the table that contains the destination address.
- [ ] When OSPF and RIP offer the same prefix, the route with the lower metric is installed.

> **Explanation:** AD (same prefix, different sources) and metric (same prefix, same protocol) decide what is **installed**; longest prefix match decides which installed route each packet **uses**. Equal metrics give several `via` lines (ECMP). AD never compares different prefixes, so the /24 wins for 10.10.40.25 because it is longer. The router scans the whole table for the longest match, not the first match. Metrics from different protocols are never compared — AD decides.

### Q4 · Drag and drop — order
<sub>Source: 10.2</sub>

Drag the steps a router takes to forward a packet into the correct order.

1. Check the FCS and accept the frame if it is addressed to the router's interface MAC address
2. De-encapsulate the IP packet and decrement the TTL
3. Look up the destination IP address and choose the longest matching prefix
4. Read the next hop and exit interface, with a recursive lookup if the next hop is not directly connected
5. Resolve the next hop's MAC address with ARP (IPv4) or ND (IPv6)
6. Build a new frame with new MAC addresses and a new FCS, and send it out the exit interface

> **Explanation:** The router checks the frame, removes it and decrements the TTL (if the TTL reaches 0 it drops the packet and returns ICMP Time Exceeded). It then looks up the destination; with no match and no default route it drops the packet and returns ICMP Destination Unreachable. Only once the next hop and exit interface are known can it ARP (or use ND) for the next hop and build the new frame. The IP addresses stay the same; the MAC addresses and FCS are new at every hop.

### Q5 · Drag and drop — match
<sub>Source: 10.3</sub>

Drag the default Cisco administrative distance to each route source.

| --- | --- |
| Connected | 0 |
| Static | 1 |
| EIGRP (internal) | 90 |
| OSPF | 110 |
| RIP | 120 |

**Extra targets:** 20 · 170 · 255

> **Explanation:** Lower AD is more trusted. The unused values belong to other sources: 20 is eBGP, 170 is EIGRP external, and 255 means unknown or unusable — such a route is never installed.

### Q6 · Multiple choice
<sub>Source: 10.6</sub>

R1's routing table contains `O 10.10.40.0/24 [110/2] via 10.0.0.2`. An engineer then enters `ip route 10.10.40.0 255.255.255.0 10.0.0.2` on R1. What is the result?

- [x] The static route replaces the OSPF route in the routing table.
- [ ] Both routes are installed, and traffic is shared between them.
- [ ] The OSPF route stays installed, because dynamically learned routes are preferred over static routes.
- [ ] The static route is installed only if OSPF loses the route to 10.10.40.0/24.

> **Explanation:** Both sources offer the same prefix, so administrative distance decides: static (AD 1) beats OSPF (AD 110), and the table now shows `S 10.10.40.0/24 [1/0] via 10.0.0.2`. The OSPF route stays in the OSPF database as a backup. Load sharing happens only between equal-metric paths from one protocol. A route that appears only when OSPF loses the prefix is a floating static, which needs a higher AD such as 130.

### Q7 · Multiple choice
<sub>Source: 10.7, 10.8</sub>

Refer to the exhibit.

```
R1# show ipv6 route
IPv6 Routing Table - default - 8 entries
Codes: C - Connected, L - Local, S - Static, U - Per-user Static route
       O - OSPF Intra, OI - OSPF Inter, OE1 - OSPF ext 1, OE2 - OSPF ext 2
       ND - ND Default, NDp - ND Prefix ...
S   ::/0 [1/0]
     via 2001:DB8:FFFF::1
C   2001:DB8:ACAD:10::/64 [0/0]
     via GigabitEthernet0/0/0, directly connected
L   2001:DB8:ACAD:10::1/128 [0/0]
     via GigabitEthernet0/0/0, receive
O   2001:DB8:ACAD:30::/64 [110/2]
     via FE80::2, GigabitEthernet0/0/1
O   2001:DB8:ACAD:40::/64 [110/2]
     via FE80::2, GigabitEthernet0/0/1
C   2001:DB8:FFFF::/64 [0/0]
     via GigabitEthernet0/0/2, directly connected
L   2001:DB8:FFFF::2/128 [0/0]
     via GigabitEthernet0/0/2, receive
L   FF00::/8 [0/0]
     via Null0, receive
```

R1 receives a packet for 2001:DB8:ACAD:50::9. How does R1 forward it?

- [x] It uses the default route and sends the packet to 2001:DB8:FFFF::1 out G0/0/2.
- [ ] It sends the packet to FE80::2 out G0/0/1, because the OSPF routes are the closest match.
- [ ] It sends the packet out G0/0/0, because 2001:DB8:ACAD:10::/64 matches the first 48 bits.
- [ ] It drops the packet, because no /64 route contains the destination.

> **Explanation:** A /64 route contains the destination only if all of the first 64 bits — the first four hextets — match. The fourth hextet of the destination is 50, so 2001:DB8:ACAD:10::/64, :30::/64 and :40::/64 all fail; a partial match counts for nothing. The only route that contains the address is the default route ::/0, so the packet goes to 2001:DB8:FFFF::1, and a recursive lookup finds that next hop on the connected 2001:DB8:FFFF::/64 out G0/0/2. The packet is dropped only when nothing matches and there is no default route.

### Q8 · Drag and drop — match
<sub>Source: 10.3, 10.9</sub>

Drag each line from `show ip route` output to its meaning.

| Line in the routing table | Meaning |
| --- | --- |
| `S 10.50.0.0/16 is directly connected, GigabitEthernet0/0/1` | Static route with only an exit interface |
| `S 10.60.0.0/16 [1/0] via 10.0.0.2` | Next-hop-only static route with the default AD |
| `S 10.70.0.0/24 [130/0] via 10.0.0.2` | Floating static route |
| `O*E2 0.0.0.0/0 [110/1] via 10.0.0.2, 00:05:12, GigabitEthernet0/0/0` | Default route advertised into OSPF |
| `L 10.0.0.1/32 is directly connected, GigabitEthernet0/0/0` | The router's own interface address |
| `10.0.0.0/8 is variably subnetted, 9 subnets, 4 masks` | Header line, not a route |

**Extra targets:** Equal-cost load sharing · OSPF inter-area route

> **Explanation:** A static route that names only an exit interface shows as "directly connected"; one that names only a next hop shows `[1/0] via` with no interface (static AD 1) and needs a recursive lookup for the next hop. A static route with a raised AD such as `[130/0]` is a floating static; this one is also next-hop-only, but its AD is not the default. `O*E2 0.0.0.0/0` is a default route advertised into OSPF as external type 2. An `L` /32 is the router's own address, so packets to it are received, not forwarded. "Is variably subnetted" lines only group subnets of a classful network. Equal-cost load sharing would show two or more `via` lines under one prefix, and an inter-area route would be coded `O IA`.

### Q9 · CLI

R1's routing table contains both `S 10.10.0.0/16 [1/0] via 10.0.0.2` and `S 10.10.40.0/24 [1/0] via 10.0.0.2`. You are at R1's privileged EXEC prompt. Enter the command that shows which routing table entry R1 uses for the destination 10.10.40.11.

### Q10 · Multiple choice
<sub>Source: 10.7, 10.11</sub>

Why does the ping from R1 to 10.255.0.2 fail?

- [x] No route on R1 contains 10.255.0.2 and there is no gateway of last resort, so R1 drops the packet.
- [ ] R1 matches 10.10.0.0/16 and sends the packet to DSW1, but DSW2 has no route back to R1.
- [ ] R1 matches the 10.0.0.0/8 line and sends the packet to DSW1, which drops it.
- [ ] DSW2 has no connected route for 10.255.0.2, so it does not accept the packet.

> **Explanation:** 10.10.0.0/16 contains only addresses that start with 10.10; the second octet of 10.255.0.2 is 255. The "10.0.0.0/8 is variably subnetted" line is a header, not a route. "Gateway of last resort is not set" means there is no default route, so R1 has nowhere to send the packet and drops it. PC1 succeeds because its traffic is routed by DSW1, which has the static route to 10.255.0.2/32 via 10.0.0.6 given in the scenario. DSW2 does have the connected /32 on Loopback0.

### Q11 · CLI
<sub>Source: 10.11</sub>

The team fixes the problem on R1 only. Using the exhibit, add a next-hop-only static route on R1 for the whole 10.255.0.0/16 block, pointing to the same next hop that R1 already uses for the campus 10.10.0.0/16 traffic. You are in global configuration mode on R1. Enter the command.

**Prompt:** `R1(config)#`

**Accepted:** `ip route 10.255.0.0 255.255.0.0 10.0.0.2` · `ip route 10.255.0.0 255.255.0.0 10.0.0.2 1`

> **Explanation:** R1's existing `S 10.10.0.0/16 [1/0] via 10.0.0.2` shows the next hop: DSW1 at 10.0.0.2. `ip route` takes the network, the dotted-decimal mask (/16 = 255.255.0.0) and the next hop; adding the default static AD of 1 at the end gives the same route. The new line reads `S 10.255.0.0/16 [1/0] via 10.0.0.2`; R1 finds the exit interface with a recursive lookup for 10.0.0.2, which matches the connected 10.0.0.0/30 on G0/0/0. A default route to 10.0.0.2 would also have fixed the ping, but it is not the route asked for here.

### Q12 · Multiple choice
<sub>Source: 10.5, 10.10, 10.11</sub>

After the fix, the ping from R1 succeeds. DSW2 sends its echo replies to R1's address 10.0.0.1. Which entry in DSW2's routing table does it use to forward them?

- [ ] C 10.0.0.4/30, because 10.0.0.1 is in the same 10.0.0.x range
- [x] S* 0.0.0.0/0 via 10.0.0.5
- [ ] The 10.0.0.0/8 line, because it contains 10.0.0.1
- [ ] None — DSW2 drops the replies because it has no route for 10.0.0.0/30

> **Explanation:** 10.0.0.4/30 covers only 10.0.0.4–10.0.0.7, and the /32 routes match a single address each, so no specific route contains 10.0.0.1. The 10.0.0.0/8 line is a header, not a route. The default route contains every address, so DSW2 sends the reply to DSW1 (10.0.0.5), reached through the connected 10.0.0.4/30 on Port-channel3. DSW1 is on 10.0.0.0/30 and delivers it to R1.
