## Questions

### Q1 · Multiple choice
<sub>Source: 12.5</sub>

Refer to the exhibit.

```
R2# show ip interface brief
Interface              IP-Address      OK? Method Status                Protocol
GigabitEthernet0/0/0   10.0.123.2      YES manual up                    up
GigabitEthernet0/0/1   10.0.12.2       YES manual up                    up
GigabitEthernet0/0/2   203.0.113.2     YES manual up                    up
Loopback20             10.20.20.1      YES manual up                    up
Loopback99             10.99.99.2      YES manual administratively down down
```

R2 has no `router-id` command under `router ospf 1`. The OSPF process starts while the interfaces are in the state shown. Which router ID does R2 use?

- [x] 10.20.20.1
- [ ] 10.99.99.2
- [ ] 203.0.113.2
- [ ] None — OSPFv2 does not start until a `router-id` command is configured

> **Explanation:** Without a `router-id` command, OSPF takes the highest IPv4 address on an **up** loopback, and only if there is none does it fall back to the highest address on an up physical interface. Loopback99 has the highest loopback address but is administratively down, so it is not considered; Loopback20 (10.20.20.1) wins even though 203.0.113.2 on G0/0/2 is numerically higher. Only an OSPFv3 router with no IPv4 address at all needs a manual `router-id` to start. Best practice is still to set the RID with `router-id`.

### Q2 · Drag and drop — order
<sub>Source: 12.3, 12.4</sub>

Two routers are connected by a point-to-point link and OSPF has just been enabled on both ends. Drag the neighbor states into the order the routers pass through, from the first state to the last.

1. Down
2. Init
3. 2-Way
4. ExStart
5. Exchange
6. Loading
7. Full

> **Explanation:** In **Down** no Hellos have been received. In **Init** a Hello has arrived but it does not yet list the router's own RID. In **2-Way** each router sees itself in the other's Hello. In **ExStart** and **Exchange** they negotiate and swap DBD packets, in **Loading** they request missing LSAs with LSRs and receive them in LSUs, and in **Full** the databases match. On a broadcast LAN two DROthers stop at 2-Way, which is normal; on a point-to-point link the single neighbor reaches Full.

### Q3 · Multiple choice — choose two
<sub>Source: 12.6, 12.7, 12.11</sub>

Refer to the exhibit.

```
R2# show ip ospf neighbor

Neighbor ID     Pri   State           Dead Time   Address         Interface
1.1.1.1           0   FULL/  -        00:00:35    10.0.12.1       GigabitEthernet0/0/1
1.1.1.1           1   FULL/DROTHER    00:00:32    10.0.123.1      GigabitEthernet0/0/0
3.3.3.3         100   FULL/DR         00:00:38    10.0.123.3      GigabitEthernet0/0/0
```

The routers use router IDs 1.1.1.1 (R1), 2.2.2.2 (R2) and 3.3.3.3 (R3). Which two statements are true? (Choose two.)

- [x] R2 is the BDR on the 10.0.123.0/24 LAN.
- [x] The link on G0/0/1 uses the point-to-point network type, so no DR or BDR was elected on it.
- [ ] R1 can never become the DR on the LAN, because its priority is 0.
- [ ] R1 and R2 have a duplicate router ID problem, because 1.1.1.1 is listed twice.
- [ ] R2's FULL adjacency with R1 on G0/0/0 is a fault, because a DROther should stay in 2-WAY.

> **Explanation:** A DROther forms FULL adjacencies only with the DR and the BDR. R2 is FULL with the DROther R1, so R2 must be the DR or the BDR, and R3 is the DR, so R2 is the BDR. On G0/0/1 the role shows `-` and the priority 0: that is how a point-to-point neighbor appears, with no election. R1's LAN priority is 1 (the G0/0/0 line). 1.1.1.1 appears twice because R1 and R2 share two links and form one adjacency per link. 2-WAY is the normal final state only between two DROthers.

### Q4 · Multiple choice
<sub>Source: 12.8, 12.11</sub>

All routers use `auto-cost reference-bandwidth 10000`, and no `ip ospf cost` commands are configured. In this design R1 has no direct link to R3: it reaches R3's Loopback30 network, 10.30.30.0/24, through R2 only — R1 to R2 over a 1 Gb/s link, then R2 to R3 over a 100 Mb/s link. Loopback30 has `ip ospf network point-to-point` and a cost of 1. Which entry does R1 show for this network in `show ip route ospf`?

- [x] `O 10.30.30.0/24 [110/111] via 10.0.12.2`
- [ ] `O 10.30.30.0/24 [110/110] via 10.0.12.2`
- [ ] `O 10.30.30.0/24 [110/11] via 10.0.12.2`
- [ ] `O 10.30.30.0/24 [110/3] via 10.0.12.2`

> **Explanation:** The metric is the sum of the outgoing interface costs from R1 to the destination: R1's 1 Gb/s link costs 10000 ÷ 1000 = 10, R2's 100 Mb/s link costs 10000 ÷ 100 = 100, and R3's loopback adds 1, so 10 + 100 + 1 = 111. Leaving out the loopback gives 110, and counting only R1's own link plus the loopback gives 11. A metric of 3 would appear only with the default reference bandwidth of 100 Mb/s, where every one of these links costs 1. The 110 in front of the slash is OSPF's administrative distance.

### Q5 · Drag and drop — match
<sub>Source: 12.7, 12.8, 12.9</sub>

Drag each OSPFv2 command to its effect.

| Command | Effect |
| --- | --- |
| `passive-interface gigabitethernet0/0/2` | The interface's network is still advertised, but no Hellos are sent on it |
| `ip ospf priority 0` | The router never becomes DR or BDR on that segment |
| `ip ospf network point-to-point` on Loopback10 | The loopback's configured mask is advertised instead of a /32 |
| `auto-cost reference-bandwidth 10000` | A 1 Gb/s interface costs 10 instead of 1 |
| `default-information originate always` | A default route is advertised even if this router has no default route itself |

**Extra targets:** The interface's network is no longer advertised · The router becomes the DR immediately

> **Explanation:** A passive interface sends no Hellos, so no neighbors form on it, but its network is still advertised. Priority 0 means never DR or BDR. OSPF advertises a loopback as a /32 host route unless it is set to point-to-point. A reference bandwidth of 10000 Mb/s makes 10 Gb/s cost 1, 1 Gb/s cost 10 and 100 Mb/s cost 100. `default-information originate` advertises a default route, and `always` does so even when the router has none. No priority value makes a router DR immediately, because the election is not preemptive.


R1 G0/0/1 (10.0.12.1/30) connects to R2 G0/0/1 (10.0.12.2/30). Both interfaces are up/up and R2's configuration has not changed, but R1 no longer has an OSPF neighbor on that link. What is the cause?

- [x] G0/0/1 is a passive interface on R1, so R1 sends no Hellos on the link.
- [ ] The wildcard mask 0.0.0.3 does not match 10.0.12.1, so G0/0/1 is not enabled for OSPF.
- [ ] The MTU differs between the two G0/0/1 interfaces.
- [ ] R2 runs a different OSPF process ID on the link.

> **Explanation:** `show ip protocols` lists G0/0/1 under Passive Interface(s). A passive interface sends no Hellos, so no adjacency forms, but 10.0.12.0/30 is still advertised because the `network` statement still covers it. Wildcard 0.0.0.3 matches 10.0.12.0–10.0.12.3, which includes 10.0.12.1. An MTU mismatch would leave the neighbor listed in EXSTART or EXCHANGE, not missing. Process IDs are locally significant and do not have to match. Removing the passive setting from G0/0/1 restores the adjacency.

### Q7 · Multiple choice — choose two
<sub>Source: 12.5, 12.10</sub>

Which two statements about OSPFv3 are true? (Choose two.)

- [x] It forms neighbors over the interfaces' link-local addresses.
- [x] On a router with no IPv4 address, `router-id` must be configured manually.
- [ ] It is enabled with `network` statements under `ipv6 router ospf 1`.
- [ ] It shares OSPFv2's neighbor table and DR election when both run on the same interface.
- [ ] It uses a 128-bit router ID taken from the highest IPv6 loopback address.

> **Explanation:** OSPFv3 keeps OSPF's states, DR/BDR rules, cost and AD, but it is enabled per interface (`ipv6 ospf 1 area 0`) and forms neighbors over link-local addresses, which is why OSPFv3 routes show FE80:: next hops. It uses the same 32-bit router ID as OSPFv2; an IPv6-only router has no IPv4 address to choose it from, so `router-id` is mandatory there. OSPFv2 and OSPFv3 are separate processes with separate neighbor tables and separate DR elections.

### Q8 · Drag and drop — match
<sub>Source: 12.4, 12.12, 12.14</sub>

Drag each OSPF symptom to its most likely cause.

| Symptom | Cause |
| --- | --- |
| `show ip ospf neighbor` shows the neighbor stuck in EXSTART | MTU mismatch |
| `%OSPF-4-DUP_RTRID_NBR` messages and unstable adjacencies | Duplicate router ID |
| Two routers on a LAN show each other as `2WAY/DROTHER` | Normal operation |
| The neighbor never appears, and `show ip ospf interface` shows different Hello and dead timers on each end | Hello/dead interval mismatch |
| Adjacencies stay up, but one router calculates every gigabit link as cost 1 while the others use 10 | Reference bandwidth mismatch |

**Extra targets:** Process ID mismatch · Network type mismatch

> **Explanation:** An MTU mismatch lets routers reach ExStart/Exchange but never Full. `DUP_RTRID_NBR` means two routers share a router ID; set unique RIDs and clear the OSPF process. Two DROthers on a broadcast LAN stay 2-WAY with each other by design. Mismatched Hello/dead timers stop the neighbor from appearing at all. A router with a different `auto-cost reference-bandwidth` keeps its adjacencies but computes different costs, so paths and metrics differ. Process IDs are local and never need to match, and a network type mismatch shows up as odd or missing routes on a two-router link, not as any of these symptoms.

### Q9 · CLI
<sub>Source: 12.10</sub>

R3 is being added to OSPFv3. `ipv6 unicast-routing` is enabled, and OSPFv3 process 1 already runs with router ID 3.3.3.3. You are in interface configuration mode for G0/0/0 (2001:db8:acad:123::3/64). Enter the command that enables OSPFv3 process 1 in area 0 on this interface.

**Prompt:** `R3(config-if)#`

**Accepted:** `ipv6 ospf 1 area 0` · `ospfv3 1 ipv6 area 0`

> **Explanation:** OSPFv3 has no `network` statements; it is always enabled per interface with `ipv6 ospf <pid> area <id>`. Newer IOS XE releases also accept the address-family form `ospfv3 1 ipv6 area 0`, which produces the same result. Once R3's neighbors are FULL, `show ipv6 ospf neighbor` lists them by router ID, and `show ipv6 route ospf` shows FE80:: next hops.

### Q10 · Multiple choice
<sub>Source: 12.7, 12.13</sub>

Why is R1 the DR, even though it has the lowest priority on the LAN?

- [x] The DR election is not preemptive: R1 was elected while it was alone on the LAN, and routers with higher priorities that join later do not take over.
- [ ] The lowest priority wins the DR election.
- [ ] The DR is chosen by the lowest router ID, and 1.1.1.1 is the lowest on the LAN.
- [ ] Priorities above 64 are ignored, so all three routers tie at priority 1.

> **Explanation:** The highest priority wins and a tie is broken by the highest router ID, so with all three routers starting together R3 (priority 100) would be DR. But the election is not preemptive: once R1 had become DR, R3 and R2 joining later could not take the role away. The roles stay until the DR fails or the OSPF process is reset on the segment. Priorities range from 0 to 255.

### Q11 · CLI
<sub>Source: 12.7, 12.13</sub>

The engineer wants the configured priorities to decide the election. You are at R1's privileged EXEC prompt. Enter the command that resets the OSPFv2 process (the engineer will answer `yes` to the confirmation and repeat the command on R2 and R3).

**Prompt:** `R1#`

**Accepted:** `clear ip ospf process` · `clear ip ospf 1 process`

> **Explanation:** `clear ip ospf process` restarts OSPFv2, so the routers form new adjacencies and hold a new election in which the priorities decide: R3 becomes DR, R2 BDR and R1 DROther. The same command makes a changed `router-id` take effect. OSPFv3 holds its own, separate DR election, so in Lab 12.1 the engineer also runs `clear ipv6 ospf process` on all three routers.

### Q12 · Multiple choice
<sub>Source: 12.7</sub>

After the processes are cleared, R3 is the DR, R2 the BDR and R1 a DROther. Later R3 reloads and rejoins the LAN two minutes after it went down. Which roles do the routers have once R3 is back?

- [x] R2 DR, R1 BDR, R3 DROther
- [ ] R3 DR, R2 BDR, R1 DROther
- [ ] R2 DR, R3 BDR, R1 DROther
- [ ] R3 DR, R1 BDR, R2 DROther

> **Explanation:** When the DR fails, the BDR (R2) becomes DR and a new BDR is elected from the routers that remain, which leaves only R1. When R3 returns, a DR and a BDR already exist, and because the election is not preemptive R3 does not take either role back despite its priority of 100. It stays a DROther, FULL with R2 and R1, until the DR fails again or the OSPF process is reset on the segment.
