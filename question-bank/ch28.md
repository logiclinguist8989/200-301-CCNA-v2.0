### Q1 · Multiple choice — choose two
<sub>Source: 2.6, 2.7, 6.8, 28.7</sub>

The campus numbers its point-to-point links with consecutive /30 subnets starting at 10.0.0.0. The R1–DSW1 link uses the first one, 10.0.0.0/30, and the routed bundle Po3 between DSW1 and DSW2 uses the next one. Which two addresses can be configured on the Po3 interfaces? (Choose two.)

- [ ] 10.0.0.3
- [ ] 10.0.0.4
- [x] 10.0.0.5
- [x] 10.0.0.6
- [ ] 10.0.0.7

> **Explanation:** A /30 mask (255.255.255.252) has a block size of 256 − 252 = 4 in the fourth octet, so the subnets start at 10.0.0.0, 10.0.0.4, 10.0.0.8 … The second one, 10.0.0.4/30, has the network address 10.0.0.4, the broadcast address 10.0.0.7 and only two usable hosts, 10.0.0.5 and 10.0.0.6 — the addresses DSW1 and DSW2 use on Po3. 10.0.0.3 is the broadcast address of the first subnet.

### Q2 · Multiple choice
<sub>Source: 16.3, 16.5, 18.5, 28.7</sub>

The campus is adding Wi-Fi 6E access points that will offer the staff SSID on the 6 GHz band. Every employee must sign in with their own account, checked by the campus RADIUS server, so that one person's access can be removed without changing anything on other devices. Which security setting should the SSID use?

- [x] WPA3-Enterprise, with 802.1X/EAP authentication against the RADIUS server
- [ ] WPA3-Personal, with SAE and one strong passphrase
- [ ] WPA2-Enterprise, with 802.1X/EAP and AES-CCMP
- [ ] Enhanced Open (OWE), which encrypts traffic without a password

> **Explanation:** Per-user credentials checked by a RADIUS server is the Enterprise mode: the AP (or the WLC) acts as the 802.1X authenticator and the RADIUS server decides, so when someone leaves you disable one account. The 6 GHz band requires WPA3, which rules out WPA2-Enterprise there. WPA3-Personal (SAE) still uses one shared passphrase for everyone, and OWE encrypts an open network but authenticates nobody.

### Q3 · Drag and drop — order
<sub>Source: 13.3, 14.3, 14.9, 22.3, 22.8, 28.5</sub>

PC1 in VLAN 10 has just booted on the finished campus, and its user opens `http://www.campus.example` in a browser. Drag the events into the order in which they happen.

1. PC1 obtains an address, the gateway 10.10.10.1 and the DNS server 10.10.99.53 from R1 through the DHCP relay
2. PC1 sends an ARP request for 10.10.10.1 and learns the HSRP virtual MAC address
3. PC1 sends a DNS query for www.campus.example to 10.10.99.53
4. DNS1 answers that www.campus.example is an alias (CNAME) of web1.campus.example, whose A record is 10.10.40.80
5. PC1 opens a TCP connection to 10.10.40.80 on port 80

> **Explanation:** Without an address PC1 can do nothing, so DHCP comes first: the VLAN 10 SVIs relay the Discover to R1 (`ip helper-address 10.0.0.1`), and the STAFF pool hands out the gateway and the DNS server. The DNS server is in another subnet (VLAN 99), so PC1 needs its gateway's MAC address before it can send the query; DSW1, the HSRP Active router, answers for 10.10.10.1 with the virtual MAC. The query goes to UDP 53. A CNAME returns a name, so the chain ends only with web1's A record, 10.10.40.80. Then the browser opens its TCP session, again through the gateway, because WEB1 is in VLAN 40.

### Q4 · Drag and drop — match
<sub>Source: 5.9, 6.10, 9.11, 12.4, 13.9, 28.9</sub>

Drag each troubleshooting signature to its most likely cause. Not every cause is used.

| Signature | Cause |
| --- | --- |
| `%CDP-4-NATIVE_VLAN_MISMATCH` is logged for an 802.1Q trunk | The two ends use different native VLANs |
| An OSPF neighbor stays in EXSTART/EXCHANGE | The interface MTUs differ |
| The members of a new LACP bundle show the flag `I` and no port-channel comes up | Both ends are set to LACP passive |
| `%SPANTREE-2-BLOCK_BPDUGUARD` is logged and an access port is err-disabled | A switch was connected to a PortFast edge port |
| DSW1 and DSW2 both show HSRP Active for group 30 | The switches cannot hear each other's hellos |
| Two OSPF routers on a LAN stay in 2-WAY with each other | Nothing: both routers are DROthers |

**Extra targets:** Area ID mismatch · Duplex mismatch

> **Explanation:** CDP reports a native VLAN mismatch, which affects only untagged frames. EXSTART/EXCHANGE is the MTU signature; an area mismatch stops OSPF earlier, before 2-WAY. The flag `I` (stand-alone) means LACP did not negotiate: at least one end must be `active`. BPDU guard err-disables an edge port as soon as any BPDU arrives. Two HSRP routers that are both Active cannot hear each other (VLAN missing from the trunk, different versions or groups, an ACL) — an error, not load sharing. On a broadcast LAN two DROthers stay in 2-WAY with each other by design. A duplex mismatch shows up as late collisions and CRC errors, not as any of these signatures.

### Q6 · CLI
<sub>Source: 5.5, 6.10, 7.5</sub>

SW1's uplink Port-channel1 is a trunk that allows VLANs 10, 30, 40 and 99. The new voice VLAN 20 has been created on every switch and must now be carried on this trunk. An engineer on R1 pings 10.0.0.6, DSW2's address on Po3, and the ping fails. Which statement describes what R1 does with the echo requests?

- [x] It sends them to 198.51.100.1, because the default route is the only route that contains 10.0.0.6
- [ ] It sends them to 10.0.0.2, because 10.0.0.0/8 contains 10.0.0.6
- [ ] It sends them to 10.0.0.2, because the static route's AD of 1 beats the default route's AD of 254

PC1 (10.10.10.11) and PC2 (10.10.30.11) have each opened an HTTPS session to 192.0.2.8 from source port 49731. Which statement about PC2's session is correct?

- [x] Its inside global address is 198.51.100.2, and R1 changed the source port to 1024 because PC1's session already uses port 49731 on that address
- [ ] Its inside local address is 198.51.100.2:1024, the address by which PC2 is known inside the campus

<sub>Source: 19.3, 20.2, 20.5, 20.6, 20.7, 20.9, 28.7</sub>

Refer to the exhibit.

```
DSW1# show access-lists STAFF-POLICY
Extended IP access list STAFF-POLICY
    10 permit udp any any eq bootps (36 matches)
    20 permit ip 10.10.10.0 0.0.0.255 any (15873 matches)
    30 deny tcp 10.10.10.0 0.0.0.255 host 10.10.99.30 eq 22
```

A new policy says that staff hosts in VLAN 10 must not open SSH or SFTP sessions to FILES (10.10.99.30) and that all other traffic from VLAN 10 is allowed. STAFF-POLICY is applied inbound on `interface vlan 10` on both DSW1 and DSW2. A user on PC3 in VLAN 10 can still copy files from FILES with SFTP. What is the cause?

- [x] Line 20 matches the SFTP packets first, so line 30 is never checked
- [ ] Line 30 puts port 22 after the destination address, so it matches only replies from FILES
- [ ] SFTP does not use TCP port 22, so line 30 cannot match it
- [ ] An extended ACL must be placed close to the destination, so it has no effect on `interface vlan 10`

> **Explanation:** An ACL is processed top-down and stops at the first match. Line 20 permits every packet from 10.10.10.0/24, including TCP 22 to 10.10.99.30, so line 30 never gets a chance — its counter shows no matches. Put the specific entry above the general one: under `ip access-list extended STAFF-POLICY` add `15 deny tcp 10.10.10.0 0.0.0.255 host 10.10.99.30 eq 22` and remove line 30, on both gateways. A port written after the destination address is the destination port, which is right for traffic to a server; SCP and SFTP run inside SSH on TCP 22; and extended ACLs belong close to the source, as here.

### Q13 · Multiple choice
<sub>Source: 27.3, 27.8, 28.7</sub>

An AI agent re-enables access ports that port security has err-disabled outside working hours. One night its audit log shows that it ran `shutdown` and `no shutdown` on SW2 Fa0/7 forty times in one hour, and each time the port was err-disabled again within seconds. Which control would have prevented this?

- [x] A limit on recoveries per switch per hour, with the agent stopping and alerting a person after repeated failed attempts
- [ ] Data classification and sanitising of everything the agent sends to the model
- [ ] Treating log lines and ticket text as data rather than as instructions
- [ ] A write tool that can change any interface on any switch, so the agent can remove the real cause itself

> **Explanation:** An agent that retries a failing action endlessly is the **runaway loop** risk, controlled by step and rate limits, timeouts and escalation to a person — for example at most three recoveries per switch per hour, stopping and alerting after two failed attempts, and asking a person when the same port violates again. Data classification controls data leakage, and treating tool output as data controls prompt injection. A broader write tool is the opposite of least privilege: the over-permissioned-tools risk.

### Q14 · Multiple choice
<sub>Source: 13.3, 13.5, 13.8, 28.7</sub>

Printer1 in VLAN 40 sends an ARP request for its default gateway, 10.10.40.1. Which device answers, and with which MAC address?

- [x] DSW1, with the virtual MAC address 0000.0c9f.f028
- [ ] DSW2, with the virtual MAC address 0000.0c9f.f028
- [ ] DSW1, with the virtual MAC address 0000.0c9f.f040
- [ ] DSW1, with the MAC address of its own VLAN 40 SVI

> **Explanation:** The Active column for Vl40 shows 10.10.40.2, DSW1's real address, and DSW2 (`local`) is only Standby. ### Q15 · Multiple choice
<sub>Source: 13.3, 13.9, 13.11, 28.9</sub>

Why did DSW2 not become the Active router again for VLANs 40 and 99 after the reload?

- [x] DSW2 is not configured to preempt in groups 40 and 99
- [ ] DSW1 has a higher priority than DSW2 in groups 40 and 99
- [ ] DSW1 and DSW2 run different HSRP versions
- [ ] VLANs 40 and 99 are not allowed on the trunk between DSW1 and DSW2

> **Explanation:** The P column is empty for Vl40 and Vl99, so preemption is not configured in those groups. HSRP preemption is off by default: while DSW2 was reloading, DSW1 (priority 100) became Active, and when DSW2 came back with priority 110 it did not take the role back — it went from Speak to Standby. If the switches ran different versions or the VLANs were missing from the trunk between them, they could not hear each other's hellos and both would show Active; here DSW2 lists DSW1 as Active, so the hellos arrive. A command that "disappears" after a reload was often added after the last `copy running-config startup-config`.

### Q16 · CLI
<sub>Source: 13.6, 13.10</sub>

You are in interface configuration mode for `interface vlan 40` on DSW2. Enter the command that allows DSW2 to take the Active role back in HSRP group 40.

**Prompt:** `DSW2(config-if)#`

**Accepted:** `standby 40 preempt`

> **Explanation:** With `standby 40 preempt` DSW2, whose priority of 110 is higher than DSW1's 100, takes over as Active at once, so the VLAN 40 gateway is aligned with its STP root (DSW2) again. Repeat with `standby 99 preempt` under `interface vlan 99`, check that `show standby brief` shows `P` and `Active local`, and save the configuration so the change survives the next reload.
