## Questions

### Q1 · Multiple choice
<sub>Source: 18.2</sub>

Refer to the exhibit.

```
R1# show running-config | include secret|password
service password-encryption
security passwords min-length 10
enable secret 9 $9$LDteSNyzLxZuVN$UDdKSJSNiNzPaV.fnQngWWaCYxGzIMOrEoxANVfw9yG
username netadmin privilege 15 secret 9 $9$xHy8T9hOm.F9xn$nLlpEWmiGefaEr0qGIq.uA/UqnxwpHQKKjaz59hKHPV
username backup privilege 15 secret 5 $1$7IRE$aBj6he9WgJmoo/Wr3UnX9P
username helpdesk privilege 1 password 7 08091F4219542112010041567A7972
```

Someone obtains a copy of R1's configuration. Which password can they recover in seconds, without any password-cracking effort?

- [ ] The password of netadmin
- [ ] The password of backup
- [x] The password of helpdesk
- [ ] The enable secret

> **Explanation:** helpdesk was configured with `password`, and `service password-encryption` turned it into **type 7**, which is reversible: it only hides the text from shoulder-surfers and can be decoded in seconds. backup uses **type 5** (MD5), which is weak by today's standards but is a hash, not a reversible encoding. netadmin and the enable secret use **type 9** (scrypt), the best available. The fix is `username helpdesk privilege 1 algorithm-type scrypt secret …`.

### Q2 · CLI
<sub>Source: 18.2</sub>

R1 needs a local account for a new engineer. Enter the command that creates the user `netops` with privilege level 15 and the password `N3t-Ops-2026`, stored as a type 9 (scrypt) hash.

**Prompt:** `R1(config)#`

**Accepted:** `username netops privilege 15 algorithm-type scrypt secret N3t-Ops-2026`

> **Explanation:** `algorithm-type scrypt secret` stores the password as a type 9 hash, the strongest type IOS offers. `privilege 15` places the user directly in privileged EXEC (`R1#`) after login; a privilege 1 user would land at `R1>` and need the enable secret. Using `password` instead of `secret` would store the password as type 0, or as reversible type 7 with `service password-encryption`.

### Q3 · Multiple choice — choose two
<sub>Source: 18.3</sub>

An engineer is enabling SSH on R2, which has no configuration yet. Which two commands must be entered before `crypto key generate rsa modulus 2048` can create the key pair? (Choose two.)

- [x] `hostname R2`
- [x] `ip domain-name campus.example`
- [ ] `ip ssh version 2`
- [ ] `transport input ssh`
- [ ] `login local`

> **Explanation:** The RSA key pair is named after the device's hostname and domain name, so a hostname and `ip domain-name` must exist before the keys are generated. `ip ssh version 2` selects the SSH version, while `transport input ssh` (refuse Telnet) and `login local` (check the local usernames) are VTY line settings. All three belong in a complete SSH setup, but none is needed to generate the keys.

### Q4 · Drag and drop — order
<sub>Source: 18.4</sub>

DSW1 is a TACACS+ client of the AAA server at 10.10.99.20. The network engineer alice opens an SSH session to DSW1. Drag the steps of the login into the order in which they happen.

1. alice opens the SSH session and enters a username and password
2. DSW1 sends an authentication START with alice's credentials to the server on TCP port 49
3. The server replies with authentication PASS
4. DSW1 sends an authorization request for an exec shell
5. The server replies with authorization PASS and priv-lvl 15, and alice gets the `DSW1#` prompt
6. DSW1 sends an accounting START record, then the commands alice enters, then a STOP record

> **Explanation:** Authentication answers "who are you?", authorization answers "what may you do?" (here privilege 15, so the session starts in privileged EXEC), and accounting records what was done for the whole session. TACACS+ separates the three functions, so authentication and authorization are separate exchanges; RADIUS returns authentication and authorization in one combined reply.

### Q5 · Drag and drop — match
<sub>Source: 18.5</sub>

Drag each characteristic to the AAA protocol it describes. A protocol can be used more than once.

| Characteristic | Protocol |
| --- | --- |
| Uses TCP port 49 | TACACS+ |
| Uses UDP ports 1812 and 1813 | RADIUS |
| Encrypts the whole payload | TACACS+ |
| Encrypts only the password | RADIUS |
| Can allow or deny each command an administrator enters | TACACS+ |
| Returns authentication and authorization in one combined reply | RADIUS |
| Open standard typically used for 802.1X, Wi-Fi and VPN user access | RADIUS |

> **Explanation:** TACACS+ (Cisco, now RFC 8907) runs over TCP 49, encrypts the whole payload, keeps authentication, authorization and accounting separate and supports per-command authorization, which makes it the usual choice for device administration. RADIUS (RFC 2865/2866) uses UDP 1812 and 1813 (old ports 1645/1646), encrypts only the password, combines authentication and authorization, and is the usual choice for network access. Both can be used for management logins.

### Q6 · Multiple choice — choose two
<sub>Source: 18.7, 18.8</sub>

DSW1's VTY lines use the method list `aaa authentication login VTY-AUTH group ADMIN-TAC local`. The group ADMIN-TAC contains a single TACACS+ server, 10.10.99.20. In which two situations does DSW1 check an SSH login against its local user database? (Choose two.)

- [x] The TACACS+ server is powered off for maintenance.
- [x] A new ACL on the path between DSW1 and the server drops TCP port 49.
- [ ] The server rejects the login because the password is wrong.
- [ ] The engineer logs in as netadmin, an account that exists only in DSW1's local database, while the server is running.
- [ ] The server accepts the login but returns privilege level 1.

> **Explanation:** IOS moves to the next method only on an **ERROR**: the server gives no answer because it is unreachable, timed out or not configured. A powered-off server and an ACL that blocks TCP 49 both mean no answer, so after the timeout DSW1 uses `local`. A reject is a **FAIL**: the login is refused and the local database is not tried, whether the password is wrong or the user is unknown to the server. This is deliberate, so that someone removed from the server cannot log in with an old local password. An accept is a PASS, which also ends the method list.

### Q7 · Multiple choice
<sub>Source: 18.6, 18.7, 18.8</sub>

Refer to the exhibit.

```
SW1# show running-config | section aaa|line
aaa new-model
aaa group server radius ADMIN-RAD
 server name ISE-RAD
aaa authentication login default group ADMIN-RAD local
aaa authorization exec default group ADMIN-RAD local if-authenticated
aaa accounting exec default start-stop group ADMIN-RAD
aaa session-id common
line con 0
 stopbits 1
line vty 0 4
 transport input ssh
line vty 5 15
 transport input ssh
```

The RADIUS server is up and reachable. An engineer connects to SW1's console port and logs in as netadmin with the correct password. netadmin exists in SW1's local database but not on the RADIUS server. What happens?

- [x] The login is refused, because the console uses the default list and the RADIUS server rejects the user
- [ ] The login succeeds, because the console port always authenticates against the local database
- [ ] The login succeeds, because SW1 tries `local` after the RADIUS server rejects the user
- [ ] The login succeeds without a password check, because no `login` command is configured under `line con 0`

> **Explanation:** After `aaa new-model`, the list named `default` applies to every line that has no named list, and that includes the console. The RADIUS server answers with a reject (FAIL), so the login ends there; `local` would be used only if the server gave no answer (ERROR). The console should not depend on the network or a server: create `aaa authentication login CONSOLE local` and apply it with `login authentication CONSOLE` under `line con 0`.

SW1# show aaa servers

Administrators log in to SW1 through RADIUS without problems, but the RADIUS server at 10.10.99.20, which receives authentication on UDP 1812 and accounting on UDP 1813, has no accounting records from SW1. What is the most likely cause?

- [x] SW1 sends its accounting requests to UDP port 1646 instead of 1813
- [ ] The shared key on SW1 does not match the key configured for SW1 on the server
- [ ] Accounting is not configured on SW1
- [ ] RADIUS does not support accounting, so a TACACS+ server is needed for accounting records

> **Explanation:** The Authen counters show accepts and rejects with no timeouts, so the server is reachable and the shared key is right. Fix it under `radius server ISE-RAD` with `address ipv4 10.10.99.20 auth-port 1812 acct-port 1813`. RADIUS does accounting on UDP 1813.

### Q9 · Drag and drop — match
<sub>Source: 18.2, 18.3, 18.6, 18.8</sub>

Drag each command to what it does.

| Command | Purpose |
| --- | --- |
| `login block-for 120 attempts 3 within 60` | Slows down password guessing |
| `transport input ssh` | Refuses Telnet on the VTY lines |
| `aaa new-model` | Turns on AAA, so method lists control logins at once |
| `show ip ssh` | Shows the SSH version and timeouts |
| `show aaa servers` | Shows whether each AAA server is UP or DEAD |
| `test aaa group ADMIN-TAC alice Al1ce-2026 legacy` | Checks a login against the server without logging out |
| `show users` | Lists who is logged in, from where and on which line |

**Extra targets:** Hides type 0 passwords as type 7

> **Explanation:** `login block-for 120 attempts 3 within 60` blocks all logins for 120 seconds after three failures within 60 seconds. `transport input ssh` allows only SSH on the lines. `aaa new-model` changes how logins work immediately, which is why a local privilege 15 user must exist first. `show ip ssh` shows the SSH settings, `show aaa servers` shows each server's state and its request, response and timeout counters, `test aaa group` tests a server login from the device, and `show users` lists active sessions. Hiding type 0 passwords as type 7 is the job of `service password-encryption`, which is not in the list.

### Q10 · Multiple choice
<sub>Source: 18.5, 18.6, 18.8</sub>

Why do alice's sessions start at privilege level 1?

- [x] The VTY lines do not apply the VTY-AUTH exec authorization list, so DSW1 never asks the server for alice's privilege level
- [ ] TACACS+ cannot carry a privilege level; only RADIUS can return one
- [ ] The authentication list ends with `local`, so DSW1 authenticated alice against its local database
- [ ] DSW1 has no enable secret, so it cannot place alice in privileged EXEC

> **Explanation:** A named list applies only where it is referenced. The VTY lines reference VTY-AUTH for `login authentication` but not for `authorization exec`, and there is no `default` exec authorization list, so no exec authorization takes place and users arrive at privilege 1. TACACS+ does return a privilege level (`priv-lvl=15`). alice exists only on the server, and `local` is used only when the server does not answer. The enable secret matters only when a privilege 1 user types `enable`.

### Q11 · CLI
<sub>Source: 18.6</sub>

You have entered `line vty 0 15` on DSW1. Enter the command that applies the existing exec authorization list VTY-AUTH to these lines.

**Prompt:** `DSW1(config-line)#`

**Accepted:** `authorization exec VTY-AUTH`

> **Explanation:** `authorization exec VTY-AUTH` makes DSW1 send an authorization request to ADMIN-TAC after a successful login. The server returns `priv-lvl=15`, so alice's next session starts at `DSW1#`. The global command `aaa authorization exec VTY-AUTH …` only defines the list; `login authentication` and `authorization exec` under the lines put named lists to use.

### Q12 · Multiple choice — choose two
<sub>Source: 18.4, 18.6, 18.7</sub>

After the fix, alice's sessions start at `DSW1#`. Which two statements about DSW1's configuration in the exhibit are true? (Choose two.)

- [x] DSW1 sends its TACACS+ requests from 10.10.99.2, so the server must list DSW1 at that address with the same shared key.
- [x] The server receives a record when each SSH session starts and when it ends.
- [ ] The server receives a record of every command alice enters at privilege level 15.
- [ ] If the server rejects a password, DSW1 checks its local database next.
- [ ] The console port authenticates against the server first and uses the local database only if the server does not answer.

> **Explanation:** `ip tacacs source-interface Vlan99` makes every request come from 10.10.99.2; the server identifies its client by the source IP of the request plus the shared key, not by the hostname. `aaa accounting exec default start-stop group ADMIN-TAC` applies to every line without a named accounting list and records session start and stop. Recording each command would need `aaa accounting commands 15 default start-stop group ADMIN-TAC`, which is not configured. A reject is a FAIL, so the local database is not tried. The console uses the CONSOLE list, which contains only `local`, so it never depends on the server.
