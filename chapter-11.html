11.1 Learning objectives

After this chapter you can:

  1. Decide when static routes are the right tool.
  2. Configure IPv4 static routes with a next hop, an exit interface, or both, and explain recursive lookup.
  3. Configure and recognise default, network, host and floating static routes.
  4. Configure IPv6 static routes, including link-local next hops.
  5. Verify static routes and troubleshoot missing, wrong, one-way and never-failing routes.

Lab itThis chapter is hands-on. Once the theory clicks, jump to Packet Tracer Lab 11.1 — Default, network, host and floating static routes, dual stack (Intermediate) and build it yourself — reading about a network is good, breaking and fixing one is better.

11.2 When static routes make sense

A static route is a route you type in by hand. It never changes unless you change it, uses no bandwidth or CPU to maintain, and reveals nothing to neighbors.

Use static routes for Avoid static routes when
A stub network with one way out (a branch, a home router) Many routers and paths: every change must be made by hand everywhere
A default route toward the ISP Paths must change automatically after a failure far away
A backup path behind a dynamic protocol (floating static) The network grows often
Forcing one specific destination along a chosen path (host route) You cannot document and maintain them reliably

The four types in objective 3.2 all use the same command; they differ only in the destination and the AD (Figure 11.1):

Type Destination Example Purpose
Default route (3.2.a) 0.0.0.0/0 or ::/0 ip route 0.0.0.0 0.0.0.0 198.51.100.1 Anything not otherwise known
Network route (3.2.b) A subnet or summary ip route 10.20.20.0 255.255.255.0 10.0.12.2 A whole remote network
Host route (3.2.c) One address: /32 or /128 ip route 10.20.20.10 255.255.255.255 10.0.21.2 One server, a loopback, a special path for one device
Floating static (3.2.d) Any prefix, with a higher AD ip route 10.20.20.0 255.255.255.0 10.0.21.2 200 Backup that appears only when the preferred route disappears

Figure 11.1 places all four route types from the table on one network, which you build in Lab 11.1. Each blue arrow is one of R1's static routes, pointing toward the destination it describes; the legend gives the exact route.

11.3 IPv4 static route syntax

ip route <network> <mask> { <next-hop-ip> | <exit-interface> | <exit-interface> <next-hop-ip> } [<AD>] [name <text>] [permanent]
Parameter Meaning Common mistake
network The destination network (all host bits 0) Typing a host address with a subnet mask: IOS rejects it with %Inconsistent address and mask
mask Dotted-decimal mask (not /24) Wrong mask covers the wrong range
next-hop-ip The neighbor's address on a directly connected subnet Using the router's own address, or a far-away address that has no route
exit-interface The local interface to send out of Using it alone on Ethernet (see below)
AD 1–255; default 1 Making a backup lower than the route it should back up
name A label shown in the configuration —
permanent Keeps the route even if the exit interface goes down Black-holes traffic during an outage; rarely wanted

All static routes are entered in global configuration mode and appear in the running configuration as ip route ... lines.

Three ways to say where to go (Figure 11.2):

Each row of Figure 11.2 shows the command, the routing table line it produces, and what R1 has to ARP for. The dashed red arrow marks the form to avoid on Ethernet; the highlighted row is the safest form.

  1. Next hop only — ip route 10.20.20.0 255.255.255.0 10.0.12.2. The router must perform a recursive lookup: it looks up 10.0.12.2 in its own table, finds C 10.0.12.0/30 ... GigabitEthernet0/0/1, and uses that interface. Shown as S 10.20.20.0/24 [1/0] via 10.0.12.2.
  2. Exit interface only — ip route 10.20.20.0 255.255.255.0 GigabitEthernet0/0/1. Shown as directly connected. On a point-to-point serial link this is fine. On Ethernet the router treats every destination as if it were on the wire and ARPs for each one; it works only if the neighbor answers with proxy ARP, and it fills the ARP cache. Avoid it on Ethernet.
  3. Fully specified — ip route 10.20.20.0 255.255.255.0 GigabitEthernet0/0/1 10.0.12.2. No recursive lookup, and ARP only for the next hop. Recommended on Ethernet, and required in IPv6 when the next hop is a link-local address.

When is a static route installed? Only when its next hop is reachable (recursion succeeds) or its exit interface is up. If the exit interface goes down, the route is removed (unless permanent). This is what makes a floating static take over (11.5).

11.4 Default route (3.2.a)

R1
R1(config)# ip route 0.0.0.0 0.0.0.0 198.51.100.1          ! HQ edge: everything unknown to the ISP
R2(config)# ip route 0.0.0.0 0.0.0.0 10.0.12.1             ! branch: everything to HQ

The route appears as S* 0.0.0.0/0 [1/0] via ... and sets the gateway of last resort. A stub site such as R2 often needs only a default route: every destination it does not own is "somewhere toward HQ".

11.5 Network route (3.2.b)

A network route reaches one remote subnet, or a summary of several:

R1
R1(config)# ip route 10.20.20.0 255.255.255.0 10.0.12.2    ! branch LAN
ISP(config)# ip route 10.0.0.0 255.0.0.0 198.51.100.2      ! one summary for all of the company

Every network route needs a matching route back on the far side. A ping fails if only one direction exists: the echo request arrives but the reply has no route home. That one-way mistake is the most common static-routing fault.

11.6 Host route (3.2.c)

A host route has a /32 mask (IPv4) or /128 (IPv6) and so beats any other route to that address by longest match:

R1
R1(config)# ip route 10.20.20.10 255.255.255.255 10.0.21.2 ! a branch server

Typical uses: reaching a router's loopback for management or as a routing protocol ID, sending one server's traffic over a different path (Figure 11.1, route c), or pointing at a single DNS or syslog server. Remember that connected interfaces already create /32 L routes for the router's own addresses; host routes you type are S routes.

11.7 Floating static route (3.2.d)

A floating static is a static route configured with an AD higher than the route it backs up. Because the preferred route has a lower AD, the floating route stays out of the routing table — it "floats" above it — until the preferred route disappears (Figure 11.3).

In Figure 11.3 the blue arrow is the route R1 is actually using. On the left the AD 1 route wins and the AD 200 route exists only in the configuration. On the right the primary interface is down, its route is removed, and the floating route is installed with [200/0].

R1
R1(config)# ip route 10.20.20.0 255.255.255.0 10.0.12.2          ! primary, AD 1
R1(config)# ip route 10.20.20.0 255.255.255.0 10.0.21.2 200      ! backup, AD 200
R2(config)# ip route 0.0.0.0 0.0.0.0 10.0.12.1                   ! primary default
R2(config)# ip route 0.0.0.0 0.0.0.0 10.0.21.1 200               ! backup default

Choosing the AD:

Backing up Floating AD must be higher than Typical choice
Another static route 1 5–254
An OSPF-learned route 110 111–254 (often 120–200)
An EIGRP-learned route 90 91–254

If the floating route's AD is equal to the primary's, both are installed and traffic is load-shared; if it is lower, the "backup" becomes the primary. Both are classic exam faults.

What a floating static can and cannot detect. It takes over when the preferred route is removed: the primary static's exit interface went down (link failure detected locally), or the dynamic protocol withdrew the route. A static route cannot detect a failure further away — for example the ISP's router behind a working link — so it keeps sending traffic into a dead path. Detecting remote failures needs tracking (IP SLA) or a routing protocol, which are beyond objective 3.2.

Viewing a floating route. It does not appear in show ip route while unused. Check the configuration (show running-config | include ip route) and, after a failure, look for its AD in brackets: S 10.20.20.0/24 [200/0] via 10.0.21.2.

Memory trickA floating static route floats above the primary because its AD is set higher (for example 130, above OSPF's 110). It sinks into the routing table only when the primary route disappears.

11.8 IPv6 static routes

IPv6 static routes follow the same ideas with three differences: the prefix is written with a slash, IPv6 routing must be enabled, and link-local next hops need an interface.

ipv6 route <prefix>/<length> { <next-hop> | <exit-interface> | <exit-interface> <next-hop> } [<AD>]

The four types on R1 and R2 (Lab 11.1 addressing):

R1
R1(config)# ipv6 unicast-routing                                             ! required for any IPv6 routing
R1(config)# ipv6 route ::/0 2001:db8:ffff::1                                 ! (a) default to the ISP
R1(config)# ipv6 route 2001:db8:acad:20::/64 2001:db8:acad:f012::2          ! (b) network route, primary
R1(config)# ipv6 route 2001:db8:acad:20::10/128 2001:db8:acad:f021::2       ! (c) host route
R1(config)# ipv6 route 2001:db8:acad:20::/64 2001:db8:acad:f021::2 200      ! (d) floating static

R2(config)# ipv6 unicast-routing
R2(config)# ipv6 route ::/0 GigabitEthernet0/0/1 FE80::1                     ! default via R1's link-local
R2(config)# ipv6 route ::/0 GigabitEthernet0/0/2 FE80::1 200                 ! floating default
Next-hop form Example Notes
Global unicast next hop ipv6 route 2001:db8:acad:20::/64 2001:db8:acad:f012::2 Recursive lookup, as in IPv4
Exit interface only ipv6 route 2001:db8:acad:20::/64 GigabitEthernet0/0/1 Works on point-to-point links; on Ethernet relies on the neighbor answering ND for every destination
Link-local next hop ipv6 route ::/0 GigabitEthernet0/0/1 FE80::1 Interface is mandatory — every link uses FE80::/10. Without it IOS replies % Interface has to be specified for a link-local nexthop

Using the neighbor's link-local address is common because it does not change if global addressing is renumbered; that is why Lab 3.1 set ipv6 address fe80::1 link-local on R1.

R1
R1# show ipv6 route static
S   ::/0 [1/0]
     via 2001:DB8:FFFF::1
S   2001:DB8:ACAD:20::/64 [1/0]
     via 2001:DB8:ACAD:F012::2
S   2001:DB8:ACAD:20::10/128 [1/0]
     via 2001:DB8:ACAD:F021::2

The floating route is again invisible until the primary route is removed.

11.9 Verifying static routes

Command Use it to check
show ip route static / show ipv6 route static Which static routes are installed
show ip route 10.20.20.10 Which entry a specific destination uses, with AD, metric and next hop
show running-config \| include ip route Every configured static route, including floating ones not installed
show ip interface brief Whether exit interfaces and next-hop subnets are up
ping 10.20.20.1 source 10.10.10.1 End-to-end reachability from the LAN address, which tests the return route too
traceroute 10.20.20.10 Which path (primary or backup) packets actually take

Why source matters. A plain ping from R1 uses the exit interface's address (10.0.12.1). That can succeed even when the branch has no route back to the HQ LAN. Pinging from the LAN address (or from a PC) proves both directions. This is an extended ping, covered fully in Chapter 15.

11.10 Troubleshooting static routes

Work through these checks in order:

  1. Is the route configured correctly? Right network address, right mask, right next hop (show running-config | include ip route).
  2. Is it installed? If not, the next hop is unreachable or the exit interface is down, or a lower-AD route to the same prefix already exists.
  3. Is it the route actually used? A longer prefix elsewhere (a host route, a more specific network) may win (show ip route <destination>).
  4. Is there a route back? Check the return path on every router, from the far end toward the source.
  5. Does the path work end to end? ping ... source, traceroute.
Symptom Likely cause Evidence Fix
Route missing from the table Next hop not on a connected subnet, or exit interface down show ip route static empty for it; next hop absent from C routes Correct the next hop; bring the interface up
IOS rejects the command Host bits set in the network (%Inconsistent address and mask) Error at config time Use the network address (10.20.20.0, not 10.20.20.1)
Ping from the router works, from the LAN fails No return route on the far router ping ... source <LAN IP> fails; far router lacks the route Add the return route
Traffic takes the backup link all the time Floating AD equal to or lower than the primary, or primary next hop wrong Both routes or only the backup installed Fix the AD (backup higher) or the primary next hop
Load sharing that was not intended Primary and backup configured with the same AD Two via lines Raise the backup AD
Backup never takes over during an ISP outage Primary static stays installed because the local link is still up Primary route still present; traffic black-holed Expected static behaviour; needs tracking or a routing protocol
One server goes a different way from its subnet A host route (/32) overrides the network route show ip route 10.20.20.10 shows the /32 Intended (Figure 11.1, route c) or remove it
Exit-interface static on Ethernet works inconsistently Relies on proxy ARP; ARP table full of remote hosts show ip arp lists many remote addresses on one interface Use a next hop or fully specified route
IPv6 route rejected Link-local next hop without an interface % Interface has to be specified for a link-local nexthop Add the exit interface
IPv6 static routes ignored ipv6 unicast-routing missing No forwarding; no RAs Enable it

11.13 Chapter 11 summary notes (exam revision)

  • IPv4: ip route <network> <mask> {next-hop | exit-int | exit-int next-hop} [AD]. IPv6: ipv6 route <prefix/len> ... [AD] with ipv6 unicast-routing enabled.
  • Next hop only = recursive lookup. Exit interface only = "directly connected"; on Ethernet relies on proxy ARP — avoid. Fully specified = best on Ethernet; mandatory for IPv6 link-local next hops.
  • Default 0.0.0.0/0 or ::/0 (S*, gateway of last resort). Network route to a subnet or summary. Host route /32 or /128 wins by longest match. Floating static = higher AD than the route it backs up; installed only when that route is removed.
  • Floating AD must exceed: static 1, EIGRP 90, OSPF 110. Equal AD = load sharing; lower = it becomes primary.
  • A static route is installed only if its next hop is reachable / exit interface up; it cannot detect remote failures.
  • Every route needs a return route. Test with ping <dest> source <LAN-IP> and traceroute.
  • Network address must have host bits 0, or IOS says %Inconsistent address and mask.

Common conceptual mistakes

Mistake Correct idea
"A floating static shows in show ip route all the time" Only after the preferred route disappears; otherwise check the configuration
"Backup route AD 1 makes failover faster" AD 1 equals the primary: both are installed and traffic is load-shared
"A ping from the router proves the route works" It may use the router's link address; test from the LAN address
"A static route fails over when the ISP fails" Only if the local next hop or interface fails
"IPv6 link-local next hops work like global ones" They need the exit interface specified

R1's primary static default points to the ISP's router across a working link. The ISP's upstream connection fails. A floating default via a second ISP does not take over. Why?

Answer it in your head (or on paper) first.

The primary static route is still installed because its local next hop is still reachable; static routes cannot see failures beyond the next hop. Tracking (IP SLA) or a routing protocol is needed.

14Evaluate an AI assistantthink, then reveal

A network assistant suggests: "Configure the backup static route with AD 1 so it takes over instantly when the primary fails." Is this good advice?

Answer it in your head (or on paper) first.

No. With AD 1 the backup equals the primary, so both are used all the time and traffic is split across both links. A backup needs a higher AD; it takes over as soon as the primary route is removed.
