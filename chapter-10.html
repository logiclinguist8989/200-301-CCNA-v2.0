Chapter 10Interpreting the routing table

🖼️ 4 figures⏱️ ~18 min read📝 Self-check: 14 questions

Objective covered: 3.1 Interpret a routing table to identify the next hop for a packet (routing protocol, prefix/mask, administrative distance, metric, and default route). This is Domain 3's foundation: static routing (Chapter 11), OSPF (Chapter 12) and FHRP (Chapter 13) all end up as lines in this table.

10.1 Learning objectives

After this chapter you can:

  1. Describe step by step how a router forwards a packet.
  2. Read every field of an IPv4 and IPv6 routing table entry.
  3. Apply the three route-selection rules in the right order: longest prefix match, administrative distance, metric.
  4. Explain the gateway of last resort and the default route.
  5. Find the next hop and exit interface for any destination from show ip route output.

Lab itThis chapter is hands-on. Once the theory clicks, jump to Packet Tracer Lab 10.1 — Reading the campus routing tables (Intermediate) and build it yourself — reading about a network is good, breaking and fixing one is better.

10.2 How a router forwards a packet

A router makes the same decision for every packet, independently (Figure 10.1):

Figure 10.1 follows one packet from arrival to departure. The two red boxes are the only routing reasons to drop it: the TTL ran out, or no route matched. Everything this chapter teaches happens in steps 3 to 5.

  1. Receive the frame. Check the FCS; accept it only if the destination MAC is the router's own interface MAC (or broadcast/multicast it listens to).
  2. De-encapsulate to the IP packet and decrement the TTL. If TTL reaches 0, drop it and send an ICMP Time Exceeded back to the source (this is how traceroute works).
  3. Look up the destination IP in the routing table and choose the longest matching prefix (10.4).
  4. No match and no default route? Drop the packet and send ICMP Destination Unreachable.
  5. Match found: read the next-hop address and/or exit interface. If the next hop is not directly connected, look it up again (a recursive lookup).
  6. Resolve the next hop's MAC with ARP (IPv4) or ND (IPv6). If the destination is on a directly connected network, ARP for the destination itself.
  7. Re-encapsulate in a new frame for the exit interface (new source and destination MAC, new FCS) and send it.

The routing table (the RIB) is built by the control plane from connected interfaces, static routes and routing protocols. For speed, the forwarding plane uses a copy optimized for lookups (Cisco Express Forwarding, CEF), but its decisions follow the same table.

Reading it, block by block:

  • Codes legend — the first column of every route tells you its source. The ones to know: C connected network, L local (the router's own address, /32 or /128), S static, S* static default (candidate default), O OSPF intra-area, O IA OSPF inter-area, O E1/E2 OSPF external, D EIGRP, D EX EIGRP external, R RIP, B BGP.
  • Gateway of last resort — the default route's next hop, used when nothing more specific matches. "Gateway of last resort is not set" means unmatched packets are dropped.
  • Header lines such as 10.0.0.0/8 is variably subnetted, 9 subnets, 4 masks are not routes. They group the entries that fall inside the classful network 10.0.0.0/8 and say how many different masks are in use. A packet to 10.200.1.1 does not match "10.0.0.0/8" here.
  • Route lines (Figure 10.2 dissects one): code, destination prefix and length, [administrative distance/metric], via next-hop address, age, exit interface.
  • Connected and local routes have no brackets and no next hop: the network is directly attached.

In Figure 10.2 each underlined part of the route line has a leader down to its meaning. Read any route the same way, left to right: how it was learned, where it goes, how trusted and how costly it is, and which neighbor and interface to use.

Metrics are protocol-specific and cannot be compared between protocols: OSPF uses cost (based on bandwidth), RIP uses hop count, EIGRP a composite of bandwidth and delay. That is exactly why AD exists.

10.4 The three decisions, and their order

Three different rules are often confused. They answer different questions, at different times (Figure 10.3):

Rule Question it answers When Compares
Administrative distance Several sources offer the same prefix; which one goes into the table? When building the table Lowest AD
Metric One protocol has several paths to the same prefix; which go in? When building the table Lowest metric; equal metrics all go in (ECMP)
Longest prefix match A packet arrives; which installed route does it use? Every packet Most specific (longest) prefix that contains the destination

The trapAD and metric never compete across different prefixes. A static route to 10.10.0.0/16 (AD 1) does not beat an OSPF route to 10.10.40.0/24 (AD 110) for traffic to 10.10.40.25. Both are installed, because they are different prefixes, and the packet uses the /24 because it is longer.

Read Figure 10.3 as two separate jobs. The left column runs whenever routing information changes and decides which routes are installed for each prefix. The right column runs for every packet and only ever looks at installed routes, choosing by prefix length alone.

10.5 Longest prefix match

A route contains a destination if the destination's first n bits equal the route's first n bits, where n is the prefix length. Among all routes that contain the destination, the router uses the one with the largest n.

Worked example on R1's table — destination 10.10.40.25 (Figure 10.4):

In Figure 10.4 the three filled bars are routes that contain 10.10.40.25; the highlighted one is longest, so it wins. The /30 is longer still but does not contain the address, so length alone is never enough: the route must match first.

  1. 0.0.0.0/0 contains everything (0 bits to compare).
  2. 10.10.0.0/16: the first 16 bits (10.10) match. Contains it.
  3. 10.10.40.0/24: the first 24 bits (10.10.40) match. Contains it.
  4. 10.10.30.0/24: the third octet differs (30 ≠ 40). Does not contain it.
  5. 10.0.0.4/30: covers only 10.0.0.4–10.0.0.7. Does not contain it.
  6. The longest containing prefix is 10.10.40.0/24 → next hop 10.0.0.2, exit G0/0/0.

Quick method: for each candidate, apply the candidate's mask to the destination (Chapter 2 block-size method) and see whether you get the candidate's network address. 10.10.40.25 with /24 → 10.10.40.0 ✓; with /16 → 10.10.0.0 ✓; the longer one wins.

10.6 Administrative distance and metric in action

AD decides between sources. If R1 also had ip route 10.10.40.0 255.255.255.0 10.0.0.2, the static route (AD 1) would replace the OSPF route (AD 110) for that same /24 in the table; the OSPF route stays in the OSPF database as a backup. If the static route were configured with AD 130 (a floating static, Chapter 11), OSPF would stay installed and the static would appear only if OSPF lost the route.

Metric decides within one protocol. If OSPF knew two paths to 10.20.0.0/24 with costs 3 and 5, only cost 3 is installed. With two paths of equal cost, both are installed and traffic is shared (equal-cost multipath, ECMP):

O        10.20.0.0/24 [110/3] via 10.0.0.6, 00:02:11, Port-channel3
                      [110/3] via 10.0.0.10, 00:02:11, GigabitEthernet1/0/24

OSPF installs up to four equal-cost paths by default (maximum-paths changes it).

Memory trickAdministrative distances to know cold: connected 0 · static 1 · eBGP 20 · EIGRP 90 · OSPF 110 · RIP 120 · iBGP 200. Lower is more trusted.

10.7 Default routes and the gateway of last resort

A default route is a route to 0.0.0.0/0 (IPv4) or ::/0 (IPv6). It contains every address but is the least specific possible, so it is used only when nothing longer matches. Typical use: the edge router points the default at the ISP, and internal routers learn or point a default toward the edge.

  • Configured statically: ip route 0.0.0.0 0.0.0.0 198.51.100.1 (shows as S*).
  • Learned from a routing protocol (for example O*E2 from OSPF's default-information originate, Chapter 12).
  • Learned from DHCP on an Internet-facing interface (AD 254).

Gateway of last resort is 198.51.100.1 to network 0.0.0.0 confirms which default is active. If it says not set, packets with no matching route are dropped with ICMP Unreachable.

10.12 Chapter 10 summary notes (exam revision)

  • Per packet: check frame → decrement TTL (0 = drop, ICMP Time Exceeded) → longest-prefix lookup → no route and no default = drop, ICMP Unreachable → ARP/ND for next hop → new frame.
  • Route line: code, prefix/length, [AD/metric], via next hop, age, exit interface. C and L lines have no brackets; L = the router's own /32 (or /128).
  • Codes: C, L, S, S* (static default), O, O IA, O E1/E2, D, D EX, R, B. "is variably subnetted" lines are headers, not routes.
  • AD: connected 0, static 1, eBGP 20, EIGRP 90, OSPF 110, IS-IS 115, RIP 120, EIGRP external 170, iBGP 200, DHCP default 254, 255 never used.
  • Order of rules: AD (same prefix, different sources) and metric (same prefix, same protocol) decide what is installed; longest prefix match decides what each packet uses. AD never compares different prefixes.
  • Equal metrics → several via lines (ECMP).
  • Default route 0.0.0.0/0 or ::/0; shown as the gateway of last resort; "not set" = no default.
  • IPv6: two-line entries, /128 local routes, link-local next hops with an exit interface.

Common conceptual mistakes

Mistake Correct idea
"The static route wins because its AD is lower" Only if it is the same prefix; otherwise the longer prefix wins
"10.0.0.0/8 is variably subnetted means there is a /8 route" It is a header grouping subnets, not a route
"The first matching line is used" The longest matching line is used, wherever it is in the table
"Metric 30 from OSPF is worse than metric 2 from RIP" Metrics from different protocols cannot be compared; AD decides
"[1/0] means metric 1" 1 is the AD, 0 the metric

An IPv6 route reads O 2001:DB8:ACAD:40::/64 [110/2] via FE80::2, GigabitEthernet0/0/1. Why is the exit interface always shown with this next hop?

Answer it in your head (or on paper) first.

Link-local addresses are valid only on one link, and every link uses FE80::/10, so FE80::2 is ambiguous without naming the interface it is on.

OSPF installs 10.70.0.0/24. An administrator adds ip route 10.70.0.0 255.255.255.0 10.9.9.9 130. Which route is in the table now?

Answer it in your head (or on paper) first.

The OSPF route stays installed (AD 110 < 130). The static route is a floating static: it appears only if OSPF loses 10.70.0.0/24.

Looking at RX's table, a network assistant says: "Traffic to 172.16.5.9 uses the OSPF route 172.16.4.0/22 because dynamic routes are preferred over static ones." Is that correct?

Answer it in your head (or on paper) first.

No. Longest prefix match comes first: the static 172.16.5.0/24 is more specific than the /22, so it is used. (Static routes also have a lower AD than OSPF, but AD is irrelevant here because the prefixes differ.)
