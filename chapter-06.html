6.2 Introduction: two cables are not automatically twice the bandwidth

In Lab 5.1, SW1 has one 1 Gb/s uplink to DSW1. If you add a second cable for more bandwidth and redundancy, Spanning Tree Protocol (Chapter 9) sees a loop and blocks one of the links (Figure 6.1, left). You pay for two links but use one. EtherChannel bundles up to eight parallel physical links into one logical link called a port-channel (Po). STP, the MAC table and routing all see a single interface, so every member forwards traffic (Figure 6.1, right). If a member fails, traffic shifts to the survivors in well under a second without any STP recalculation.

In Figure 6.1 the cabling is identical on both sides; only the configuration differs. On the left, STP must block the red dashed link to prevent a loop. On the right, the ellipse marks the bundle: STP treats Po1 as one port, so both highlighted links carry traffic.

6.3 How EtherChannel works

  1. You add physical ports to a channel group with channel-group <n> mode <mode>.
  2. The switch creates interface port-channel \, the logical interface you configure and monitor.
  3. A negotiation protocol (LACP or PAgP) checks that the far end agrees and that the members are compatible.
  4. Compatible members become bundled; the port-channel comes up.
  5. Each frame is assigned to one member by a hash of its addresses (6.4), so one conversation always uses one link.
Term Meaning
EtherChannel Cisco's name for link aggregation
Port-channel (Po) The logical interface representing the bundle
Member (bundled) port A physical interface inside the bundle
Channel group The number that ties members to their port-channel (Po1 = group 1)
LACP Link Aggregation Control Protocol, IEEE 802.3ad (now 802.1AX), open standard
PAgP Port Aggregation Protocol, Cisco proprietary (recognise it; v2.0 names only LACP)

6.4 Load balancing: per flow, not per packet

EtherChannel does not split one transfer across all links. The switch runs a hash on fields of each frame — source and/or destination MAC, IP address or port — and the result picks one member. Every frame of the same flow produces the same hash, so it always uses the same link and arrives in order (Figure 6.2).

In Figure 6.2 the highlighted flows hash to member Gi0/1 and the grey flows to Gi0/2. Which flow lands on which link depends on the hash result, not on the order the flows started.

  • One large file copy between two hosts is limited to one member's speed (1 Gb/s on a 2 × 1 Gb/s bundle).
  • Many flows between many hosts spread across all members.
  • If traffic is uneven, choose a hash with more variety. Between Layer 3 devices, src-dst-ip usually spreads better than src-mac (all routed frames share the router's MAC).
DSW1
DSW1(config)# port-channel load-balance src-dst-ip      ! global; applies to all bundles
DSW1# show etherchannel load-balance
EtherChannel Load-Balancing Configuration:
        src-dst-ip

The default method and the available options vary by platform. Each end chooses its own method independently; they do not have to match.

6.5 Negotiation: LACP, PAgP or static

Mode Protocol Behaviour
active LACP Sends LACP packets and starts negotiation
passive LACP Answers LACP but never starts it
desirable PAgP Sends PAgP and starts negotiation
auto PAgP Answers PAgP but never starts it
on None Bundles unconditionally, no negotiation

Which pairs form a bundle?

Side A \ Side B active passive on desirable / auto
active Yes Yes No No (different protocols)
passive Yes No — both wait No No
on No No Yes No

The same logic applies to PAgP: desirable + desirable or desirable + auto bundle; auto + auto does not.

Best practiceUse LACP active on both ends. It is an open standard (works with servers, hypervisors and other vendors), detects mis-cabling, and removes a member that stops talking LACP. Avoid on: if one end bundles and the other does not, you can create a forwarding loop.

LACP details worth knowing: LACP can manage up to 16 links per bundle, of which 8 are active and up to 8 are hot-standby. Each side has a system priority (lower wins and decides which links are active) and each port a port priority; defaults are 32768.

Memory trickLACP: Active asks, Passive pauses. PAgP: Desirable asks, Auto waits. Two that only wait (passive + passive, auto + auto) never form a channel.

6.6 Member requirements

All members of one EtherChannel must match each other and the far end, or they are suspended from the bundle:

Must match Example of a mismatch
Speed and duplex One member hard-coded 100 Mb/s
Switchport type One member Layer 2, another no switchport
Switchport mode One member access, another trunk
Access VLAN (access bundles) VLAN 10 on one port, VLAN 30 on another
Trunk native VLAN and allowed VLAN list (trunk bundles) Allowed 10,30 on one member, 10,30,40 on another
Same channel-group number and compatible mode Gi1/0/1 in group 1, Gi1/0/3 in group 2

The channel-group number is local: Po1 on DSW1 may connect to Po5 on SW1. Matching numbers is simply good documentation.

6.7 Configuring a Layer 2 EtherChannel (trunk)

Figure 6.3 (left) shows the result. Configure the same on both switches.

Both panels of Figure 6.3 bundle two members with LACP; the difference is what the port-channel is. Po1 on the left is a trunk configured with switchport commands; Po3 on the right is a routed interface with an IP address at each end. Both appear again in Lab 6.1.

DSW1
DSW1(config)# interface range gigabitethernet1/0/1 , gigabitethernet1/0/3
DSW1(config-if-range)# description Po1 members to SW1
DSW1(config-if-range)# switchport mode trunk
DSW1(config-if-range)# switchport trunk native vlan 999
DSW1(config-if-range)# switchport trunk allowed vlan 10,30,40,99
DSW1(config-if-range)# channel-group 1 mode active       ! creates Po1 and starts LACP
Creating a port-channel interface Port-channel 1
DSW1(config-if-range)# exit
DSW1(config)# interface port-channel 1
DSW1(config-if)# description Po1 to SW1
DSW1(config-if)# switchport mode trunk
DSW1(config-if)# switchport trunk native vlan 999
DSW1(config-if)# switchport trunk allowed vlan 10,30,40,99

Order and inheritance. Configure the members identically first, then add channel-group. After the bundle exists, make Layer 2 changes on interface port-channel 1; IOS copies them to every member, which keeps members consistent. Changing one member directly is the usual way to get it suspended.

Command Mode Purpose
channel-group <n> mode active Interface (member) Adds the port to group n using LACP active; creates Po n if needed
channel-group <n> mode passive Interface (member) LACP, waits for the other side
channel-group <n> mode on Interface (member) Static bundle, no LACP (avoid)
interface port-channel <n> Global config Configures the logical interface
port-channel load-balance <method> Global config Sets the hash method
lacp system-priority <n> / lacp port-priority <n> Global / interface Influence which links are active when more than 8

6.8 Configuring a Layer 3 EtherChannel (routed)

Between two Layer 3 switches (or a Layer 3 switch and a router) the bundle can be a routed link with one IP address (Figure 6.3, right). The members must be routed ports before they join the group, so the port-channel is created as Layer 3.

DSW1
DSW1(config)# interface range gigabitethernet1/0/21 - 22
DSW1(config-if-range)# description Po3 members to DSW2
DSW1(config-if-range)# no switchport                       ! first: make members Layer 3
DSW1(config-if-range)# channel-group 3 mode active
DSW1(config-if-range)# exit
DSW1(config)# interface port-channel 3
DSW1(config-if)# no switchport                             ! confirm the bundle is Layer 3
DSW1(config-if)# ip address 10.0.0.5 255.255.255.252
DSW1(config-if)# no shutdown

DSW2 is the mirror image with 10.0.0.6/30. The IP address goes on interface port-channel 3, never on the members.

Layer 2 EtherChannel Layer 3 EtherChannel
Members Switchports (access or trunk) Routed ports (no switchport)
Addressing None; carries VLANs One IP address on the port-channel
STP Runs on the port-channel Not involved
Shown in summary as Po1(SU) — S = Layer 2 Po3(RU) — R = Layer 3
Typical use Access to distribution trunks; server/hypervisor bundles Distribution to core; switch to router; routed campus

6.10 Troubleshooting EtherChannel

Symptom Likely cause Fix
Members show I (stand-alone); no Po up LACP on one side only, both sides passive, or PAgP on one side and LACP on the other Use active on at least one side (best: both) with the same protocol
One member shows s (suspended) Its configuration differs (allowed VLANs, native VLAN, access VLAN, speed, duplex) Make members identical; configure on the port-channel interface
Ports go err-disabled, log shows %PM-4-ERR_DISABLE: channel-misconfig One side on, the other not bundling (EtherChannel misconfiguration guard) Use LACP on both sides; then shutdown / no shutdown the members
Bundle forms but one member stays D Physical fault on that link (Chapter 1) Check cabling and counters
Layer 3 Po has no IP / shows Layer 2 (S) no switchport not applied before channel-group Remove members, set no switchport on members and Po, re-add
Bundle with the wrong switch Members cabled to two different devices show lacp neighbor; correct the cabling
One link saturated, the other idle Hash method suits the traffic poorly Change port-channel load-balance (for example to src-dst-ip)

Order for troubleshooting: physical state of each member → same protocol and compatible modes → identical member configuration → correct neighbor → load-balance method.

6.13 Chapter 6 summary notes (exam revision)

  • EtherChannel bundles up to 8 active links into one logical port-channel; STP, MAC learning and routing see one interface. LACP can hold 8 more in hot-standby (16 total).
  • Load balancing is per flow (hash of MAC/IP/port). One flow never exceeds one member's speed. port-channel load-balance src-dst-ip is a common choice.
  • Modes: LACP active/passive; PAgP desirable/auto; static on. passive + passive and auto + auto never bundle; protocols cannot mix; on bundles only with on. Best practice: LACP active on both ends.
  • Members must match: speed, duplex, switchport type, mode, access VLAN or native + allowed VLANs.
  • Layer 2 Po: channel-group n mode active on members, then configure interface port-channel n (trunk settings are copied to members).
  • Layer 3 Po: no switchport on members before channel-group; IP address on the port-channel.
  • Verify: show etherchannel summary — Po(SU) Layer 2 in use, Po(RU) Layer 3 in use; members (P) bundled, (I) stand-alone, (s) suspended, (D) down.

Common conceptual mistakes

Mistake Correct idea
"A 2 × 1 Gb/s bundle gives one download 2 Gb/s" One flow uses one member: 1 Gb/s
"passive on both ends is the safe choice" Neither side starts LACP; no bundle forms
"Put the IP address on each member of a Layer 3 bundle" One IP, on the port-channel interface
"Channel-group numbers must match on both switches" They are local; matching is only good documentation
"Fix a suspended member by changing that member" Configure the port-channel so all members inherit identical settings
