Chapter 13First hop redundancy protocols

🖼️ 3 figures⏱️ ~18 min read📝 Self-check: 13 questions

Objective covered: 3.4 Interpret the operational status of First Hop Redundancy Protocols (HSRP and VRRP) — the exam asks you to read and explain HSRP and VRRP status output (13.8). Configuration is included because building a group once makes that output easy to read.

13.1 Learning objectives

After this chapter you can:

  1. Explain why hosts need a redundant default gateway and what an FHRP provides.
  2. Describe virtual IP and virtual MAC addresses, active/standby (HSRP) and master/backup (VRRP) roles.
  3. Explain priority, preemption, timers, tracking and failover.
  4. Compare HSRP, VRRP and GLBP.
  5. Configure and verify HSRP on a pair of Layer 3 switches.

Lab itThis chapter is hands-on. Once the theory clicks, jump to Packet Tracer Lab 13.1 — HSRP on the distribution pair (Intermediate–Advanced) and build it yourself — reading about a network is good, breaking and fixing one is better.

13.2 The problem: one gateway per host

A host has one default gateway address. In Lab 5.1 every PC in VLAN 10 uses DSW1's SVI, 10.10.10.1. If DSW1 fails, the hosts keep sending off-subnet traffic to 10.10.10.1 and nothing answers — even though DSW2 could route for them. Changing the gateway on every host is not practical, and hosts do not run routing protocols.

A first hop redundancy protocol (FHRP) makes two or more routers share a virtual IP address and a virtual MAC address. Hosts use the virtual IP as their gateway. One router actively forwards for it; another stands by and takes over the same addresses if the first fails (Figure 13.1).

In Figure 13.1 the dashed box is the virtual router that hosts believe they are talking to. The highlighted DSW1 owns it while active; the Hellos let DSW2 notice when DSW1 stops.

13.3 How an FHRP works

  1. Routers in the same group exchange Hello (advertisement) messages on the shared subnet.
  2. The router with the highest priority becomes active (HSRP) or master (VRRP); a tie is broken by the highest real IP address.
  3. The active router answers ARP requests for the virtual IP with the virtual MAC, and forwards frames sent to that MAC.
  4. The standby router listens. If Hellos stop for the hold time, it becomes active and sends a gratuitous ARP so switches relearn where the virtual MAC now lives.
  5. Hosts notice nothing: the gateway's IP and MAC have not changed.

Preemption. If a higher-priority router comes back after a failure, should it take over again? With preempt enabled it does; without it, the current active router keeps the role. HSRP preemption is off by default; VRRP preemption is on by default.

Tracking. A router can lower its own priority when something else fails — for example its uplink toward the core. If DSW1 tracks its uplink and decrements its priority from 110 to 90, DSW2 (100) takes over (with preempt), avoiding a gateway that has no way out.

Figure 13.2 shows a failure with HSRP's default timers.

13.5 HSRP, VRRP and GLBP compared

Feature HSRP VRRP GLBP
Standard Cisco proprietary Open standard (RFC 5798, VRRPv3) Cisco proprietary
Roles Active / Standby (others Listen) Master / Backup AVG (gateway) and up to 4 AVFs (forwarders)
Load sharing Per group (different VLANs, different active routers) Per group Within one group, across up to 4 routers
Virtual MAC v1: 0000.0c07.acXX; v2: 0000.0c9f.fXXX 0000.5e00.01XX 0007.b400.XXYY
Multicast / transport v1 224.0.0.2, v2 224.0.0.102; UDP 1985 224.0.0.18; IP protocol 112 224.0.0.102; UDP 3222
Default timers Hello 3 s, hold 10 s Advertisement 1 s, down ≈ 3 s Hello 3 s, hold 10 s
Default priority 100 (higher wins) 100; 255 for the address owner 100
Preemption default Off On Off
Virtual IP may equal a real interface IP No Yes (that router is the owner) No
IPv6 HSRPv2 VRRPv3 Yes

HSRP versions. Version 1 supports groups 0–255 and IPv4 only; version 2 supports groups 0–4095, IPv6 and millisecond timers. The two versions are not compatible, so use the same version on all group members. Matching the group number to the VLAN ID (group 10 on VLAN 10) is a common, readable convention.

HSRP states: Initial → Learn → Listen → Speak → Standby or Active. Seeing routers stuck in Speak or both Active usually means they cannot hear each other's Hellos.

Memory trickGLBP is the only FHRP with balancing in its name — and the only one that load-balances across routers by default. HSRP and GLBP are Cisco; VRRP is the open standard.

13.6 Configuring HSRP

Objective 3.4 asks you to interpret HSRP and VRRP status, so configuration is not strictly required; configuring HSRP once makes every concept concrete. All commands are in interface configuration mode on the SVI (or routed interface) that faces the hosts. Each router keeps its own real IP; the virtual IP is the one hosts use.

DSW1
DSW1(config)# interface vlan 10
DSW1(config-if)# ip address 10.10.10.2 255.255.255.0      ! real address; .1 becomes the virtual IP
DSW1(config-if)# standby version 2
DSW1(config-if)# standby 10 ip 10.10.10.1                  ! group 10, virtual IP
DSW1(config-if)# standby 10 priority 110                   ! default 100; higher wins
DSW1(config-if)# standby 10 preempt                        ! take the role back after recovering

DSW2(config)# interface vlan 10
DSW2(config-if)# ip address 10.10.10.3 255.255.255.0
DSW2(config-if)# standby version 2
DSW2(config-if)# standby 10 ip 10.10.10.1
DSW2(config-if)# standby 10 preempt                        ! priority stays 100
Command Purpose Notes
standby version 2 HSRPv2 (groups 0–4095, IPv6, ms timers) Same version on every member
standby <grp> ip <virtual-ip> Join group, set the virtual IP Same group number and virtual IP on all members; the virtual IP is in the subnet but on no interface
standby <grp> priority <0-255> Election priority Default 100
standby <grp> preempt Reclaim the Active role when priority is higher Off by default
standby <grp> timers <hello> <hold> Faster failover, e.g. timers 1 3 Match on all members (the Active router's timers are learned)
track 1 interface <int> line-protocol + standby <grp> track 1 decrement 20 Lower priority when the uplink fails Global track object, then reference it in the group; needs preempt on the peer to matter
standby <grp> ipv6 autoconfig IPv6 virtual gateway (link-local, learned from the virtual MAC) HSRPv2 only; use a different group number from the IPv4 group on the same interface

Load sharing across VLANs. HSRP elects one Active router per group, so make DSW1 Active for VLANs 10 and 30 and DSW2 Active for VLANs 40 and 99. Align each VLAN's HSRP Active router with its STP root (Chapter 9) so frames reach the gateway without crossing an extra switch.

13.7 Configuring VRRP (for comparison)

VRRP is configured the same way in principle; the syntax depends on the IOS release.

DSW1
! Classic IOS (VRRPv2)
DSW1(config-if)# vrrp 10 ip 10.10.10.1
DSW1(config-if)# vrrp 10 priority 110                       ! preempt is already on

! IOS XE (VRRPv3)
DSW1(config)# fhrp version vrrp v3
DSW1(config)# interface vlan 10
DSW1(config-if)# vrrp 10 address-family ipv4
DSW1(config-if-vrrp)# address 10.10.10.1 primary
DSW1(config-if-vrrp)# priority 110

VRRP may use a router's own interface address as the virtual IP; that router is the address owner, gets priority 255 automatically and is always Master while it is up. Packet Tracer limitation: VRRP is not available in most Packet Tracer versions (check with vrrp ? in interface mode). If yours lacks it, practise VRRP on paper using this section and do Lab 13.1 with HSRP.

13.8 Verifying HSRP

DSW1
DSW1# show standby brief
                     P indicates configured to preempt.
                     |
Interface   Grp  Pri P State   Active          Standby         Virtual IP
Vl10        10   110 P Active  local           10.10.10.3      10.10.10.1
Vl30        30   110 P Active  local           10.10.30.3      10.10.30.1
Vl40        40   100 P Standby 10.10.40.3      local           10.10.40.1
Vl99        99   100 P Standby 10.10.99.3      local           10.10.99.1

Read each line: interface, group, this router's priority, P = preempt, this router's state, who is Active and Standby (local = me), and the virtual IP. DSW1 is Active for VLANs 10 and 30 and Standby for 40 and 99, exactly the planned split.

DSW1
DSW1# show standby vlan 10
Vlan10 - Group 10 (version 2)
  State is Active
    2 state changes, last state change 00:04:11
  Virtual IP address is 10.10.10.1
  Active virtual MAC address is 0000.0c9f.f00a (MAC In Use)
  Hello time 3 sec, hold time 10 sec
  Preemption enabled
  Active router is local
  Standby router is 10.10.10.3, priority 100 (expires in 9.296 sec)
  Priority 110 (configured 110)

The virtual MAC 0000.0c9f.f00a is HSRPv2's prefix plus the group number in hexadecimal (10 = 0x00A). On a PC, arp -a after pinging the gateway shows 10.10.10.1 mapped to that MAC; it does not change after a failover. (Output layout varies slightly by platform.)

Interpreting VRRP status. The same reading skills apply to VRRP; only the words differ (Master/Backup instead of Active/Standby). Example from a router running VRRPv3 on IOS XE (column layout varies by release):

DSW2
DSW2# show vrrp brief
  Interface   Grp  A-F Pri  Time Own Pre State   Master addr/Group addr
  Vl10         10 IPv4 100     0  N   Y  BACKUP  10.10.10.2(r)/10.10.10.1
  Vl40         40 IPv4 110     0  N   Y  MASTER  10.10.40.3(r)/10.10.40.1

Read it as: in group 10 this router (priority 100) is Backup and the Master is 10.10.10.2; in group 40 it is Master. Own N means its own interface address is not the virtual IP (an owner would show Y and priority 255); Pre Y means preemption is on, VRRP's default. The virtual IP is the address after the slash.

You see It means
HSRP Active / VRRP MASTER This router forwards for the virtual IP
HSRP Standby / VRRP BACKUP Ready to take over (HSRP has exactly one Standby; VRRP may have several Backups)
HSRP Listen A third router that is neither Active nor Standby
HSRP Speak or Init for a long time Hellos not exchanged, or the interface is down
P (HSRP) / Pre Y (VRRP) Preemption configured
Both routers Active / Master They cannot hear each other: an error, not load sharing
Command Shows
show standby brief One line per group: state, priority, preempt, Active/Standby, virtual IP
show standby [interface] Full detail: virtual MAC, timers, state changes, tracking
show vrrp brief / show vrrp The VRRP equivalents
show track Tracked objects and their state
PC: ipconfig and arp -a Gateway is the virtual IP; gateway MAC is the virtual MAC

Both routers Active for the same group They cannot hear each other's Hellos: VLAN missing from the trunk between them, different group numbers, different HSRP versions, an ACL show standby brief on both shows local as Active; fix the trunk, group or version
Wrong router stays Active after recovery preempt missing on the higher-priority router Add standby <grp> preempt
Wrong router Active from the start Priorities as default (tie broken by highest real IP) Set priorities deliberately
%HSRP-4-DIFFVIP1 log, inconsistent gateway Virtual IP typed differently on the members Make the virtual IP identical

Gateway stays on a router whose uplink failed No tracking track the uplink and decrement the priority below the peer's

13.11 Lab 13.2 — FHRP challenge

On a copy of Lab 13.1 apply: (1) on DSW2 interface vlan 30 → standby 30 ip 10.10.30.254; (2) on DSW2 interface vlan 40 → no standby version 2 (so it runs version 1); (3) on DSW1 interface vlan 10 → no standby 10 preempt, then shutdown and no shutdown that SVI. Diagnose with show standby brief, logs and pings.

Answer key (hide until done): (1) Virtual IP mismatch — a %HSRP-4-DIFFVIP1 message; hosts using 10.10.30.1 may lose their gateway if DSW2 becomes Active. (2) Version mismatch — the versions cannot hear each other, so both switches show Active for VLAN 40 (and both answer for the virtual IP with different MACs). (3) No preemption — after the bounce DSW2 stays Active for VLAN 10 although DSW1 has the higher priority, so VLAN 10 traffic no longer follows the STP root. Fix each and re-check.

13.12 Chapter 13 summary notes (exam revision)

  • Hosts have one default gateway; an FHRP gives a group of routers a shared virtual IP and virtual MAC so the gateway survives a router failure without host changes.
  • One router forwards (HSRP Active, VRRP Master); another waits (HSRP Standby, VRRP Backup). Highest priority wins (default 100), tie → highest real IP.
  • Preemption: HSRP off by default, VRRP on. Tracking lowers priority when an uplink fails.
  • Failover = Hellos stop for the hold time → standby takes over → gratuitous ARP updates switch MAC tables.
  • HSRP: Cisco, Hello 3 s / hold 10 s, UDP 1985, v1 224.0.0.2 MAC 0000.0c07.acXX, v2 224.0.0.102 MAC 0000.0c9f.fXXX (IPv6 in v2). VRRP: open standard, 224.0.0.18, protocol 112, MAC 0000.5e00.01XX, virtual IP may be a real address (owner, priority 255). GLBP: Cisco, load balances within one group (AVG + AVFs).
  • Load share by making different routers Active for different VLANs; align with the STP root.
  • Verify: show standby brief, show standby, show vrrp brief; on hosts, gateway = virtual IP, arp -a shows the virtual MAC.

Common conceptual mistakes

Mistake Correct idea
"Hosts are configured with both routers' addresses" Hosts use only the virtual IP
"The standby router forwards half the traffic" Within one HSRP group only the Active router forwards; share load with multiple groups
"A recovered higher-priority router always takes over" Only with preempt (off by default in HSRP)
"The virtual MAC changes after a failover" It stays the same; only the switch port that owns it changes
"HSRP and VRRP can be mixed in one group" They are different protocols and never form one group
