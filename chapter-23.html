Chapter 23Layer 2 security features

🖼️ 3 figures⏱️ ~18 min read

Objective covered: 4.7 Configure Layer 2 security features: a. DHCP snooping, b. Dynamic ARP inspection, c. Storm control, d. RA guard, e. Port security. These features run on the access switches, where users plug in, and stop attacks that routers and ACLs never see.

23.1 Learning objectives

After this chapter you can:

  1. Match each Layer 2 attack to the feature that stops it.
  2. Configure DHCP snooping with trusted and untrusted ports and read its binding table.
  3. Configure dynamic ARP inspection, including ARP ACLs for statically addressed hosts.
  4. Configure storm control and RA guard.
  5. Configure port security with sticky MAC addresses and choose a violation mode.
  6. Recover err-disabled ports and troubleshoot each feature.

23.2 Attacks at the access layer

Attack What happens Feature that stops it
Rogue DHCP server A device hands out leases with its own address as gateway or DNS → traffic interception DHCP snooping
DHCP starvation Thousands of fake DISCOVERs exhaust the pool DHCP snooping rate limit, port security
ARP spoofing / poisoning Attacker claims the gateway's IP with its own MAC → man-in-the-middle Dynamic ARP inspection (uses the snooping table)
Broadcast/multicast storm A loop or faulty NIC floods the VLAN, starving links and CPUs Storm control (STP still prevents loops, Chapter 9)
Rogue IPv6 router advertisement A host sends RAs and becomes the IPv6 default gateway RA guard
MAC flooding / unauthorised devices Fake source MACs fill the MAC table (switch floods like a hub), or someone plugs in a personal switch Port security

23.3 DHCP snooping

DHCP snooping classifies every port as trusted or untrusted (Figure 23.1):

  • Trusted ports (uplinks towards the real DHCP server or relay) accept all DHCP messages.
  • Untrusted ports (default; all access ports) may send client messages (DISCOVER, REQUEST, RELEASE) but any server message (OFFER, ACK, NAK) arriving on them is dropped.
  • From the ACKs it lets through, the switch builds a binding table: client MAC, leased IP, lease time, VLAN and port.
  • Optional rate limit per untrusted port stops starvation; exceeding it err-disables the port.

In Figure 23.1 the green uplink is trusted, so R1's replies reach PC1, while the rogue server's OFFER on an untrusted access port is dropped. The bottom band is the binding table that DAI uses next.

SW1(config)# ip dhcp snooping
SW1(config)# ip dhcp snooping vlan 10,30
SW1(config)# no ip dhcp snooping information option
SW1(config)# interface range GigabitEthernet0/1 - 2
SW1(config-if-range)# description Uplinks to DSW1/DSW2 (use the port-channel if bundled)
SW1(config-if-range)# ip dhcp snooping trust
SW1(config-if-range)# interface range FastEthernet0/1 - 24
SW1(config-if-range)# ip dhcp snooping limit rate 15
  • Snooping does nothing until it is enabled globally and per VLAN.
  • no ip dhcp snooping information option: by default a snooping switch inserts option 82 (relay information) into client requests while leaving the relay address (giaddr) empty. A Cisco relay or server that receives such a packet on an interface not set to trust relay information drops it, and clients get no address. When the snooping switch is not itself the relay — as here, where DSW1/DSW2 relay to R1 — disable the insertion (or configure the relay to trust it).
  • If the uplinks are an EtherChannel, configure ip dhcp snooping trust on the port-channel interface.

23.4 Dynamic ARP inspection (DAI)

DAI checks every ARP message that arrives on an untrusted port: the sender's IP and MAC must match a DHCP snooping binding for that port and VLAN, or an ARP ACL. Mismatches are dropped and logged (Figure 23.2).

In Figure 23.2 the first row matches its binding; the second claims the gateway's address from a port bound to another IP, so it is dropped; the third has no binding because it is statically addressed and is allowed only by an ARP ACL.

SW2(config)# ip arp inspection vlan 10,40
SW2(config)# ip arp inspection validate src-mac dst-mac ip
SW2(config)# arp access-list STATIC-HOSTS
SW2(config-arp-nacl)# permit ip host 10.10.40.11 mac host 00D0.BA11.4011
SW2(config-arp-nacl)# permit ip host 10.10.40.80 mac host 0001.6340.0080
SW2(config-arp-nacl)# exit
SW2(config)# ip arp inspection filter STATIC-HOSTS vlan 40
SW2(config)# interface range GigabitEthernet0/1 - 2
SW2(config-if-range)# ip arp inspection trust
SW2(config-if-range)# interface range FastEthernet0/1 - 24
SW2(config-if-range)# ip arp inspection limit rate 15
  • DAI depends on DHCP snooping for its bindings: enable snooping first and let clients renew.
  • Statically addressed hosts (printers, servers) have no binding — permit them with an ARP ACL, or their ARP is dropped and they go silent. (The MAC addresses above are examples; read the real ones from each device.)
  • validate src-mac dst-mac ip adds checks that the Ethernet and ARP MAC addresses agree and that the IP addresses are valid.
  • Untrusted ports are rate-limited to 15 ARP packets per second by default; exceeding the limit err-disables the port.

23.5 Storm control

Storm control measures broadcast, multicast or unknown-unicast traffic arriving on a port, per second, and acts when it rises above a threshold — a safety net for loops and faulty NICs.

SW1(config)# interface range FastEthernet0/1 - 24
SW1(config-if-range)# storm-control broadcast level 1.00 0.50
SW1(config-if-range)# storm-control multicast level 2.00
SW1(config-if-range)# storm-control action trap
  • level 1.00 0.50 = act when broadcasts exceed 1 % of the port's bandwidth; resume when they fall below 0.5 % (the falling threshold is optional). Thresholds can also be set in packets per second (level pps 500) or bits per second (level bps 10m).
  • Default action: the switch drops the excess traffic of that type until it falls below the threshold. storm-control action shutdown err-disables the port instead; action trap sends an SNMP trap (and a log message) as well.
  • Choose thresholds above normal traffic: too low and normal ARP and DHCP broadcasts are dropped.
SW1# show storm-control FastEthernet0/1 broadcast
Interface  Filter State   Upper        Lower        Current
---------  -------------  -----------  -----------  ----------
Fa0/1      Forwarding       1.00%        0.50%         0.02%

Forwarding = below the threshold; Blocking = storm detected and excess dropped; Shutdown = port err-disabled.

23.6 RA guard

IPv6 hosts learn their default gateway (and often their prefix, through SLAAC) from Router Advertisements. Any device can send RAs, so a misconfigured PC or an attacker can become the IPv6 gateway for the whole VLAN. RA guard drops RAs (and ICMPv6 redirects) arriving on ports where no router should be.

SW1(config)# ipv6 nd raguard policy HOST-PORTS
SW1(config-nd-raguard)# device-role host
SW1(config-nd-raguard)# exit
SW1(config)# ipv6 nd raguard policy UPLINKS
SW1(config-nd-raguard)# device-role router
SW1(config-nd-raguard)# exit
SW1(config)# interface range FastEthernet0/1 - 24
SW1(config-if-range)# ipv6 nd raguard attach-policy HOST-PORTS
SW1(config-if-range)# interface range GigabitEthernet0/1 - 2
SW1(config-if-range)# ipv6 nd raguard attach-policy UPLINKS
  • device-role host (the default if you attach a policy without a role) blocks all RAs entering that port; device-role router allows them.
  • RA guard protects even networks that "do not use IPv6": hosts have IPv6 enabled by default, so a rogue RA can still give them an IPv6 gateway and DNS server.
  • Verify with show ipv6 nd raguard policy HOST-PORTS (lists the policy and the ports it is attached to).
  • On older access switches such as the 2960, IPv6 first-hop security may need a newer image or an IPv6-capable SDM template (check show sdm prefer; changing the template needs a reload); Catalyst 9000 switches support it directly.

23.7 Port security

Port security limits which and how many MAC addresses may send frames into an access port.

SW1(config)# interface FastEthernet0/1
SW1(config-if)# switchport mode access
SW1(config-if)# switchport port-security
SW1(config-if)# switchport port-security maximum 2
SW1(config-if)# switchport port-security mac-address sticky
SW1(config-if)# switchport port-security violation restrict
  • The port must be a static access (or trunk) port; on a dynamic (DTP) port the command is rejected.
  • Defaults once enabled: maximum 1 address, violation mode shutdown, no sticky learning, no aging.
  • Allowed addresses can be static (switchport port-security mac-address 0060.2F11.0001), dynamic (learned, lost on reboot) or sticky (learned and written into the running configuration — save it to keep them).
  • A PC behind an IP phone needs a maximum of at least 2 (some platforms count the phone in the voice VLAN separately; 3 is a common safe value).
Violation mode Frames from the extra MAC Log/SNMP message Violation counter Port
protect Dropped No No Stays up
restrict Dropped Yes Increments Stays up
shutdown (default) Dropped Yes Increments Err-disabled

Recovering an err-disabled port: remove the cause, then shutdown and no shutdown on the interface. To recover automatically: errdisable recovery cause psecure-violation and errdisable recovery interval 300 (seconds). The same mechanism applies to DHCP snooping (dhcp-rate-limit), DAI (arp-inspection), storm control and BPDU guard (Chapter 9).

23.9 Lab 23.1 — Securing the access layer (Intermediate)

Objective: 4.7 a–e. Start from: your Lab 22.1 file. Packet Tracer support: the 2960 in Packet Tracer supports DHCP snooping, dynamic ARP inspection and port security. storm-control and ipv6 nd raguard are accepted only in some versions; if your version rejects them, do those steps on a real switch or a Catalyst 9000 node in Cisco Modeling Labs, and still answer the questions from 23.5–23.6.

Figure 23.3 is the target state. Green lines and the green band are the trusted uplinks; everything in the grey band applies to every access port; the red line on SW1 is the rogue server you add for testing.

Step 1 — Watch a rogue DHCP server win. Add a Server-PT ROGUE to SW1 Fa0/10 (switchport mode access, switchport access vlan 10): IP 10.10.10.200/24. In Services → DHCP, turn the service on with a pool: default gateway 10.10.10.200, DNS 10.10.10.200, start 10.10.10.100, mask 255.255.255.0. On PC1 run ipconfig /release and ipconfig /renew until it gets a 10.10.10.10x address with gateway 10.10.10.200 (the rogue usually answers first because it is closer). That PC would now send all its traffic to the attacker.

Step 2 — DHCP snooping on SW1 and SW2. Find the uplinks with show etherchannel summary and show interfaces trunk, then:

SW1(config)# ip dhcp snooping
SW1(config)# ip dhcp snooping vlan 10,30,40
SW1(config)# no ip dhcp snooping information option
SW1(config)# interface range GigabitEthernet0/1 - 2
SW1(config-if-range)# ip dhcp snooping trust
SW1(config-if-range)# interface range FastEthernet0/1 - 24
SW1(config-if-range)# ip dhcp snooping limit rate 15

(Use your port-channel interface instead of Gi0/1–2 if the uplinks are bundled.) Repeat on SW2. Renew PC1, PC2 and PC3: PC1 now gets a lease from R1 with gateway 10.10.10.1. Check show ip dhcp snooping binding on both switches.

Step 3 — Dynamic ARP inspection. On SW1 and SW2:

SW1(config)# ip arp inspection vlan 10,30,40
SW1(config)# interface range GigabitEthernet0/1 - 2
SW1(config-if-range)# ip arp inspection trust

From PC3, ping 10.10.40.11: it now fails, because Printer1's ARP has no binding. Find the MAC addresses of Printer1 and WEB1 (show mac address-table interface fa0/2 and fa0/6 on SW2) and permit them:

SW2(config)# arp access-list STATIC-HOSTS
SW2(config-arp-nacl)# permit ip host 10.10.40.11 mac host <Printer1-MAC>
SW2(config-arp-nacl)# permit ip host 10.10.40.80 mac host <WEB1-MAC>
SW2(config-arp-nacl)# exit
SW2(config)# ip arp inspection filter STATIC-HOSTS vlan 40

Ping again: it works. From ROGUE, ping 10.10.10.1 fails — its ARP is dropped (no binding). Read show ip arp inspection statistics.

Step 4 — Port security. On both switches:

SW1(config)# interface range FastEthernet0/1 - 24
SW1(config-if-range)# switchport port-security
SW1(config-if-range)# switchport port-security maximum 2
SW1(config-if-range)# switchport port-security mac-address sticky
SW1(config-if-range)# switchport port-security violation restrict

Generate traffic from every host, then show port-security address. Test a violation: on SW1 Fa0/1 set switchport port-security maximum 1 and switchport port-security violation shutdown. Disconnect PC1, connect a new PC to Fa0/1 and ping: the port goes err-disabled. Check show interfaces status err-disabled and show port-security interface fa0/1, reconnect PC1, then recover with shutdown / no shutdown. Save the configuration so the sticky addresses survive a reload.

Step 5 — Storm control and RA guard (on SW1 access ports; see the support note above):

SW1(config)# interface range FastEthernet0/1 - 24
SW1(config-if-range)# storm-control broadcast level 1.00
SW1(config-if-range)# exit
SW1(config)# ipv6 nd raguard policy HOST-PORTS
SW1(config-nd-raguard)# device-role host
SW1(config-nd-raguard)# exit
SW1(config)# interface range FastEthernet0/1 - 24
SW1(config-if-range)# ipv6 nd raguard attach-policy HOST-PORTS

Verify with show storm-control broadcast and show ipv6 nd raguard policy HOST-PORTS.

Step 6 — Remove the attacker. Delete ROGUE, shutdown Fa0/10, and save. Run the Lab 22.1 tests again (DNS, web, printer) to prove nothing legitimate broke.

23.10 Lab 23.2 — Troubleshooting challenge (Advanced)

Start from: your finished Lab 23.1 file. One fault at a time; find it with show commands and the log.

# Fault to introduce
A On SW2, no ip dhcp snooping trust on the uplinks
B On SW2, no ip arp inspection filter STATIC-HOSTS vlan 40
C On SW1 Fa0/2, switchport port-security maximum 1, violation shutdown, then connect a second PC through a hub or replace PC2
D On SW1, no ip dhcp snooping vlan 30, then ipconfig /release and /renew on PC2

Solutions

  • A — uplink untrusted. PC3 cannot renew (it ends up with a 169.254.x.x address). show ip dhcp snooping lists no trusted interfaces on SW2, and the log shows OFFERs dropped on the uplink. Re-trust the uplinks.
  • B — ARP ACL removed. Printer1 and WEB1 become unreachable from other VLANs; show ip arp inspection statistics shows rising drops in VLAN 40. Re-apply the filter.
  • C — port-security violation. PC2's port is err-disabled (show interfaces status err-disabled, %PORT_SECURITY-2-PSECURE_VIOLATION). Remove the extra device, restore the intended maximum, then shutdown / no shutdown.
  • D — snooping removed from a VLAN that DAI still inspects. PC2 gets an address, but no new binding is created, so DAI drops its ARP and PC2 cannot reach its gateway. show ip dhcp snooping no longer lists VLAN 30; show ip arp inspection statistics shows drops in VLAN 30. Re-add ip dhcp snooping vlan 30 and renew.

23.11 Chapter 23 summary notes (exam revision)

  • DHCP snooping: ip dhcp snooping + ip dhcp snooping vlan X; uplinks ip dhcp snooping trust; untrusted ports drop OFFER/ACK/NAK; builds the binding table; limit rate; no ip dhcp snooping information option when a separate relay would reject option 82.
  • DAI: ip arp inspection vlan X; uplinks ip arp inspection trust; checks ARP against snooping bindings or arp access-list (+ ip arp inspection filter); validate src-mac dst-mac ip; default 15 pps on untrusted ports.
  • Storm control: storm-control {broadcast|multicast|unicast} level <rising> [<falling>] (%, pps or bps); default action drop; action shutdown | trap.
  • RA guard: ipv6 nd raguard policy NAME → device-role host|router; ipv6 nd raguard attach-policy NAME on ports; blocks rogue IPv6 RAs.
  • Port security: access port; switchport port-security, maximum, mac-address sticky, violation protect|restrict|shutdown (default shutdown, max 1).
  • Err-disable: show interfaces status err-disabled; recover with shutdown/no shutdown or errdisable recovery cause ….

Common conceptual mistakes

Mistake Correct idea
"Enabling ip dhcp snooping globally protects every VLAN" It must also be enabled per VLAN
"Access ports must be trusted so clients can get addresses" Clients only send client messages; trust the uplinks towards the server
"DAI works on its own" It needs snooping bindings or ARP ACLs
"Protect mode logs violations" Only restrict and shutdown log and count
"Sticky addresses are permanent automatically" Only after the configuration is saved
"RA guard is useless without IPv6 deployed" Hosts run IPv6 by default and accept rogue RAs

23.13 Answer key with explanations

  1. Server messages: DHCPOFFER, DHCPACK, DHCPNAK (and DHCPLEASEQUERY replies). Client messages are allowed.
  2. Dynamic ARP inspection; it compares the ARP sender IP/MAC with the DHCP snooping binding table (or an ARP ACL) for that port and VLAN.
  3. ip dhcp snooping, ip dhcp snooping vlan 10,30, interface port-channel 1 → ip dhcp snooping trust (plus no ip dhcp snooping information option if the relay is another device).
  4. interface fa0/7 → switchport mode access, switchport port-security, switchport port-security maximum 1, switchport port-security mac-address sticky, switchport port-security violation restrict.
  5. Protect: drops, no log, no count, stays up. Restrict: drops, logs, counts, stays up. Shutdown: drops, logs, counts, err-disables the port.
  6. A second MAC address appeared; in shutdown mode the port was err-disabled. Remove the unauthorised device (or change the policy), then shutdown and no shutdown on the interface (or use errdisable recovery).
  7. (a) The uplinks are not trusted, so OFFERs are dropped; (b) the switch inserts option 82 with an empty giaddr and the relay drops it — fix with no ip dhcp snooping information option or trust on the relay.
  8. Static hosts have no snooping binding, so DAI drops their ARP. Create an arp access-list permitting its IP/MAC and apply ip arp inspection filter <name> vlan <id>.
  9. When broadcast traffic exceeds 1 % of the port bandwidth, the excess broadcasts are dropped until it falls below 0.5 %. (Shutdown or trap only if configured.)
  10. On access ports where hosts connect; it blocks IPv6 Router Advertisements (and redirects) arriving on them. Uplinks towards real routers get a router-role policy or none.
  11. B and C. Port security needs a static access (or trunk) port; the default violation mode is shutdown; it does not depend on DHCP snooping.
  12. No. Trusting access ports would let a rogue server on any of them hand out leases — the exact attack snooping prevents. Trust only the uplinks towards the legitimate server or relay.
