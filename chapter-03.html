Chapter 3IPv6 addressing and prefix sizing

🖼️ 4 figures⏱️ ~21 min read

Objective covered: 1.4 Troubleshoot IPv6 address configuration, assignment, and prefix sizing (unicast and modified EUI-64). The focus is on unicast addresses; multicast appears only where IPv6 needs it to work (NDP, SLAAC, DAD).

IPv6 removes IPv4's two hardest skills — odd-sized subnetting and NAT — and replaces them with new ones: reading long hexadecimal addresses, building interface IDs, and understanding how hosts configure themselves.

3.1 Learning objectives

After this chapter you can:

  1. Write any IPv6 address in full and in its shortest valid form, and spot invalid ones.
  2. Identify the prefix, subnet ID and interface ID, and plan /48, /56, /64, /127 and /128 prefixes.
  3. Recognise global unicast, link-local, unique local, loopback, unspecified and key multicast addresses.
  4. Calculate a modified EUI-64 interface ID from a MAC address.
  5. Explain static, SLAAC, stateless DHCPv6 and stateful DHCPv6 assignment, and the NDP messages behind them.
  6. Configure, verify and troubleshoot IPv6 on Cisco routers and on Windows, macOS and Linux hosts.

3.2 Introduction: why IPv6

IPv4 has about 4.3 billion addresses, and the regional registries ran out of fresh IPv4 blocks years ago; NAT has stretched the supply. IPv6 uses 128-bit addresses — about 3.4 × 10^38 — so every LAN gets a /64 with more addresses than the whole IPv4 Internet, and end-to-end addressing returns. Most networks today run dual stack: IPv4 and IPv6 side by side on the same interfaces, which is how this guide's labs are built.

3.3 Address format and the two compression rules

An IPv6 address is 128 bits written as 8 hextets (groups of 4 hexadecimal digits, 16 bits each) separated by colons. Hex digits are 0–9 and a–f; letters are case-insensitive, but lowercase is the recommended way to write them (RFC 5952).

Full form: 2001:0db8:acad:0010:0000:0000:0000:0001

Rule 1 — drop leading zeros in each hextet: 0db8 → db8, 0010 → 10, 0000 → 0. Never drop trailing zeros: acad stays acad, and 0010 is 10, not 1.

Rule 2 — replace one run of consecutive all-zero hextets with ::, once per address: 2001:db8:acad:10:0:0:0:1 → 2001:db8:acad:10::1.

Full Shortest valid form Note
2001:0db8:0000:0000:0000:ff00:0042:8329 2001:db8::ff00:42:8329 Both rules
fe80:0000:0000:0000:0250:79ff:fe66:6801 fe80::250:79ff:fe66:6801 Typical link-local
2001:0db8:0000:0001:0000:0000:0000:0001 2001:db8:0:1::1 :: goes on the longest zero run
0000:0000:0000:0000:0000:0000:0000:0001 ::1 Loopback
0000:...:0000 :: Unspecified address

Invalid addresses the exam likes: 2001:db8::1::5 (two :: — the length becomes ambiguous); 2001:db8:g::1 (g is not hex); 2001:db8:12345::1 (five digits in a hextet).

Expanding back: count the hextets you can see, then fill the :: with enough 0000 groups to make 8. 2001:db8:a::12 shows 4 hextets, so :: = 4 zero hextets → 2001:0db8:000a:0000:0000:0000:0000:0012.

3.4 Prefix, subnet ID and interface ID

A typical global unicast address has three parts (Figure 3.1):

Figure 3.1 splits one address into its 8 hextets. The first three come from the provider, the highlighted fourth is the part you design (here VLAN 10), and the last four identify the interface. The interface ID shown is the EUI-64 value built in Figure 3.2.

Part Bits Who sets it Example (2001:db8:acad:10::/64)
Global routing prefix 48 (often) The ISP or registry assigns it to your site 2001:db8:acad
Subnet ID 16 You, when you plan your network 10
Interface ID 64 The host or administrator ::1, or an EUI-64 / random value

The prefix length (/64) works exactly like an IPv4 CIDR prefix: it says how many leading bits identify the network. IPv6 has no broadcast address and no "network and broadcast minus two" rule; every interface ID in the subnet is usable (the all-zeros ID is reserved as the subnet-router anycast address, which you rarely need to think about).

Prefix sizing rules for the exam:

Prefix Typical use Why
/32 What an ISP receives from a registry Room for many customer sites
/48 One enterprise site 16 bits left for subnets = 65,536 /64 subnets
/56 Small business or home from an ISP 8 bits left = 256 /64 subnets
/64 Every LAN or VLAN SLAAC and EUI-64 need a 64-bit interface ID; anything longer breaks SLAAC
/127 Point-to-point router links Two addresses only; recommended by RFC 6164 for links
/128 Loopbacks, host routes One address

Counting subnets: subnets = 2^(new prefix − old prefix). A /48 holds 2^(64−48) = 2^16 = 65,536 /64s; a /56 holds 2^8 = 256 /64s; a /60 holds 16.

A readable plan for this guide. With the site prefix 2001:db8:acad::/48, the 4th hextet is the subnet ID. Using the VLAN number as the subnet ID makes addresses self-documenting:

VLAN IPv4 (from Chapter 2) IPv6 prefix Router (gateway) address
10 Staff 172.16.0.0/25 2001:db8:acad:10::/64 2001:db8:acad:10::1 and fe80::1
30 Wireless 172.16.0.128/26 2001:db8:acad:30::/64 2001:db8:acad:30::1 and fe80::1
40 Printers 172.16.0.192/27 2001:db8:acad:40::/64 2001:db8:acad:40::1 and fe80::1

Note that subnet ID 10 is hexadecimal (decimal 16); it is just a label that matches the VLAN, which is perfectly valid.

3.5 IPv6 address types

IPv6 has unicast (one interface), multicast (a group) and anycast (the nearest of several interfaces sharing an address). There is no broadcast; jobs that used broadcast in IPv4 (ARP, DHCP Discover) use multicast instead.

Type Prefix / range Starts with Routed? What it is for
Global unicast (GUA) 2000::/3 2 or 3 Yes, Internet-wide Public IPv6 addresses, like public IPv4
Link-local (LLA) fe80::/10 fe80 Never leaves the link Neighbor discovery, routing protocol neighbors, the default gateway address hosts use
Unique local (ULA) fc00::/7 (in practice fd00::/8) fd Inside the organisation only Private addressing, similar in spirit to RFC 1918 (but not used with NAT)
Loopback ::1/128 ::1 No Tests the host's own stack (like 127.0.0.1)
Unspecified ::/128 :: No Source address before a host has one; ::/0 is the default route
Multicast ff00::/8 ff Scope-dependent One-to-many delivery

Every IPv6-enabled interface has a link-local address, even when it has no global address. That is why fe80:: addresses appear in ipconfig on almost every PC.

Multicast addresses you must recognise (they make IPv6 work):

Address Who listens
ff02::1 All nodes on the link
ff02::2 All routers on the link (joined after ipv6 unicast-routing)
ff02::5 / ff02::6 OSPFv3 routers / designated routers (Chapter 12)
ff02::1:ffXX:XXXX Solicited-node multicast: the last 24 bits of a unicast address. Used by NDP and DAD instead of broadcast

Example: for 2001:db8:acad:10::1 the solicited-node address is ff02::1:ff00:1.

3.6 Modified EUI-64: building an interface ID from a MAC address

A 48-bit MAC address is too short for a 64-bit interface ID. Modified EUI-64 stretches it in three steps (Figure 3.2). Worked example: PC1's MAC 0050.7966.6801, subnet 2001:db8:acad:10::/64.

  1. Split the MAC in half: 0050.79 | 66.6801.
  2. Insert FFFE in the middle: 0050:79ff:fe66:6801.
  3. Flip the 7th bit of the first byte (the universal/local bit): first byte 00 = 00000000 → 00000010 = 02. Interface ID: 0250:79ff:fe66:6801.
  4. Add the prefix: global address 2001:db8:acad:10:250:79ff:fe66:6801; link-local fe80::250:79ff:fe66:6801.

Figure 3.2 follows the steps above byte by byte (each box is one byte, two hex digits). Highlighted boxes are the bytes that change at each step: FF FE is inserted in step 2, and only the first byte changes in step 3.

Flipping, not setting. If the 7th bit is already 1 it becomes 0. MAC 0200.5e11.2233: first byte 02 = 00000010 → 00000000 = 00, giving interface ID 0000:5eff:fe11:2233. On fe80::/64 that gives fe80::5eff:fe11:2233; on 2001:db8:acad:10::/64 it gives 2001:db8:acad:10:0:5eff:fe11:2233.

Quick hex trick for step 3: the 7th bit is worth 2 in the first byte, so add 2 if that bit is 0 (00→02, 0c→0e, a8→aa) or subtract 2 if it is 1 (02→00, 0e→0c). Only the second hex digit of the first byte ever changes.

Who uses EUI-64? Cisco IOS uses it automatically for link-local addresses, and for global addresses when you add the eui-64 keyword. Modern Windows, macOS and Linux hosts usually generate random or stable-privacy interface IDs instead, so you cannot predict a PC's address from its MAC. The exam still expects you to calculate EUI-64 by hand.

3.7 Neighbor Discovery Protocol (NDP): the engine behind IPv6

IPv6 has no ARP and no broadcast. NDP, carried in ICMPv6, does those jobs and more with five messages:

Message ICMPv6 type Sent to Purpose
Router Solicitation (RS) 133 ff02::2 (all routers) Host asks: "any routers here?"
Router Advertisement (RA) 134 ff02::1 (all nodes), or the asking host Router announces prefix, prefix length, flags, and itself as a default gateway
Neighbor Solicitation (NS) 135 Solicited-node multicast of the target "What is the MAC for this IPv6 address?" (replaces ARP request); also used for DAD
Neighbor Advertisement (NA) 136 The asker (or ff02::1) "That address is mine; here is my MAC" (replaces ARP reply)
Redirect 137 The host A better first hop exists on this link

Duplicate Address Detection (DAD). Before using any unicast address, a node sends an NS for its own new address. If anyone answers with an NA, the address is a duplicate and is not used. A Cisco router logs %IPV6_ND-4-DUPLICATE, and Windows shows the address as "Duplicate".

Because ICMPv6 carries NDP, blocking all ICMPv6 breaks IPv6. This matters later for ACLs.

3.8 Address assignment methods

IPv6 offers more ways to get an address than IPv4. What a host does is controlled by flags in the RA the router sends:

  • A flag (Autonomous, in the prefix information): 1 = "build your own address from this prefix" (SLAAC).
  • O flag (Other configuration): 1 = "ask a DHCPv6 server for other information" such as DNS servers.
  • M flag (Managed): 1 = "get your address from a DHCPv6 server".
Method RA flags Address comes from DNS comes from Default gateway comes from
Static n/a Typed by hand Typed by hand Typed (or learned from RA)
SLAAC only A=1, O=0, M=0 Host: prefix from RA + its own interface ID RA's DNS option (RDNSS), if sent RA (router's link-local)
Stateless DHCPv6 (SLAAC + DHCPv6) A=1, O=1, M=0 Host via SLAAC Stateless DHCPv6 server RA
Stateful DHCPv6 M=1 (A usually 0) DHCPv6 server DHCPv6 server RA — DHCPv6 never gives a gateway

Exam tip the default gateway in IPv6 always comes from the Router Advertisement, never from DHCPv6. If routers stop sending RAs, hosts lose their gateway even with a working DHCPv6 server. Hosts normally use the router's link-local address (for example fe80::1) as their gateway.

3.9 SLAAC step by step

Figure 3.3 shows PC1 joining the Staff VLAN with SLAAC.

  1. Link-local first. PC1 creates an fe80:: address on its own and checks it with DAD (an NS for that address; no reply means it is unique).
  2. RS. PC1 sends a Router Solicitation to ff02::2 instead of waiting for the next periodic RA.
  3. RA. R1 replies with prefix 2001:db8:acad:10::/64, A=1, M=0, O=0, and a router lifetime that makes R1 (fe80::1) a default gateway.
  4. Build. PC1 combines the /64 prefix with an interface ID (EUI-64 or random) to form its global address.
  5. DAD again. PC1 sends an NS for its new global address. No NA comes back, so the address becomes valid.
  6. Ready. PC1 now has a link-local address, a global address and a default gateway, with no DHCP server involved.

Read Figure 3.3 top to bottom; time runs downward and arrows show which device sends each NDP message. Steps 1 and 4 happen inside PC1 without any message to R1. The address built in step 4 is the EUI-64 result from Figure 3.2; a Windows PC would use a random interface ID instead.

Why SLAAC needs /64: the host must add a 64-bit interface ID. If the RA advertises a /80 or /96 prefix, SLAAC hosts do not configure a global address.

3.10 Configuring IPv6 on Cisco IOS

R1(config)# ipv6 unicast-routing                          ! enables IPv6 routing AND sending RAs
R1(config)# interface gigabitethernet0/0/0
R1(config-if)# ipv6 address 2001:db8:acad:10::1/64        ! static global unicast
R1(config-if)# ipv6 address fe80::1 link-local             ! easy-to-read gateway address
R1(config-if)# no shutdown
R1(config-if)# exit
R1(config)# interface gigabitethernet0/0/1
R1(config-if)# ipv6 address 2001:db8:acad:30::/64 eui-64  ! interface ID built from the MAC
R1(config-if)# no shutdown
Command Mode Purpose Common mistake
ipv6 unicast-routing Global config Turns the router into an IPv6 router: forwards IPv6 between interfaces, joins ff02::2, sends RAs Forgetting it — interfaces still get addresses, but hosts receive no RAs and get no global address or gateway
ipv6 address <prefix>/<len> Interface config Static address; prefix length typed with a slash Unlike IPv4, the /64 form is used here
ipv6 address <prefix>/64 eui-64 Interface config Builds the interface ID with modified EUI-64 Typing a full address with eui-64; give only the prefix
ipv6 address fe80::1 link-local Interface config Replaces the automatic EUI-64 link-local Using the same link-local on two links is fine; on the same link it is a duplicate
ipv6 enable Interface config Creates only a link-local address Expecting it to add a global address
ipv6 address autoconfig Interface config Makes the router itself a SLAAC client Rarely used on routers except toward an ISP
ipv6 nd other-config-flag / ipv6 nd managed-config-flag Interface config Sets the RA's O or M flag (stateless or stateful DHCPv6) Setting M=1 without a DHCPv6 server or relay

An interface may hold several global IPv6 addresses at once; adding a second ipv6 address does not replace the first, unlike IPv4.

Systematic order: link up → link-local present → RA received (global address and gateway present) → DAD passed (no duplicate) → gateway reachable → remote reachable. This mirrors Figure 2.6 for IPv4.

3.14 Chapter 3 summary notes (exam revision)

  • 128 bits, 8 hextets. Drop leading zeros in each hextet; use :: once for the longest run of zero hextets.
  • Structure: /48 site prefix + 16-bit subnet ID + 64-bit interface ID. Every LAN is /64; /127 for router links; /128 for loopbacks. /48 = 65,536 /64s; /56 = 256.
  • Types: GUA 2000::/3; link-local fe80::/10 (every interface has one, never routed); ULA fc00::/7 (fd…); loopback ::1; unspecified ::; multicast ff00::/8. No broadcast.
  • Key multicast: ff02::1 all nodes, ff02::2 all routers, ff02::1:ffXX:XXXX solicited-node (last 24 bits).
  • EUI-64: split MAC, insert FFFE, flip the 7th bit (±2 on the first byte). Cisco uses it for link-local by default; modern PCs usually use random IDs.
  • NDP (ICMPv6): RS 133, RA 134, NS 135, NA 136, Redirect 137. NS/NA replace ARP. DAD = NS for your own address.
  • RA flags: A=1 SLAAC; O=1 stateless DHCPv6 for DNS; M=1 stateful DHCPv6. Gateway always from the RA.
  • IOS: ipv6 unicast-routing (no RAs without it), ipv6 address x/64, … eui-64, ipv6 address fe80::1 link-local. Verify with show ipv6 interface brief, show ipv6 interface, show ipv6 route, show ipv6 neighbors.

Common conceptual mistakes

Mistake Correct idea
":: can be used twice to shorten more" Only once; twice makes the address ambiguous
"0010 shortens to 1" Only leading zeros go: 0010 → 10
"IPv6 has broadcast like IPv4" No broadcast; multicast (ff02::1, solicited-node) does those jobs
"DHCPv6 gives the default gateway" Gateway always comes from the Router Advertisement
"EUI-64 sets the 7th bit to 1" It flips the bit: 1 becomes 0, 0 becomes 1
"Use /120 on a LAN to save space" LANs use /64; SLAAC breaks with longer prefixes

3.16 Answer key with explanations

  1. 2001:db8::ff00:42:8329. Leading zeros dropped (0db8 → db8, 0042 → 42); the three zero hextets become ::.
  2. 2001:0db8:000a:0000:0000:0000:0000:0012. Four hextets are shown, so :: stands for four zero hextets.
  3. 001A2B | 3C4D5E → insert FFFE → 001a:2bff:fe3c:4d5e → flip the 7th bit of 00 → 02 → interface ID 021a:2bff:fe3c:4d5e → 2001:db8:acad:1:21a:2bff:fe3c:4d5e.
  4. B. 02 = 00000010; flipping the 7th bit gives 00000000 = 00, so the interface ID is 0000:5eff:fe11:2233 → fe80::5eff:fe11:2233. A forgot to flip; C inserted FFFE in the wrong place; D skipped FFFE.
  5. A /48 has 16 subnet bits before /64: 2^16 = 65,536. A /56 has 8: 2^8 = 256.
  6. C. fd00::/8 is the used half of the unique local range fc00::/7.
  7. B. Without ipv6 unicast-routing R1 sends no RAs, so SLAAC hosts get neither a prefix nor a gateway; they keep only their link-local addresses. DHCPv4 (A) is unrelated; a duplex problem (D) would not produce this pattern.
  8. B and D. B expands to 2001:db8:0:0:1:0:0:5 (eight hextets). D is valid: ::ffff:1 is six zero hextets followed by ffff and 1. A uses :: twice; C contains g; E has five digits in a hextet.
  9. SLAAC requires a /64 prefix so the host can add a 64-bit interface ID. A /80 leaves only 48 bits, so hosts ignore the prefix for autoconfiguration. Use /64.
  10. G0/0/1 has only an automatic (EUI-64) link-local address — it was configured with ipv6 enable or nothing more. It needs a global address, for example ipv6 address 2001:db8:acad:61::1/64, so its RAs carry a prefix.
  11. B. ff02::2 is all-routers; IOS joins it when it acts as an IPv6 router. ff02::1 is joined by every IPv6 interface; ff02::5 is OSPFv3; D is a solicited-node group.
  12. Take the last 24 bits (cd:1234) and append them to ff02::1:ff00:0/104 → ff02::1:ffcd:1234.
  13. (a) From a stateful DHCPv6 server. (b) From the Router Advertisement — DHCPv6 never supplies a gateway.
  14. It is the zone (scope) index: the interface number the link-local address belongs to. Every link uses fe80::/64, so the host must say which interface to use.
  15. No. LANs should use /64: SLAAC and EUI-64 need a 64-bit interface ID, and IPv6 has no address shortage to save. Longer prefixes are appropriate only on point-to-point links (/127) or loopbacks (/128).
